# QQ 简短口语与多轮回应

## 行为约定

普通群聊、私聊以 20–60 字、1–2 句为软目标，简单确认可以更短。先回答问题或表达观点，再给最重要的理由；影响理解的认识边界通常放在末尾，答案成立所需的条件不能省略。用户要求展开或解释本身复杂时允许详细口语，详细程度与正式程度分开。

普通场景去掉迟疑开场及完整的“感动—害羞—回礼”循环。称赞、维护或技术更新先回应具体内容。只有本轮明确的意外、强烈情绪或表达困难才允许有依据的短暂停顿；收到称赞本身不构成例外。缺少历史细节时询问具体缺口，不主动宣告“我不记得”，也不能假装记得或补写共同经历。

现有 gate 在同一次决策中规划回应意图、首句要点、新增问题、篇幅和必要边界。正文生成消费该计划，风格偏差只记录，不新增模型调用或修订次数，不在发送阶段截断或改写冻结文本。

## 证据与多轮范围

编译器与现有校验器消费同一组实际入模的结构化记忆证据。证据来自获授权入口，保留原会话、渠道、来源引用及“用户陈述／暂定／有争议／已核验发送”等状态。当前新消息、任意来源 ID、已裁剪资料或其他群的记录不能证明本会话的往事。一条合法记忆不能支持无关的历史断言。

风格窗口只使用本会话最近八轮实际已发送内容，分段按决定合并，失败或未确认草稿不计入；部分送达只代表已送出的片段。最近三分钟的入站上下文与发送回执用于区分重复已答、新增条件和新问题。重复点名优先等待；新条件回答增量；新实质问题正常进入决策。曾考虑过、曾生成过或仅文本相似都不等于已答。

共享认知、现有模型与情绪配置、10/60 秒发送冷却、60 秒总期限、新上下文抢占和未知交付保护继续生效。允许回答的新问题仍受传输规则约束。

## 验证与发布要求

回归覆盖来源隔离、证据裁剪、记忆状态、完整及部分交付、观点追问、重复点名中夹入新问题、强情绪例外和详细解释。纯检索调用及旧决定记录保持兼容。

离线成对评估冻结十二组四轮场景，每个版本重复两次；两个版本各自沿用前轮模拟交付的回复。固定人格、主辅模型、情绪及推理参数，保留版本和输入哈希。Kimi K3 盲评与规则指标分别记录，缺少评审、调用失败或未运行语义校验都不能记成通过。

发布门槛为普通回复至少 90% 不超过 60 字且不超过两句、直接问题至少 90% 首句进入答案；普通场景指定迟疑前奏、完整关系循环和主动忘记声明为零；回归中无新增虚构往事、跨范围引用或因同题误吞新问题。风格检测不能以少量词汇命中替代全部语义评估。

发布候选只包含本次功能增量；工作区内其他尚未发布的改动不自动进入发布包。通过验收后使用既有 Linux 发布和备份流程，保留旧 release，检查首批五十轮有交付证据的回复。未达到门槛时保留候选及失败证据，继续修复，不标记已上线。
