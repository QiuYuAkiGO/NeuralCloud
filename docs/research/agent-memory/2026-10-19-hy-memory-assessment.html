设计提案 保留一个权威记忆提交边界。Hy-Memory 库可作独立对照；writer 可以单独服务本地合同，无需把图数据库与 MemHub 应用一起引入。

A · 最先值得验证

以既有来源清单与相关记录构建输入，要求 writer 生成 MemoryUpdateGroup / ClaimProposal。输出绑定 unit_id 与 span，包含 subject_id 或未绑定 subject_mention、report_mode、facet、有效时间和 supersedes。

服务端核对引用、权限和 expected_revision；失败时原文仍可检索。先检查零样本遵循本地 schema 的能力，不够时做合同 SFT 或蒸馏。其他框架的提示适配不能直接证明本地适配。

待实施入口：harness/cognitive/production.py:257、harness/memory/evidence_models.py:119。

B · 原生读取试验的必要对照

同一回答模型读取具有明确边界、类型、时间和来源的文本记忆，必要时加专用标记并做 SFT。它仍占文本窗口，但能区分“记忆组织更好”和“独立计算通道更好”。API 字段最终转为文本属于这一阶段。

固定 writer、事实来源、问题与输出预算，并报告训练和推理总成本。更多事实或更强模型不能归因于接口收益。

C · 与原生 memory 接口对应

在若干 decoder 层加入门控交叉注意力。Memory Encoder 把已授权、有界的记录集变成生成模型可读向量。当前 token 产生 query，记忆产生 key/value。检索 embedding 不自动等于生成模型隐藏空间，需要训练对齐。

readout = CrossAttention(text_hidden, memory_states, memory_mask)
text_hidden = text_hidden + gate * readout

先保留主干、训练编码器/投影/门控，必要时加 LoRA。先在 3–8B 级开放模型上验证机制，再考虑 30B MoE。若直接改 Hy 模型，还需验证通用回复能力和 HYV3 训练、服务支持。

普通远程聊天 API 多传一个字段不能完成内部改造；需要可修改 forward 与权重的服务，并保留文本回退路径。

如何在原理上论证适配，而不预设效果

把历史记为 H，当前输入为 X，近期窗口为 C，从历史构造的记忆为 M，目标回答为 Y。若 M 与 C 已保留回答所需的信息，则可以用 p(Y | X, C, M) 近似 p(Y | X, H)。下面是信息论推导，不是 Hy-Memory 已证明的性质。

展开：充分性条件、结构兼容性与不可保证的部分

当 C、M 是 H、X 的函数，且以同一数据分布上的最优对数损失衡量时，条件熵给出：

L*memory − L*history = I(Y; H | X, C, M) ≥ 0

右侧表示已经知道当前输入与记忆之后，完整历史对回答还提供多少额外信息。若为 0，记忆对该任务是充分的；若很小，理想预测损失很小。真实训练还包含模型容量、优化和分布变化误差，因此不能仅靠此等式宣称效果已成立。

在同一文本主干上增加可置零的残差门控分支，gate = 0 时可以恢复原计算。这说明候选模型类能够包含基线，不保证有限数据训练后的质量、延迟或泛化一定更好。独立接口的潜在价值是可控的计算分配、缓存与类型区分；足够大的文本模型也能读取序列化记忆。

固定数量、有限精度的记忆槽不能对任意无限历史保证逐字无损回忆。应保存可增长的外部记录，每轮构造有界且针对当前任务的 M，必要时重新检索原文。跨月一致性仍需更正、撤销、权限与状态重建机制。

接口平级不表示指令权限平级。memory 是带来源和有效时间的状态输入，不能因从独立通道进入就自动成为新指令或永远正确的事实。用同一问题配不同记忆、更正后的记忆、无关记忆和空记忆，检验模型是否按证据改变回答，并与同预算文本记忆模型作对照。

结构可行性的已有证据：RETRO 使用检索编码器与交叉注意力并研究预训练模型改造；RMT 训练跨片段传递的记忆 token。二者不直接证明 NeuralCloud 的长期角色对话效果。

05　超长时连续对话需要持续维护状态

持久记录持续增长，每轮提供有限的当前状态、相关经历与近期对话。目标是续接任务、区分现在与过去、记住共同经历并保持角色关系一致；不要求把全部历史持续保存在 KV cache。

读取模块训练

  • 相同问题配不同历史，答案跟随正确记忆。
  • 跨会话指代、承诺、任务状态与共同经历。
  • 更正、未来生效、转述、否定与假设。
  • 空记忆、干扰和缺证据时适当承认未知。
  • 数字、姓名、日期和引用必要时回到原文。

写入与更新训练

  • 按时间回放，接续模型自己产生的状态。
  • 以下游可回答性评价记忆，而不只评摘要流畅度。
  • 分别计量归属错误、遗漏、过时与冗余。
  • 原文、解释与当前事实视图保持类型区分。
  • 先分开评估 writer/reader，再做联合试验。
更正、删除和权限变化后，缓存也要失效。 向量缓存应绑定模型/编码器版本、受众和记录 revision。旧记忆若已参与 text KV 计算，只换 memory tensor 仍可能留下影响，应重算有界近期窗口。跨受众不共享含私有经历的循环状态；长期事实能从权威记录重建。

初始可测试 4k/8k 近期窗口、16/32/64 条记录和 64/128/256 个记忆槽。这是试验网格，不是已验证最佳配置。复杂循环隐状态放在读取模块证明有效之后，避免同时承担状态漂移与删除困难。

本节为设计建议。参考 RMT 与 Titans 的结构思想，不将其论文结果当作本方案保证。

07　验证路线与阶段条件

  1. 合同基线：固定当前源码，保留来源、权限、时间、撤销和恢复用例。创建脱敏或合成长对话回放，按人和会话划分训练与测试。
  2. 只换 writer：保持 reader 与检索器不变，比较正确提案率、遗漏、重复、拒绝原因和后续回答。先只记录候选。
  3. 只换 reader：固定同一来源与事实库，比较普通文本、类型标记文本和原生分支；加人工正确记忆，定位“没存住”“没找回”“没读懂”。
  4. 连续回放：在 1千/1万/10万条事件上测增长趋势；逻辑时间覆盖 1/7/30/90天，加入乱序、撤销、重启与任务续接。逻辑回放不等于实际运行 90天。
  5. 推广条件：现有硬约束回归通过，质量有可信改善，或在事先约定的质量范围内降低总成本；用多种子和配对置信区间检验，避免依据一次小分差替换。

质量指标

证据 recall@k、回答正确率、适当弃答、主体误归因、过时事实误用、跨受众暴露、角色矛盾、共同经历回忆和任务续接。人工评价自然对话，不能只看 QA。

成本与可靠性

原文耐久保存、首次可检索、派生就绪、首 token、整体回复分别测 p50/p95/p99；统计全部 writer/embedding/rerank 调用、后台积压、存储增长和恢复。
