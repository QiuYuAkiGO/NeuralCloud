NEURALCLOUD · LIVE MEMORY ARCHITECTURE PILOT · 2026-10-19

两套记忆架构，能让最终回答答对多少

固定同一个写入与回答模型，在中文合成历史上比较记忆写入、维护和检索后的最终回答。Hy-Memory pro 使用发布源码；NeuralCloud 使用现有 production / evidence-v2 子系统。

本轮 Hy-Memory pro 为 31/36，NeuralCloud 为 28/36。Hy 领先 8.3 个百分点；按历史分组的 95% 区间包含零差异。这个小样本呈现 Hy 更好的趋势，尚不足以证明整体架构或长期连续对话更优。

沿原始记录定位的失误

下列是看到结果后的诊断，未用于调整本轮答案、评分规则或记忆设置。

  • multi_hop_plan · destination：NeuralCloud 已成功提交含临海的记忆提案，但该题实际检索上下文没有临海；回答因此只给出日期和晚数，缺少目的地。
  • multi_person · ming：NeuralCloud 已成功提交阿明要求热拿铁的记忆，但实际召回偏向当前对话者林澄的记录，未给回答模型提供温度要求。当前实现使用当前对话者 subject 加分和中文双字词重合排序。
  • unfinished_task · next：NeuralCloud 的备份已完成更新被 evidence_revision_identity_context_changed 拒绝；原始事件仍已落盘，但该题没有召回完成状态。同一段历史的 state 问题可以答对，说明问题依赖检索问法。
  • reported_hypothetical · current：NeuralCloud 的杭州居住地提案被 evidence_group_schema_invalid 拒绝，原始事件仍在；回答上下文只有大理假设和无关日常片段，回答不知道目前住址。
  • late_history · current：NeuralCloud 的海宁更新被 evidence_revision_temporal_interval_changed 拒绝，该题未召回海宁原始事件，错误沿用青州。
  • late_history · old：Hy 正确提取了晚到的 10 月 3 日洛川记录，但随后归并输出将 10 月 16 日海宁内容写成新 SUPERSEDE 节点；检索演化链把当前海宁内容标到 10 月 3 日。最终历史追溯回答错误。此处是本轮写入模型与归并流程的共同结果，不能单独归因为 SDK 算法。
  • exact_reference · booktime：Hy 提取器已把 10 月 22 日 16 点取件写入 intentions；本轮沿用 search 的 intention_limit=0 默认值，因此 proactive 通道为空。NeuralCloud 也已提交含取件时间的提案，但其该题召回未包含该信息。两组的回答都缺少日期时间。

NeuralCloud 共接受 66 个提案组、拒绝 26 个；拒绝包括重复提案，不能等同于丢失了相同数量的事实。原始事件仍保留。检索上下文平均长度：NeuralCloud 5,832 字符，Hy 2,049 字符；较长表示包含更多格式与内容，不能单独证明信息覆盖更好。

后续优先验证：保留原始证据、权限与时间约束，测试语义检索、去重和重排；再测试被拒提案的修复闭环。Hy 应另测 intention 通道和晚到历史的时间处理。这些改进效果尚未测量。

评审分歧与指标边界

共有 8 个“题目 × 条件”出现分数或编造标记分歧。若放宽为任一次评审完全通过，计数为：NeuralCloud evidence-v2 29/36；Hy-Memory pro 33/36；完整授权历史（诊断） 35/36；无记忆（诊断） 3/36。这是评分规则敏感性检查，不能替代主指标或当作人工校准后的准确率。

逐条复核发现个别评审添加了原评分要求之外的条件。例如书架位置题已经答对“第二层靠窗”，却因未重复页码被扣分；Hy 的服务状态题已经答对“恢复演练及切换均未完成”，仍有一次因未复述暂停背景而扣分。也有漏判：NeuralCloud 的住处条件回答缺少评分要求中的10月25日，却被两次评审都判为通过。原始分数完整保留，没有事后改成有利于某组的分数。自动评分存在双向误差，当前数字只能作为首轮方向性证据。

本轮衡量的是事实完整性、时序和持续对话的信息承接。没有对语言风格、情感体验、真人满意度或数月运行稳定性作验证。评审为同一个 kimi-k3 的两次调用，未经过独立人工标注。

怎样理解这次实验

  • 12 段独立历史、432 条消息、36 个问题；每段历史分三批写入，问题与答案要求未交给 writer。查询模拟跨会话，仅给检索记忆和当前问题。
  • 覆盖更正、有效时间、任务续接、转述、共同经历、语义回忆、多人归属、未知信息、精确编号、跨片段整合、受众隔离和晚到历史。每类只有三题，不能当作领域基准。
  • 两组写入与回答使用官方 deepseek-flash，关闭思考。Hy 使用 Chroma、bge-m3、pro 模式；没有启用 ultra / System 2；沿用 search 默认的 intention_limit=0，意图通道关闭。NeuralCloud 使用现有提案 schema、证据校验和 SQL recall。两组写入模型输出上限同为 4096 token。
  • 回答记忆最多 6000 个 Unicode 字符，按完整记录保留；这不等于相同 token 数。NeuralCloud 与 Hy 保留各自记录表示，格式开销属于本次架构配置。
  • Hy 以故事与受众分区隔离；NeuralCloud 使用原有 visibility。受众政策由评测适配器提供，不代表 Hy 原生实现了相同权限合同。
  • 完整历史是能力诊断：它也答错时，应先检查问题、评分或回答模型。无记忆用于观察猜测和弃答水平。所有中间记录、异常、使用量和原始回答都已保存。
  • 仅一轮写入、一个生成模型与一个自动评审模型。反转顺序不等于独立的人类验证。12 段历史的置信区间不能覆盖数据分布选择、模型变化或长期状态漂移。

运行条件与工程限制

  • pilot-01 在第四段历史发生 Windows SQLite 缓存关闭与后台 trace 写入冲突，未完成且不计入本轮分数。
  • pilot-02 仅关闭 Hy 可选数据库 trace，并把历史 worker 改为 1；数据集、模型、提示词、记忆设置、字符预算和评分规则保持不变。网关和 JSONL 审计仍开启，129 个已安装 Hy Python 源文件与固定发布源码一致。
  • NeuralCloud 采用现有 production appraisal 提示词、schema、证据验证和 SQL recall；模型接口统一为通用 JSON completion。此适配不等同于原生产模型的完整约束解码与角色运行时。
  • 本轮没有运行被拒绝提案的后续修复队列，也没有运行完整会话投递与角色行为流程。
  • 两次评分使用同一个独立于生成模型的 kimi-k3，并反转匿名答案顺序；不是两个人类或两个不同的评审模型。

完成的 pilot-02 保存了全部 144 个回答和 72 次评审，结束时源码哈希检查通过。另有 48 项本地记忆与评测合同检查通过；这些测试不能替代上述回答质量实验。
