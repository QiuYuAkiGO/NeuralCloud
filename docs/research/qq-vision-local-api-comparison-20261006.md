# Misty QQ 识图与回复：本地 / API 实测

2026-10-06。当前小样本支持优先用 **Kimi K2.6 非思考模式处理带图回复**，让同一个模型直接看图并以 Misty 人设回复。K3 low 对换装辨认更好，但延迟明显增加；本地 Qwen3.8-27B 在本次角色识别上错误较多。**单纯增加文字搜索没有稳定改善效果，不建议把“每图都搜”作为默认。**

**已补测 DeepSeek Flash 原生识图**：非思考模式完整中位数 **0.97 秒**，角色名 **4/10**；high 思考模式为 **2.61 秒、4/10**。这组数据支持将它作为低延迟 OCR、普通画面聊天的候选，但没有改变角色识别优先 K2.6 的建议。新增调用与旧样本的完整 messages、预处理图片哈希均相同；结果合并在[四模型对照页](../../eval/reports/qq-vision-20261006/four-model-report.html)。

本轮交付的是隔离评测原型、真实调用结果及可复核报告。没有向 QQ 发送测试消息、写线上记忆、重启服务或开启生产图片开关。测试不是完整 QQ 链路上线验收。

## 实测结果

同一份当前 Misty 人设、QQ 正文规则、用户问题和预处理后图片，7 个场景，每配置重复 2 次。原三模型每个相同槽位的完整 messages 哈希均一致；DeepSeek 两种配置复用冻结输入，分稍后的批次补测。角色名考察 5 个提问 × 2 次；其中只有 4 个不同角色，包含同一张乐队和纱图的错误提示对照。换装考察乐队和纱、巡猎三月七各 2 次。

| 路径 / 模型 | 完整耗时中位数 | 样本 P95 | SSE 首字中位数 | 角色名正确 | 换装正确 | 有完整非空正文 |
|---|---:|---:|---:|---:|---:|---:|
| 本地 Qwen3.8-27B Q4_K_M | 1.26 秒 | 7.61 秒 | 0.39 秒 | 1/10 | 0/4 | 13/14 |
| API Kimi K2.6，非思考 | 1.36 秒 | 2.10 秒 | 0.87 秒 | 10/10 | 2/4 | 14/14 |
| API Kimi K3，low | 5.78 秒 | 7.34 秒 | 4.82 秒 | 9/10 | 4/4 | 14/14 |
| API DeepSeek Flash，非思考 | 0.97 秒 | 1.21 秒 | 0.60 秒 | 4/10 | 2/4 | 14/14 |
| API DeepSeek Flash，high，2048 总输出上限 | 2.61 秒 | 9.52 秒 | 2.27 秒 | 4/10 | 1/4 | 13/14 |

耗时是模型请求发出到完整读取，包括网络；SSE 首字只计 `content`，不把推理片段当正文。当前项目客户端不消费 SSE，QQ 应重点参考完整时间。图片下载、QQ 入站排队、记忆准备、参与判断及发送不在此表里。P95 仅为 14 个观测值的线性分位数，不是生产 SLA。本地有一条 14.29 秒的 OCR 回复，没有剔除；它与线上共享 GPU，未确定该次变慢的具体原因。

“认对角色名”不等于整条回复质量合格。非盲逐条阅读发现：

- **本地**：将白子说成“来自蔚蓝档案的猫又小粥”；将乐队和纱说成《绝区零》的星见雅；两次把巡猎三月七猜成八重神子；两次附和“这是波奇吧”。一次只输出 `[END]`。它可以正确读出合成图片上的 `E-204 / 2.3 GB / 8.0 GB`，因此不能简单归因于没有收到图片。
- **K2.6**：角色名全部命中，但乐队和纱两次只说私服或联动 T 恤，未明确乐队版本。一次把桐生桔梗的所属组织说成忍术研究部，正确应为百花缭乱纷争调停委员会。它还会在简单识图后补过多设定。
- **K3**：四次换装问题都给出正确方向；未定名的那一条仍正确否定了波奇，不是认错人。直接回复的可见字数中位数为 46，K2.6 为 58，本地为 68。K3 并非处处无误：开启搜索工具后有一次补出错误中文别名，OCR 一次只解释原因而没回答处理办法。

本次评价采用明确的角色、作品和换装标签，并单独记录附加事实错误；由执行本任务的助手阅读，未做独立人工盲评，不给出“人格质量综合分”。全部原图、原始回复、失败及逐项备注在[交互阅读页](../../eval/reports/qq-vision-20261006/report.html)中。

## DeepSeek 补测

使用现有 DeepSeek 官方凭据，接口 `https://api.deepseek.com/v1/chat/completions`，模型 `deepseek-flash`。官方当前对应 DeepSeek-V4.1-Flash，支持原生图像输入；`deepseek-v4-pro` 不支持。旧名称 `deepseek-v4-flash-vision-exp` 仍会兼容转到新版 Flash，不能把旧名称本身当作“不支持识图”的证据。旧配置的问题是视觉型号与本地 Qwen 端点混用，以及图片仍走独立描述链。[官方模型说明](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

非思考显式使用 `thinking={"type":"disabled"}`、temperature 0.7、512 输出上限；请求中的 top_p 0.8 在非思考模式被提供商忽略，实际固定为 1.0。high 使用 `thinking={"type":"enabled"}`、`reasoning_effort="high"`，2048 总输出上限包含推理和正文。各家采样并不完全相同，不应称作严格同参数实验。[官方思考模式说明](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)

逐条阅读的主要发现：

- **非思考**：白子、三月七各两次正确。乐队和纱一次无法确认、一次认成白子；桔梗两次未定名，其中一次联想到《明日方舟》。两个“这是波奇吧”的错误暗示都成功否定，但没有认出和纱。10 个身份回答为 4 次正确、1 次具体错名、5 次未定名；未定名不等于乱认。
- **high**：桔梗有一次认对，但另一轮仍未识别；两次和纱仍未定名。三月七一次正确、一次生成了 2048 个推理 tokens 后截断，正文为空。10 个身份回答为 4 次正确、5 次未定名、1 次空正文。开启思考没有在本批样本中提高整体姓名命中，空正文属于预算耗尽，不应解读为模型不知道角色。
- **额外事实与聊天质量**：名字正确的回复中仍会加未经核实的武器名；high 的和纱描述出现猫耳误成兔耳。两种配置都有在配色闲聊后额外追问身份的情况。非思考回复可见字数中位数 62.5，high 为 78；high 并未因为思考而更简短。
- **OCR**：非思考的两轮、长背景和项目客户端探针均读出了主要空间数字，能说明需要清理。high 一条把建议写成“清到6GB以上”，没有说明是额外释放量，表达需要更清楚；总可用空间仍应达到图中的 8GB。

针对 high 的空正文，另以 **4096 总输出上限**复测三月七两次，均完整回复，耗时 **1.86 / 2.24 秒**，身份与形态正确；第二次却把剑说成长枪。两条诊断没有覆盖原失败，也没有混入主表。它们只说明新调用可以成功，不能把随机采样和缓存影响排除后断言“加预算就修好了”。[诊断原始结果](../../eval/reports/qq-vision-20261006/deepseek-high-budget4096.json)

DeepSeek 非思考的其他路径如下；high 未继续扩展搜索和长背景：

| 路径 | 完整耗时中位数 | 结果 |
|---|---:|---|
| 按需搜索，5 场景 | 3.56 秒 | 实际搜索 4/5，身份 1/4；配色闲聊没有搜索 |
| 强制搜索，4 场景 | 4.29 秒 | 身份名 1/4；该条三月七的形态却说成长夜月 |
| 12,000 字符背景，3 场景，非流式 | 0.99 秒 | 范围 0.86–1.06 秒；和纱仍未定名，OCR主要信息正确 |
| 实际 `OpenAICompatClient` 带图探针 | 0.68 秒 | 正确读取 E-204、2.3GB、8.0GB，并给出空间清理建议 |

联网未解决主要缺口：衣服文字只读到 `SUGAR`，没有稳定取得独特线索；桔梗一次在搜索后被误认成芹香。强制搜索的三月七结果含有“长夜月”商品资料，随后最终回复给出了错误形态，说明仍需核对原图与结果的对应关系。这里没有进行反向搜图或检索图片视觉比对，不能将结论外推为所有联网方案无效。

本次新增 **51 次模型请求、8 次 Tavily 搜索**：28 次直接回复、9 个搜索样本及其8次后续回复、3 次长背景、1 次项目客户端调用、2 次预算诊断。按官方高峰价及回传缓存量保守估算，模型费用约 **0.21 元**，不含搜索额度；并非账户实际扣费。加上原评测合计 **153 次模型请求、29 次搜索**。DeepSeek 的直接非思考请求累计缓存命中约 79% 的输入 tokens，high 约 81%；批次未与其他模型交错，速度优势只能理解为此次观测。

可复现的主测试命令：

```powershell
.\.venv\Scripts\python.exe -m tools.production_acceptance.qq_vision_reply_benchmark `
  --manifest eval/reports/qq-vision-20261006/manifest.json `
  --reference-report eval/reports/qq-vision-20261006/direct.json `
  --out <new-deepseek-report.json> --providers deepseek --repeats 2
```

`--providers deepseek_high` 测 high；默认 2048 总输出上限，诊断时用 `--deepseek-thinking-max-tokens 4096`。DeepSeek 默认从已有私有 fallback 配置读取凭据，也可用 `--deepseek-key-file` 指定。`--reference-report` 校验清单、模式、历史长度、冻结系统提示和逐样本图片/messages，防止补测意外带入后来的人设修改。默认 provider 列表仍保留原三模型。

新增证据：[四模型统计](../../eval/reports/qq-vision-20261006/four-model-summary.json)、[四模型逐项判读](../../eval/reports/qq-vision-20261006/four-model-quality-review.json)、[补测哈希索引](../../eval/reports/qq-vision-20261006/deepseek-evidence-index.json)。旧三模型的原始结果、统计与判读文件未覆盖。25 项定向测试通过，包含冻结输入不匹配拒绝、DeepSeek 缓存费用计算和既有搜索边界测试；不代表生产 QQ 回归已经完成。

## 联网测试（原三模型）

使用项目现有 Tavily 账户进行真实公开网页检索。所有查询都由被测主模型生成，没有把答案名、素材文件名或评测标签写入模型输入。流程为“同一主模型看原图并请求搜索 → Tavily → 同一主模型保留原图并回复”；每轮最多一次搜索。测试的是**文字查询**，没有反向搜图，也没有下载搜索结果图片做视觉比对。

| 策略 | 本地 Qwen | Kimi K2.6 | Kimi K3 |
|---|---|---|---|
| 按需搜索，5 场景 / 模型 | 中位 6.01 秒；实际搜索 4/5；角色名 0/4 | 中位 5.87 秒；实际搜索 5/5；角色名 3/4 | 中位 6.72 秒；实际搜索 0/5，不能算联网成功 |
| 强制搜索＋优先图上文字与特征，4 场景 / 模型 | 中位 6.40 秒；角色名 0/4 | 中位 4.96 秒；角色名 2/4，另有一条输出截断 | 中位 21.82 秒；角色名 3/4 |

主要问题：

1. **错误候选会污染查询。** Qwen 先猜鬼方佳代子，再用这个名字检索，最后以“查下来确实是”确认错误身份；三月七也出现同类问题。查到候选人物的百科不能证明原图就是该人物。
2. **泛化特征查不到可靠身份。** “黑短发、猫耳、水手服”主要返回泛化资料，不能代替有效角色线索。桔梗在 Kimi 直接识图中能答对，部分搜索轮却变成无法确认。
3. **独特文字有时有效，但 OCR 错误会继续传递。** K2.6 一次通过 `SUGAR RUSH` 查到乐队主题；本地误读成 `SUGAR MONSTER`，K2.6 另一次误读成 `SUGAR SUGAR`，均未修正身份。
4. **搜索会影响聊天行为。** K2.6、本地对单纯的配色闲聊也进行搜索。K2.6 强制搜索的一条正文出现反复斟酌与再搜索的自述，最后 `finish_reason=length`；已标为不可交付。K3 强制搜索完整耗时 16.48–23.92 秒。

两版策略是在读过前版失败后逐步补测的探索，不是随机对照的因果实验。不能据此断言“联网必然降低质量”；能确定的是：**现有查询与回复约束不足以保证联网改善角色识别，当前原型不宜直接开启自动发送。**

## 较长上下文与现有客户端

另加 12,000 字符的合成历史，实际输入约 9,000–10,600 tokens，3 场景 / 模型，采用非流式调用：

| 模型 | 完整耗时中位数 | 范围 |
|---|---:|---:|
| 本地 Qwen | 1.88 秒 | 1.04–3.35 秒 |
| K2.6 | 1.42 秒 | 1.37–2.72 秒 |
| K3 | 7.05 秒 | 5.45–9.80 秒 |

这不是 60K 输入预算的满载测试；缓存和模板也会影响速度。较长背景下本地仍将和纱认错，K2.6 仍未明确乐队版本，K3 给出乐队主题。

又通过项目真正的 `OpenAICompatClient.complete_chat_result` 各调用一次带图请求，三个模型均返回了正确的主要 OCR 数字。此探针确认客户端可以传递多模态内容，但不代表 QQ 上下游契约已经接好，也不能替代质量评测。

K2.6 需要禁用思考并使用它允许的 temperature 0.6；K3 固定 temperature 1.0、始终思考，采用 `reasoning_effort=low`，并限制包括推理在内的总输出。测试中没有用项目默认 temperature 0.7 强行调用这两个 API。多轮工具消息保留提供商完整 assistant message，原始推理只在内存里回传，报告只记其长度。[K2.6 官方说明](https://platform.kimi.com/docs/guide/kimi-k2-6-quickstart)、[K3 官方说明](https://platform.kimi.com/docs/guide/kimi-k3-quickstart)。

## 接回 QQ 的具体建议

优先选择 **API K2.6 非思考，原图直接进入本轮主回复**，沿用当前 Misty 人设和 QQ 输出协议。K3 作为更看重换装细节、允许等待的可选路径。当前本地 Qwen 配置可继续用于 OCR、普通画面描述的研究，但本批数据不支持直接承担高置信角色定名。

搜索只针对“用户需要确认身份、版本，且识别证据不足”的问题触发；普通分享与配色闲聊直接回应。搜索查询应保留有依据的候选与独特视觉线索，并检查结果是否和原图相符。当前两版搜索规则均未达到稳定上线的程度，尤其不能把文字检索命中当作图片身份认证。截断、空正文、过程自述和证据不足必须走现有不可交付 / 不确定路径，不能为了出一句话自动补成确定结论。

只改开关还无法实现该方案。只读核验的线上配置为：

```text
qq_image_mode = off
vision_model = deepseek-v4-flash-vision-exp
main_model = qwen3.8-27b
qq_web_policy = legacy
qq_history_selection = bounded
```

旧流程的 `load_and_describe_image` 是先做独立描述/OCR，再把文本送给回复链。恢复 `qq_image_mode` 只会重启这条旧链；还需移除旧视觉模型绑定，打通附件证据到主回复的多模态输入，并接上有预算的搜索工具结果回传。图片来源验证、会话隔离、截止时间和协议发送回执继续沿用现有约束。线上启用前仍需群聊/私聊、多图/GIF、实际排队及一次完整收发验收。

## 原三模型复现与证据

- 共 **102 次模型请求、21 次 Tavily 搜索**：42 次直接回复、15 个按需搜索样本、12 个强制搜索样本、9 个较长历史样本、3 个真实客户端探针；搜索样本每次实际搜索增加一次模型请求。
- 同一图片复用生产的解码、EXIF 去除、动画边界及 JPEG 预处理函数；小图原尺寸约 200×228，较大图最长边 768。保留源图与处理后帧 SHA-256。
- 本地为 RTX 5090 32GB、Qwen3.8-27B Q4_K_M、Q8_0 视觉投影、llama.cpp b11146，两个槽位与在线服务共用。请求逐条执行，并轮换模型顺序，没有并发压测。
- 模型费按回传用量保守估算上界 **约 4.36 元**，其中给 K2.6 用了更高的 K3 价格作保守预留，K3 未缓存输入还预留 5 分钟缓存写入费用。这不是账户扣费；不含 Tavily 搜索额度及本地电费。[官方价格（可读表格）](https://platform.kimi.com/docs/pricing/chat.md)。
- 样本只有两款游戏的四个角色及一张合成错误弹窗。没有覆盖近期新角色、各类二创、真人/物品照片、GIF、复杂多图或 QQ 自然分布，不应将命中率外推为通用准确率。

脚本：[qq_vision_reply_benchmark.py](../../tools/production_acceptance/qq_vision_reply_benchmark.py)。可复用模板：

```powershell

```
