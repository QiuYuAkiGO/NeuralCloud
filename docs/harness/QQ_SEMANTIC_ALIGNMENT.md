## 配置和作用范围

配置沿用已有设置序列化位置 `gui-settings.json` 的 `qq_latency` 对象，但使用独立开关和名单，不继承延迟优化名单：

```json
{
  "qq_latency": {
    "qq_semantic_alignment_mode": "observe",
    "qq_semantic_alignment_conversations": ["2015188508/712342021"]
  }
}
```

实际修改时合并这两个字段，保留对象内的其他设置。

- `off` 是默认模式，默认名单为空。旧记录可继续读取。
- `observe` 在现有事实校验调用中附加独立语义结果，不启用新的 gate、正文、情绪引导，也不因新增语义结果要求重写。
- `enforce` 启用理解摘要、原文优先、情绪表达约束和语义纠偏。首次正常回复沿用现有调用链；明确偏离最多重写一次，重新检查仍偏离则进入 `guard_wait`，正文不发送，记录 `reply_semantic_rejected`。
- 名单键为 `账号/会话`。`[]` 不启用任何会话，`null` 表示全部；本次上线只能使用上述一个明确键，不能设为 `null`。

语义策略版本为 `reply-semantics-v6`，情绪表达策略为 `expression-only-v1`。开关、名单、版本绑定到待恢复任务的配置快照。切换后不沿用不匹配的任务。情绪策略变化仅刷新指导文本缓存，不重新累计已处理的情绪刺激。

## 数据流和失败处理

`QQReplyPlan.understanding` 是可选模型判断，包含最多三种交流行为、240 字摘要和最多八条已入模消息引用。格式或引用无效时舍弃摘要并记录诊断，不再调用一次 gate。执行模式指导 gate 先形成当前作者的理解，再决定参与；等待时也允许保存理解摘要，但不会因此生成正文。`must_address` 的提示词限定为需要回应的意思，不规定赞同、安慰或固定开场。

内部 `ResponseSemanticContext` 保存会话、可信触发引用和可选计划，随编译上下文及暂停快照传递。校验器把引用映射到最终入模的原始证据行；缺失、裁剪、跨会话或非用户陈述不能补成有效来源。gate 摘要明确标记为可能出错的模型解释。

新增 `alignment` 状态为 `aligned`、`misaligned`、`uncertain`、`not_applicable`。明确偏离必须提供问题、对应原文行，以及正文的精确引文或遗漏说明。不确定不会单独触发重写，事实和人设检查继续生效。

执行模式下，报告缺少或含无效 `alignment` 会进入已有报告修复机制：最多两次报告尝试，共用原来的 8 秒截止时间。报告不可用时不放行未检查正文，也不靠再次生成正文修复校验器故障。关闭校验器或没有实际检查的路径不会被当成语义通过。明确语义拒绝与模型故障分别处理。

## 复现验证

数据链路测试检查实际生成输入及校验器收到的证据行，覆盖直接生成、暂停恢复、裁剪、消息缺失、同文不同作者、跨会话来源和旧记录。行为测试覆盖一次修正、连续偏离、报告无效和共享截止时间，验证不会增加理解调用或发送被拒绝正文。

在现有 QQ 成对评测命令 `freeze` 中增加 `--semantic-alignment`，即可冻结原有 12 个场景和新增 8 个四轮场景；两版本各重复两次，计划 320 个轮次。`run` 使用独立 SQLite、情绪状态和模拟送达回执，不构造真实 QQ 发送适配器。生成使用冻结的线上模型和配置，独立评分使用已有 Kimi 评测接口。

离线时延覆盖情绪处理、gate、正文生成、校验及模拟送达，不包含真实 QQ 网络传输和线上队列等待。线上采样另记录实际端到端时延，不能用离线数字代替执行模式的持续观察。隔离情绪状态从空状态开始，不代表事故时刻的完整角色状态。

```text
python -m eval.qq_brief.runner freeze --run-dir RUN --baseline-root BASELINE --candidate-root CANDIDATE --production-snapshot SNAPSHOT --credential-file PRIVATE_CONFIG --semantic-alignment --generation-routing primary-only
python -m eval.qq_brief.runner run --run-dir RUN --mode live --workers 2
python -m eval.qq_brief.runner seal --run-dir RUN --mode live
python -m eval.qq_brief.runner judge --run-dir RUN
python -m eval.qq_brief.runner analyze --run-dir RUN --mode live
```

凭据通过私有配置或 `MOONSHOT_API_KEY` 环境变量提供，不写入命令参数或评测记录。语义评测中，生成失败的轮次保留原始错误和状态快照，不模拟送达；后续轮次继续，重跑复用已有记录，不重新生成已完成轨迹中的失败样本。修改候选版本须创建新的冻结运行目录。原有评测仍采用失败后停止的行为，其显式 `--retry-errors` 会保留原始失败和请求。语义汇总将发生过生成失败的轮次计为失败，延迟采用保留的初始失败耗时，不能通过补跑提高验收分数。

严格同模型比较使用 `--generation-routing primary-only`：仅在冻结的评测设置中关闭正文模型回退，仍使用线上配置的原主模型，辅助模型与情绪模型不变。主模型故障应保留为失败，不能偷偷换模型后计入同模型验收。默认 `configured` 仍可测试完整生产回退行为，但需核对实际 HTTP 模型返回值；两版实际正文模型不同的运行只能作为补充诊断。该参数不修改生产配置，也不预热或增加生成调用。

评测观察到任一模型接口返回 401/402/403/429 时，保存当前轮原始结果，并写入两个版本的停止标志；在途请求允许结束，后续轮次不再调用。额度或权限恢复后应重新检查条件，再选择新的冻结验收运行，不删除原失败或自动充值。普通临时故障继续沿用语义套件的失败保留策略。

补充事故重放由 `eval/qq_brief/incident_probe.py` 完成：每个版本分别运行完整事故前文和三个改写句，采用相同冻结模型配置。角色状态为新的隔离状态，并非事故当时情绪快照；原文顺序和相对时间保持不变。该补充测试不计入 320 轮成对分母。

## 关闭与回滚

出现明确正常回应误拦截或累计延迟超限，先将该会话的语义模式关闭，并通过现有服务设置刷新流程生效。不能删除聊天、记忆、情绪状态或 SQLite 文件。

启动或兼容性故障回滚发布与配置：先记录本次发布前的实际符号链接、配置原始字节和各服务运行状态；停止受此次发布影响的服务，恢复配置并原子切回所记录的发布路径，然后恢复原服务运行状态。检查 QQ 连接及新鲜心跳、运行目录和发布哈希。不得把旧文档中的发布路径当作当前回滚目标，也不启动发布前已经停用的服务。
