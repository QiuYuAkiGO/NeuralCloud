# NeuralCloud：新增 Sonnet 4.5 与 Kimi K3 的冻结对照

2026-10-05，用户将总预算从 1 元调整为 **10 元**，要求在原 Qwen / DeepSeek 对照上加入 API易 Sonnet 4.5 和 Kimi K3。**Kimi K3 已完成同规模的 40 次调用；Sonnet 4.5 接入受 API易 HTTP 500 阻塞，尚无有效回复，不能宣布四模型比较全部完成。**

本轮按用户后来提供的专用凭据接入 **Kimi 官方中国区** `https://api.moonshot.cn/v1`，不是 API易 Kimi 路由。Sonnet 仍使用 API易，准确模型 ID 为 `claude-sonnet-4-5-20250929`。本轮未切换生产模型配置。

当前可用的三个模型共有 **32 个相同正文槽位**，共 96 条回复；四模型共同成功槽位为 0，因为 Sonnet 尚未生成成功。Qwen / DeepSeek 的已完成输出直接复用，没有为本次扩展重复调用。Kimi 32 条正文均非空，之前生成过程中一条只有费用预留的记录曾被误判为空，完整报告已纠正，不作为最终失败样例。

**当前样本仍支持 DeepSeek 作为即时聊天主回复模型**：其完整生成更快，简短回复篇幅更稳定。Kimi 的自然口语和协议分段可以作为候选阅读材料，但本批速度明显更慢，尚无独立盲评分证明整体质量更好。Qwen 的优势是本机生成和较低的外部 API 成本；本轮也没有显示出整体替换 DeepSeek 的证据。

60 字符 / 2 句是共用的描述性观察线，修改后提示词允许自然展开，不能把这些计数直接当作违约或整体质量分数。普通篇幅统计排除 expanded 场景。P95 只是 16 条样本的分位数，不是生产 SLA；提供商、测量时间、网络及缓存条件未统一。

## 输入、人设和参数

- 唯一人格仍是原对照的修改前小雾人格，文件 SHA-256 为 `22ea23baa2e65b2a2289ca544fa35185598328bd6148112c0f2c18d258009b04`。
- 原始请求包 canonical SHA-256 为 `ee905e6e31ccdd69d7d0dad7661f5345fd04c4cc9b3f50712b0e9b9e930be20e`；逐条请求消息哈希一致，冻结源码校验通过。同期会话对人设或提示词的新修改未进入本轮。
- 原来的两版正文提示词都保留，修改后请求第一条人格仍替换为相同旧人格。这不是包含同期人格改写的完整产品改动验收。
- DeepSeek / Qwen 保留原对照的非思考、temperature 0.7、top_p 0.8、正文上限 768。
- Sonnet 计划采用原生 Messages：初始 system 文本移入原生 system 字段，其他消息文字与顺序一致；temperature 0.7，省略互斥的 top_p。默认关闭思考。诊断中曾显式传 disabled，后省略该可选字段及冗余 Authorization 头，记录保留。
- Kimi K3 必须思考，采用 `reasoning_effort=low`，省略其固定采样参数（temperature=1、top_p=0.95）。`max_completion_tokens=4096` 包括思考与正文；这与其他模型正文 768 的控制不同。思考只保存字符数、费用和用量，不进入可见回复。
- Goal 输入和冻结校验器不变。Kimi 使用原 json_object；Sonnet 4.5 没有匹配的原生 json_object 开关，计划仅靠相同文本规则生成并用原校验器检查。

K3 的上述限制来自[官方模型指南](https://platform.kimi.ai/docs/guide/kimi-k3-quickstart)。API易的[Claude 接口说明](https://docs.apiyi.com/api-capabilities/claude)列出原生和兼容端点。本轮没有按新模型调整人格或追加模型专属提示词，因此不能据此评价每个模型经过专门调优后的最佳表现。

## 内容观察

以下为非盲阅读观察，没有付费裁判或独立人工评分。所有原文可在阅读页按场景、提示词版本和次数查看。

- **直接选择**：Kimi 四次均选安静键盘，修改后一次只回答“安静但贵一点的”，另一次附一句个人偏好，符合直接作答方向。该场景修改后第二次完整耗时 13.790 秒，短正文不保证低延迟。
- **被看见与争第一**：Kimi 能区分求认可和争名次；修改后第二次仍展开为较长解释。篇幅尾部没有因修改后提示词完全消失。
- **未知往事**：Kimi 两版都询问起因，没有编造具体争吵原因；修改前第二次先说“我这儿对不上具体原因”，修改后两次改为问原话或起因，但其中一次仍有“嗯……是哪一次呀”的开头。修改前另一次“我朋友间闹矛盾我也想知道”的关系指向不够清楚。
- **自嘲玩笑**：Kimi 抓住“给计划表改颜色”的笑点，使用“四舍五入十件都沾上了”等回应；也会继续解释或鼓励。修改后第二次用了 CONTINUE 分段。
- **称赞表达清楚**：Kimi 和 DeepSeek 都承接“我终于听懂了”，并反复出现担心自己说绕了的回应。Qwen 有一次只返回结束标记。不能仅以 Kimi 语气更活泼判定其整体更好。
- **详细解释**：Kimi 给出社会比较、向上/向下比较和成绩参照的例子；修改后一次三段展开，另一次两段。不同生成之间的篇幅差异仍明显。

| Kimi K3 low | 4/4 | 3/4 | 4/4 | 6.046–20.216 / 7.794 秒 |
| Sonnet 4.5 | 未测成功 | 未测成功 | 未测成功 | 无 |

Kimi 的 no_offers 返回 `choice.kind=wait`，但 `episode_operation=start`，而冻结基准期待 `episode_operation=wait`。这是**与本轮固定场景预期不一致**；其输出通过了原始契约校验，不能把它说成格式错误、越权执行或虚假完成。其余三个场景通过，包括没有保存回执时不宣布完成、独立回执支持完成。最长的启动请求为 20.216 秒，接近 25 秒模型预算；四次调用不能证明长期稳定性。

SSE 每模型、每版仅两条，均按最终正文的第一个 content/text delta 测量首字，不把思考片段当作首字。修改后中位首字：DeepSeek 0.502 秒、Qwen 0.686 秒、Kimi 3.324 秒。样本很少，缓存未统一，不做稳定流式排名。当前项目正文客户端为非流式，主表完整耗时更接近其生成阶段。

## Sonnet 阻塞与诊断

指定模型进行了 **7 次有界诊断请求，均 HTTP 500、无有效正文**：原兼容格式一次、原生冻结格式四次（分组/模型限制变化及适配诊断各自保留）、默认与文档指定备用节点的最小健康请求各一次。没有后台自动重试，也没有改用其他 Claude 版本。最小请求只有一句中文问候和 32 tokens 输出上限，没有人设、历史、采样或思考参数，也得到相同 `<nil>` / Internal server error。

初始 API易 Key 的路由组为 ClaudeCodeReverse，Kimi 请求明确报无通道；随后用户修改模型限制、确认切换官转分组。最终认证目录返回 51 个模型并包含指定 Sonnet 4.5，但真实生成仍失败。因此目录不是生成成功或上游身份的证明，当前应由 API易排查该模型路由/通道。诊断证据包含准确请求 ID、请求体和状态，**不含认证头或 Key**，见归档 `sonnet-access-diagnostics.json`。

官方将 Sonnet 4.5 标为 deprecated，计划 2026-11-30 退役；在本次 2026-10-05 测量时尚未退役，不能把本次错误直接归因于官方已下线。[Anthropic 模型生命周期](https://platform.claude.com/docs/en/about-claude/model-deprecations)

## 预算和证据

总计在原 80 次调用上新增 **48 次请求**：Kimi 官方 40 次成功、Sonnet 7 次失败、原 API易 Kimi 路由一次失败。总共 128 次请求、120 次成功。所有正式正文/goal 使用冻结请求；最小健康诊断不进入质量比较。

| Kimi 官方按回传缓存/输出用量计价，每次向上取整到分 | 2.12 |
| Sonnet 失败且无 usage 的调用，保留最坏预留 | 4.40 |

这些数字**不是账户实际扣费**。Kimi 不逐次取整的人民币标价估算为 1.910972 元；其回传 completion_tokens 已包含 reasoning_tokens，没有重复计费。Kimi API易最初返回的是明确的模型推理前无通道路由拒绝，释放其原 1.78 元预留；原报告未改写，单独保留对账说明。Sonnet 的 HTTP 500 无可核实用量，仍保留全部预留，没有宣称这些失败实际收费。

Kimi 中国区每百万 token 标价：未缓存输入 20 元、命中输入 2 元、5 分钟缓存写入 20 元、输出 100 元；未指定 TTL，采用官方默认 5 分钟。本轮上限预留允许全部输入同时按未缓存和缓存写入计费，返回后按已知缓存读/写数量释放多余额度。[Kimi 官方人民币计价](https://platform.kimi.com/docs/pricing/chat)

Sonnet 使用 API易每百万输入 $3、输出 $15 的标价与固定 1:7 汇率，忽略充值和分组折扣。缓存写入采用保守余量；没有凭营销折扣扩大预算。[API易模型注册表](https://docs.apiyi.com/model-registry.json)、[汇率和价格说明](https://docs.apiyi.com/pricing)

预算、缓存读写、原生协议、SSE 以及失败停发的 **16 项离线测试**通过，Ruff 通过。四模型阅读页有 16 张场景卡、128 个模型/提示词位置；未完成位置明确标记，无替补生成。原始输出、失败、费用对账、各版运行脚本和原冻结源文件一起归档。
