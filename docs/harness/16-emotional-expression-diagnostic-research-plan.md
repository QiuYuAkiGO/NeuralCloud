> 状态：Planned；已完成源码调研与实验设计，真实请求审计、模型对照、后训练均未执行。
>
> 日期：2026-09-14。目标分支：`codex/grounded-agency`。

> 用户当前反馈：云端 DeepSeek V4.1 Flash 最终回复情绪表达不足；待检验的首要假设是“模型不理解项目参数的意义”。模型名称来自用户描述，实际 provider、请求 model、响应 model、部署配置与运行路径待 P0 核验。

## 1. 目标与交付边界

本调研要定位情绪表达不足发生在哪一层，并据证据决定优先修复输入接线、参数语义、状态投影、表达提示、校验机制，还是进入模型对比或后训练。

“情绪鲜明”定义为：读者能分辨情绪及其变化，表达强度符合当前情境、经历和人格；允许克制、平静与沉默。篇幅、感叹号、依恋措辞或主动联系次数不能单独代表改善。

本次提交仅交付调研计划、文档入口与进度登记。不修改生产 Prompt、Persona、状态算法、模型路由、数据库或部署，不执行付费模型实验，不向 QQ 或其他渠道发送消息。后续实验按本计划分阶段实施；发布与训练不能由诊断结果自动触发。

问题必须分别回答：

1. 状态有没有进入这一次最终回复请求？
2. 进入请求的表示是否保留足够信息？
3. 模型能否正确理解其定义、方向、强度和变化？
4. 理解之后，是否能按人格自然表达？
5. 初稿是否被校验、重生成或交付处理削弱？
6. 改善表达是否损害事实、行动一致性或研究条件？

## 2. 已查明的源码事实与未决问题

下表均针对上述固定提交，不表示线上当前实例一定使用同一路径。

| 编号 | 源码事实 | 对诊断的含义与边界 |
| --- | --- | --- |
| F1 | [内感渲染器](../../harness/compiler/compiler.py)用 `emotion_hint.label` 映射文案，不读取 `emotion_hint.intensity`；`nominal` 提前返回通用平稳描述 | 固定其余渲染输入、仅改变 intensity 时，文本不会随之改变；不能将不可见差异的无响应归因于模型 |
| F2 | [状态摘要](../../harness/homeostasis/models.py)只取前三个主要需要；渲染主要表达方向、趋势和显著性档位 | 原始值、偏离程度与第四至第七个需要可能未形成可见刺激；需记录摘要和最终 messages，不能只看 GUI |

| F5 | [普通角色调用](../../harness/llm/character.py)生成后经过 [Validator](../../harness/validator/validator.py)，可进行修订 | 需要分别评分初稿、各次修订和最终正文；尚无证据证明 Validator 是主因 |

| F7 | [研究 manifest](../../harness/research/grounded_agency/manifest.py)禁止 opaque 条件开启语义内稳态、策略排序与派生情绪；[外层 manifest](../../harness/research/manifest.py)要求表达 off | 分支名称不能证明当前运行 opaque；需取活动 manifest。Opaque 的语义未知是实验条件 |

| F9 | 共享 [HTTP 客户端](../../harness/llm/client.py)普通 chat 默认 temperature=0.7；该方法本身没有显式声明 DeepSeek 思考开关 | 需要核验发送 payload、provider 默认值和代理覆盖；源码默认值不等于实际生效值 |

当前仅有“源码支持的风险点”，没有根因排名的实测结论。尤其不能直接断言 DeepSeek 天生缺少情绪能力，或认为参数语义补充一定优于原实现。

## 3. 假设与可证伪条件

| 假设 | 支持证据 | 削弱该假设的证据 |
| --- | --- | --- |
| H0 输入接线或陈旧状态 | 实际回复请求缺少目标状态；revision 不匹配；QQ 路径只有 persona；缓存复用了旧输入 | 目标信息已按最新合法 revision 完整进入真正生成正文的请求 |
| H1 参数语义不明确 | 在信息量不变时，补定义/单位/方向后，独立理解探针及表达适配稳定改善 | 原条件已准确理解定义与变化，补定义无实质收益 |
| H2 投影丢失强度或趋势 | 不同原始状态的模型可见输入相同；保留丢失信息后出现稳定响应差异 | 原请求已保留被测差异，增强投影无收益 |
| H3 人格或表达指令过度压制 | 仅澄清“克制但可辨”或提供示例后改善，同时保持人格 | 指令变化后仍平淡，或只是产生夸张和人格漂移 |
| H4 生成/校验/交付削弱 | 初稿合适，修订后辨识度下降且缺乏对应事实或机制违规原因 | 初稿已平淡，或修订确实修复违规且没有额外损伤 |
| H5 端点与生成模式影响 | 同一可见输入下，显式模式或 provider 对照产生可重复差异 | 模式无实质影响，或所谓差异来自版本漂移、超时、截断 |
| H6 表达能力/后训练不足 | H0–H5 排查后仍不足，理解正确但表达弱；少样本或另一模型有稳定优势 | 接线或语义修复已解决，尚不需要训练 |

假设可以同时成立。模型在独立探针中说对参数含义，只说明该探针上的可提取理解，不能证明正式生成一定使用了该信息。

## 4. P0：确认运行路径与采集真实请求

### 4.1 路径身份

选取用户标记为“平淡”的 10 条最近回复，并另取 10 条普通回复作背景样本；不足时保留实际数量。先核验每条属于：

- 普通 GUI/Cognitive 角色回复；
- QQ 单人草稿；
- QQ 专用 gate → persona 回复；
- GA model_structured/action_only；
- 其他路径或无法确定。

分别记录活动配置来源、manifest hash、persona 工作副本 hash、代码提交、模型调用阶段、状态目录与会话来源。不能用 builtin 预设替代实际工作副本。GA action_only 没有回复正文是正常结果，不能计为情绪表达失败。

### 4.2 最小请求证据

在真正的 HTTP 请求边界采集脱敏证据，覆盖主模型、辅助判断和所有修订：

- 精确 messages、角色顺序、完整正文、调用阶段及 source/provenance；
- 原始合法状态、profile/目标带、summary、revision、采样时间、编译时间与请求时间；
- 请求 model、响应 model、provider origin、请求 ID（如提供）、时间窗、已知别名映射；
- thinking、reasoning_effort、temperature、top_p、max_tokens、stop 等实际发送值；未发送、provider 文档默认、实际是否确认生效分别记录；
- 初始生成 content、每次修订输入/输出、validator verdict 与触发原因、最终交付前文本；
- finish_reason、用量、耗时、超时和重试、缓存命中/结果复用标记。

不需要隐藏思维链作为证据。凭据、真实成员身份、QQ 原文只进入获准的私有诊断数据，tracked 报告使用脱敏 fixture 和散列引用。对未获准再次发送给云端的数据，使用本地合成等价案例，不静默外发。

若只能得到编译前或 GUI 展示数据，标记 `payload_unverified`，不进入“模型不理解参数”的确认性归因。若实际调用路径无状态输入，先交付 H0 结果和接入建议，再进入下游对照。

### 4.3 无模型的可见性审计

1. 以生产 renderer 编译同 label、同 salience、同 needs/trend，仅 intensity 不同的成对输入。
2. 扫描同一显著性档内的不同偏离程度，并检查最后三名以外维度的可见性。
3. 核对完整 homeostatic segment 是否完整进入请求；既有必需片段超预算会失败，不应先假设被静默截断。
4. 核对心理、关系、会话等可选片段是否丢失或过期。
5. 保存状态差异、summary 差异、文本差异和模型可见上下文 hash。

去除仅供审计、未发送给模型的元数据后，若两组 payload 完全相同，标记 `unobservable_contrast`：不要求模型输出差异，也不花费 live 调用“验证理解失败”。这是表示层问题，不是模型失败。

P0 交付：`route-audit.md`、`visibility-matrix.json`、脱敏请求样本与重现步骤。

## 5. P1：分开检验语义理解、信息丢失与表达风格

以下为拟实现的离线实验条件，不是现有 CLI 选项。每次只更改指定因素；生产状态、人格和输出约束保持冻结。所有实验输出仅写本地证据，不触发聊天交付、记忆写回或身体动作。

### 5.1 双基线，避免混淆语义与新增信息

先固定一套语义路径允许使用的信息 F：状态所属主体、字段定义、量程与目标带、值、趋势、证据范围。不得给不具备标定的关系数值编造临床或概率意义；例如 trust=0.7 不自动等于 70% 可信概率。

| 条件 | 输入处理 | 主比较与解释 |
| --- | --- | --- |
| A-prod | 原样重放实际正文请求 | 产品基线；用于衡量实际收益，不单独用于 H1 因果归因 |
| B0-values | 在冻结的中性任务模板中给出 F 的字段和值，移除解释字典 | 参数理解基线；若 F 比 A-prod 多信息，必须明确记录 |
| B1-defined | 相对 B0 仅增加字段含义、方向、区间定义，不增加“应该怎样回复” | B1−B0 检验 H1 |
| C-verbal | 将 B1 中完全相同的 F 改写为保真中文，保留强度、趋势与不确定性，不推荐动作或亲密程度 | C−B1 检验表示形式与表达利用；不能解释成新增信息效应 |
| D-example | 相对 C 增加冻结的、来自其他场景的少样本表达示范 | D−C 检验可示范的表达能力与风格习惯 |

B0/B1/C 的每个输入都附信息清单；由独立复核者确认除了定义/编码形式，没有新增原因、关系事实、情绪结论或行为要求。无法匹配的样本只作探索性案例。

另设 H2 成对条件：在同一中文模板内比较“当前投影信息”与“仅补入已知但原投影丢失的强度/趋势”。同时保存 A-prod；这种改动明确归类为信息增强，不能称为“模型终于读懂了原参数”。

### 5.2 独立理解探针

复制同一可见输入到独立请求，要求返回短结构化判断，不要求思维链：

- 状态属于谁；哪些字段不足以判定；
- 相对目标带的方向、变化是增强/稳定/缓和；
- 两个状态哪一个偏离更大；
- 已证实的原因、仅可能的解释和未知信息；
- 对无定义字段是否承认不确定。

评分依据冻结的字段契约；纯符号且没有学习经历的 opaque 条件不设置人类情绪“标准答案”。理解探针输出不能再喂回正式回复样本，以免测量本身提供答案。

### 5.3 人格与校验的单因素对照

在 C 的基础上单独增加 E-style：“保持慢热、轻柔和克制，但让不同情绪在措辞、节奏与关注点上可辨；强度服从情境，允许平静。”保留所有事实边界与人格核心。此处文字是实验处理，不能混称原人格行为。

先比较同一实际初稿与各次修订，定位 H4；必要时只在离线评分支路旁路 Validator 作定位实验。旁路输出不用于交付，也不能作为生产发布候选。任何生产改进仍须通过原有校验与独立人工事实审查。

同时检查 calm/attentive 是否为仍有效的当前状态，不能为了让模型更激动而直接删除真实平稳状态。

## 6. 场景、采样与评分

### 6.1 探索样本

设计 12 个匿名场景族，每族至少两个保持其他条件一致的状态/历史变体：

1. 精力充足与精力不足；
2. 认知负荷平稳与偏高；
3. 可预测情境与信息不足；
4. 胜任感受挫与获得可验证进展；
5. 选择权充分与受到限制；
6. 连接需要与社交密度过高；
7. 新鲜感不足与刺激过量；
8. 疲惫且愿意交流的冲突需要；
9. 不适稳定与正在缓和；
10. 同一 label、同档 salience 下的强度差异；
11. 相同用户话语在偶尔失约与多次失约的客观历史下；
12. 平静和证据不足的负对照。

内稳态是需要/状态信息，不唯一决定开心、愤怒、依恋等人类情绪。评分接受多种符合事实的表达，不能预设连接不足必然委屈，或把情绪越强计为越好。

先选 6 个场景族、每族 2 个变体，每条件重复 3 次。A-prod/B0/B1/C/D 共 180 次首轮回复调用；独立理解探针对 B0/B1/C 各运行一次，共 36 次，计划基础规模 216 次。额外模型修订、helper、judge 和 E-style/模式实验单独计数；重复生成不是新的独立场景。

在请求前依据 P0 实测 token 量与当时 provider 单价估算总费用，设置有界请求数、修订次数和累计费用上限；上限值进入冻结运行配置。先运行无外部交付的小样本，预算不足保留已完成 evidence，不自动扩样或切换付费模型。

### 6.2 评分量表

两位人工评分者先用少量非测试样本校准；隐藏模型、条件名、生成顺序及 expected win。评分者看到必要的合法情境事实，但不看到处理标签。模型裁判只能辅助，必须记录其版本和提示，并人工复核争议与全部高风险错误。

每条回复分别评分：

| 指标 | 评分方法 |
| --- | --- |
| 情绪辨识度 | 1–5；平静可辨同样合格，不按标点或篇幅判分 |
| 情境/状态适配 | 1–5；检验强度、趋势、混合需要与事实的一致性 |
| 人格一致性与自然度 | 各 1–5；克制不等于没有区分，避免客服与漫画化反应 |
| 事实/行动一致性 | 二元违规标记并附证据：虚构经历、错误归因、把未执行动作说成已完成 |
| 机制泄漏与无依据身体症状 | 分项记录，沿用既有规则与人工核验 |
| 平稳状态过度表达 | 负对照中过度不适、亲密或冲突表达比例 |
| 多轮连续性 | 验证阶段每段 4–6 轮；是否随新证据调整、是否反复重置情绪 |
| 代价 | 总调用数、token、请求/端到端延迟、修订率、错误率；没有流式遥测时 TTFT=null |

主指标预先指定为“情境/状态适配”配对差；情绪辨识度是共同报告的次指标。不能仅凭更生动但更不符合事实的输出判成功。保留原评分与分歧，不用讨论后的一致评分隐藏原始不一致。

### 6.3 确认与决策口径

Pilot 用于检查可行性、费用和方差，不得直接作效果确认。用未见的新场景与新历史构造确认集，先冻结主要比较、最小有用效应、样本量和排除规则。以至少 30 个独立配对场景/episode 为初始规划，按 pilot 方差和资源重新估算；30 不是通用充分样本量。

同一场景的多次输出先聚合；按独立场景/episode 做 cluster bootstrap，报告配对差和 95% 区间。若存在多个预注册主比较，使用 Holm 校正。按路线和场景族分层报告，不能由总均值掩盖负对照或某一维度退化。小分层样本只作描述性结果。

建议在确认前冻结以下工程决策标准：

- 适配评分改善至少 0.5/5，配对差 95% 区间下界大于 0；
- 自然度与人格一致性不劣于基线 0.25/5 以上，以非劣界评估，而非只看点估计；
- 负对照过度表达增加不超过 5 个百分点，报告区间；证据不够则记 inconclusive；
- 机制泄漏、虚构执行和无依据身体症状出现任何已确认案例，候选先修复再评估；零例只表示样本内未见，报告样本量与不确定性；
- 延迟与费用满足执行前冻结的部署预算；不临时降低质量门槛换通过。

以上是本调研建议阈值，不覆盖或降低既有发布门禁。未达到阈值可得出“未支持该改进”，不能据此证明模型永远没有该能力。

## 7. DeepSeek 端点与版本控制

官方 2026-09-10 发布说明将 V4.1 Flash 的 API model 标识写为 `deepseek-flash`，并说明旧 Flash 别名会路由到新模型。当前思考模式文档说明默认启用，thinking 下 temperature 不生效。第三方转发服务可能有不同映射，必须依据实发 payload 与供应商证据核验，不能把设置存在等同于生效。

P2 模式对照在 C 或选定固定输入上单独进行：

- 显式 thinking enabled 与 disabled；
- 思考 effort 固定并记录；只在支持且有效时比较采样温度；
- 不同时更改 Prompt、模型、token cap 和模式；
- 限额需容纳推理与正文，记录截断/空正文；截断样本保留并计入失败率，不挑选重试成功样本。

模型别名无法固定后端版本时，记录请求/响应身份与时间窗，将各条件交错运行；发现升级或路由改变则拆分分析。不能仅用相同 model 字符串宣称相同模型。

官方资料证明接口和模型版本信息，不证明其情绪表现优劣。思考模式可能影响结果是待测假设；不预设关闭思考必然更自然。

## 8. 与 Grounded Agency 的隔离

本计划的 B/C/D/E 等情绪表达实验用于产品语义路径或显式声明的语义对照，不进入 opaque 核心条件。

必须保持：

1. `opaque_current/history` 继续关闭语义摘要、derived emotion 和 homeostatic expression；不绕过 NeutralityScanner。
2. 不向核心模型、belief appraiser 或其记忆提供隐藏真值、符号映射、评估答案或人工情绪归因。
3. 不新增固定信任奖励、依恋 drive 或“用户特殊”的目标函数。
4. 报告阶段若加载表达适配器，不得改写已提交决定；表达回流历史仍会影响后续决定，必须纳入实验 treatment。
5. action_only、无表达适配器与有适配器条件分别冻结；不能仅凭文本后处理隔离就声称未来行动不受影响。
6. 符号学习另用 GA 现有历史、客观经历、belief 消融与反转评测，不能用“补上符号解释”宣称中性条件学习成功。

普通表达 PASS、GA 工程机制 PASS、功能性自主研究支持是三个不同结论。

## 9. 实施任务与复用范围

| 阶段 | 工作 | 交付/完成条件 |
| --- | --- | --- |
| P0 接线与可见性 | 读取实际请求、核验路线、离线 renderer 对比 | 能将样本定位到具体路径；不可见/陈旧输入先单列 |
| P1 诊断工具 | 复用现有表达证据采集；增加隔离请求回放、信息清单、条件 hash 和理解探针 | 离线 fake 能证明条件只改指定因素；没有交付或生产记忆写回 |
| P2 Pilot | 执行有界样本与必要模式对照 | 全部调用、失败、费用、评分可追溯；选出待确认假设 |
| P3 确认 | 新场景盲评、成对分析、多轮连续性 | 给出效应区间、分层退化、支持/不支持/不确定结论 |
| P4 修复建议 | 按根因选择接线、投影、提示、模式或训练方案 | 形成具体补丁/独立训练设计；不由计划提交自动实施 |
| P5 产品回归 | 候选接回真实生成路径并复验 | 满足原表达门禁与相关动作/事实回归，研究条件无泄漏 |

优先复用：

- [现有表达评测](../../eval/homeostatic_expression/README.md)及其 production/evaluation 证据采集；
- [工作决策分层评估](15-homeostatic-decision-evaluation-design.md)中的可见性检查思想，不重复发明工作/恢复效果指标；
- [GA runner](../../eval/grounded_agency/README.md)的条件冻结与证据隔离；
- [QQ 草稿](../../harness/qq/draft.py)、[QQ 决策](../../harness/qq/decision.py)的实发请求，用于排查真实投诉路径；
- [调用日志](../../infra/trace/call_log.py)与 [HTTP 客户端](../../harness/llm/client.py)作为证据边界。

若实施需要新增诊断模块，建议目录 `eval/emotional_expression_diagnostics/`；这是待实现位置，本计划不提供虚构的可运行 CLI。普通语义表达、QQ 和 GA 的样本分开保存，不假设原有表达评测已经覆盖 QQ 或 opaque。

既有表达发布评测要求九类条件、每类至少 30 对及独立 fresh-state soak。本调研的离线替换输入和旁路实验统一 `release_eligible=false`，不能直接替代原门禁。只有候选改动正式接入生产路径后才按原规程回归。

## 10. 根因到改进的决策表

| 观察结果 | 下一步 |
| --- | --- |
| 最终正文请求没有状态 | 修复该路径的状态接入或明确其不使用内稳态；不先训练模型 |
| 不同状态生成相同可见输入 | 修正信息投影，显式处理强度、趋势和相关证据；先验证表达收益 |
| 补定义有效，中文转换增益有限 | 增加精简的参数契约和标定说明，无须新增情绪生成模型 |
| 理解探针正确，示例/风格澄清有效 | 优先少样本/提示方案；稳定收益后再考虑 SFT 固化 |
| 初稿良好、修订削弱 | 检查具体误判，修复校验规则；保留事实与动作保护 |
| 模式/供应商差异显著 | 固定合适配置，记录版本与成本，不归因为人格或参数语义 |
| 以上不足，其他模型在同一实验中更好 | 评估更换表达模型或开放权重模型后训练的收益/成本 |
| 只提升文风，状态适配和多轮连续性不变 | 记录“表达风格改善”，不声称情绪状态建模或自主能力改善 |

云端 DeepSeek API 调用权不等于拥有其微调接口。进入 SFT/LoRA/DPO 前，单独核验供应商是否提供训练服务、权重许可、训练资源和数据使用条件；不能假设可以在当前 API 上直接加载 LoRA。若另用开放权重表达模型，视为新增模型/路由处理，重新做事实与未来决策回流对照。

## 11. 证据清单与最终报告模板

拟议每次运行保存：

- `run-manifest.json`：源码、provider、模型/Persona/Prompt/状态 hash、费用上限、条件定义与排除规则；
- `route-audit.md`、`visibility-matrix.json`：路径、缺失字段、相同输入与未决项；
- `requests.jsonl`：独立案例/变体/重复/调用/修订 ID、处理因素、实发参数、响应身份、初稿和最终正文引用；
- `ratings.jsonl`：匿名评分、评分者、分歧、证据引用；
- `analysis.json`、`report.md`：样本流向、失败率、区间、费用与根因结论。

以上为拟议文件名；本次没有生成或声称存在真实运行证据。公开脱敏副本和私有原始证据分别做 hash，不把脱敏后正文的 hash 当成原请求 hash。

最终报告逐项填写：

1. 核验过的真实运行路径与模型身份；
2. 状态是否可见、信息是否充分；
3. H0–H6 各自为 supported / not_supported / inconclusive / not_tested；
4. 参数定义、信息增强、表达风格、Validator 和模式各自的效应；
5. 负对照、事实/行动错误与多轮退化；
6. 最小必要修复和是否值得后训练；
7. 未覆盖的路线、版本、样本与研究结论。
