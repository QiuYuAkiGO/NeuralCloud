# 每日经历清洗与认知修订

每日修订在 Cognitive 服务内运行，使用独立外部模型清洗经历、综合历史并独立复核，然后原子更新现有记忆、印象和关系。原始来源不改写。实时 QQ 同化、本地对话和每日修订共用证据身份与派生对象。

## 配置与启动

复制 `presets/daily-revision.example.json`，填写密钥文件的**绝对路径**，将 `NC_DAILY_REVISION_CONFIG` 绑定到配置文件的绝对路径。密钥文件只包含 API Key；Linux 文件权限为 `0600`，不提交到仓库。配置端点必须与密钥所属服务匹配。默认使用 `https://api.moonshot.cn/v1` 的 `kimi-k3`，也支持配置其他兼容严格 JSON Schema 的 HTTPS 端点。

默认未启用。凭据准备好后设置 `enabled=true`；启动后按北京时间 03:00 处理前一自然日，首次补跑最近 7 个完整自然日。每日额度 `daily_token_budget=null` 表示不设日硬上限；单次输出仍限制为 32,768 tokens，并发为 1。额度按实际请求日计算，补跑历史日期不会绕开今天的额度。用量包括思考所用的 completion tokens；网络结果不确定时保留预算预留，不假装未计费。

修订配置仅传入 Cognitive。模型不可用、配置错误和额度不足会反映在修订状态中，不使用主模型或辅助模型替代。

## 运维界面与接口

共享 GUI 的 `/daily-revision` 页面提供配置、历史、证据、变更预览、手动运行、重试和回滚。它使用经过认证的 Runtime 控制面 `/v1/cognitive/control`：

```json
{"operation":"daily_revision.run","payload":{"day":"2026-09-14","dry_run":true}}
```

操作包括 `daily_revision.status/history/detail/run/retry/rollback/configure`。运行立即返回任务标识，模型在后台执行。`dry_run` 保存完整预览，不提交角色状态。详情中的证据是原文数据；界面不展示密钥或模型思考内容。正常共享运行通过独立记忆维护权限操作，不开放通用 debug 修改权限。

## 处理规则

1. 冻结共享来源的插入水印，分页读取发生时间范围内的原文。覆盖本地聊天、QQ、已回读核验的留言板和已验证完成的行动。提交归档早于会话窗口截断；旧记录的缺失时间或行动凭证以覆盖缺口报告，不伪造完整历史。
2. 按角色、会话和可见范围分区。K3 清洗所有记录并保留保留/合并/忽略结果；综合阶段产生事实候选、印象及关系调整；独立复核重新检查原文和反证。输出截断、证据不完整或审核否决，整个分区均不提交。
3. 发言保留作者归属。引用、自述完成、图片解释、自身反思和自身总结不成为对他人的新独立支持。历史清洗中的降级分类继续保留。人物身份和关系 target 由程序赋予，不由昵称猜测。
4. 同源重跑或换模型不增加独立支持。合并经历只计一次；反证能够降低置信度。印象保留第一印象与修订历史，事实仍经候选阈值固化；争议和已替代事实不作为确定事实检索。
5. 关系四维每个目标每日变化上限：亲近/信任/依恋各 `0.05`，近期紧张 `0.15`；依恋增加需要跨日独立支持。重新解释替换原贡献，数值和文字一起提交。

派生判断通过按权限过滤的上下文进入下一次对话，明确标为可修订判断；不把模型结论伪装成对方原话。情绪模式原有分工保持不变。

## 提交、故障与回滚

SQLite 保存任务、来源冻结、阶段缓存与预算；角色 preset 的原子保存是唯一生效点。模型计算不持前台锁，提交时检查 owner 和相关结论基线。前台新增的独立对话保留；基线变化使综合与复核重新运行。已通过阶段缓存按请求内容寻址，可用于中断恢复。

保存、发布或任务确认失败后，通过 preset receipt 恢复，不重复增加置信度。语义错误的重试保留有效清洗，但重新综合和复核。401/402/403、额度耗尽及反复模型错误可在界面查看和修复。

第一次纳管时记录现有状态基线；此后的外部写入和日修订均进入变更记录。撤销批次通过重放有效贡献恢复受影响对象，保留之后的独立修改。依赖被撤销解释的后续任务失效并重新排队。被直接撤销的原批次保留永久标记，不会在普通重启恢复时重新生效。

维护暂停、备份和关闭会等待真实运行中的后台任务。取消等待不意味着底层 HTTP 已停止，Cognitive 在实际结束前保留 owner 锁。部署备份包含修订配置、密钥引用及任务数据库，并按迁移目标重写路径。

## 隔离历史回放

先取得同一实例的只读共享库与 preset 快照，再运行：

```powershell
uv run --no-sync python -m harness.memory.revision --config C:\private\daily-revision.json --source-db C:\snapshot\shared-memory.sqlite3 --preset C:\snapshot\misty.json --output C:\snapshot\revision-preview --self-member-id 2015188508
```

输入数据库使用 SQLite backup 复制到输出目录后处理；原数据库和原 preset 不写入。默认回放最近 7 天，也可传 `--start YYYY-MM-DD --end YYYY-MM-DD`。输出包含 `revised-preset.json`、任务数据库和不含密钥的 `report.json`；出现错误保留进度，重跑使用已完成的模型缓存。该工具只修改隔离副本，正式生效使用服务的日修订任务。

## 验证

`tests/test_daily_revision_*.py` 覆盖来源、模型协议、预算、队列恢复、作用域、关系上限、反证、贡献重放、PostgreSQL 迁移、服务生命周期、权限和界面。实机模型调用及历史回放的验收应保存独立报告，并区分合成样例、真实历史副本与正式实例结果。
