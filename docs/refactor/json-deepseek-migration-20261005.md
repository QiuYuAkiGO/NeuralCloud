## 调用范围

通过 `NC_STRUCTURED_LLM_CONFIG` 显式启用独立路由。配置只包含 `model=deepseek-flash`、绝对路径 `api_key_file` 和 `cache_friendly_inputs=true`，不在仓库保存密钥。统一使用官方 `/responses`、`text.format=json_schema`、`reasoning.effort=none`。

| 场景 | 接入方式 |
| --- | --- |
| 解析、复杂度判断、社交解释、检索规划、记忆整理/洞察/分层 | 为现有 `complete_json` 补充实际输出 Schema，经独立路由发送 |
| 回复校验 | 独立结构化路由；保留调用时限及输出预算 |
| QQ 发言决策、生产决策与评估、能力/目标/网页/留言板/日记/终端决策 | 已有 typed decision 自动解析独立提供方 |
| 情绪评估、情绪指引 | 使用同一独立提供方和实际 Schema；保留情绪降级规则 |
| QQ 记忆 | 动态 Schema 保留真实来源 ID、作者范围和私聊约束；继续执行本地证据校验 |
| Agency、身体信念、实体评估 | 为原先返回 JSON 的聊天调用补充 Schema |
| 日记式每日记忆修订 | 独立 HTTP 调用适配 Responses；保留三阶段校验、检查点、预算、计量和重试规则；线上功能仍关闭 |
| QQ 图像描述、屏幕读取 | 支持 user 图像内容到 Responses 的无损映射；通过模拟传输验证，未启用原本关闭的视觉功能，也未声称做过真实图像 API 验收 |

结构化对象中自带 `text` 的生产/留言板/日记任务会整体交给 DeepSeek。普通自然语言调用保留原主模型及正文备用通道。旧自主聊天的首行 `silent/speak` 协议没有改成 JSON。

未配置独立通道时保留原有行为。上游错误、截断、无效 JSON 或不满足 Schema 的输出不会自动转交 Qwen/辅助模型，也不会修补成合法结果；各业务原有的失败处理仍生效。引用、权限、实时预算等语义检查继续在本地执行。

## 缓存策略

固定系统规则、Schema 与人格优先，稳定记忆和历史随后，当前事件、情绪/稳态数据、当前来源集合及生产预算后置。只重排用户 JSON 顶层字段并紧凑编码，不改变消息角色、数组顺序、嵌套数据、来源归属或实时值。不以填充无用文本提高百分比，不保留已撤回的记忆。

旧辅助提示中可无损表达为 JSON 的 Python 字典也使用同一布局；有重复键、非有限数、元组等不能无损转换的输入维持原样。保留既有 QQ 分块历史、人设前缀与生产提示优化。QQ 记忆不再在用户正文中重复完整 Schema，但仍在解码约束中发送同一动态 Schema。

本地按原请求标识复用的情绪结果、每日修订阶段检查点等保持原有生命周期；没有跨当前事件复用模型答案。API token 命中率与本地答案复用是不同指标。

25 类项目协议各验证一次，再对 QQ gate、情绪 guidance、生产 choice 各进行两种布局 × 6 次请求，共 **61/61** 返回通过 Schema/Pydantic 校验。每次都更新当前事件和预算，第 5 次移除一条记忆，用真实人格与合成任务，全部不执行模型提出的动作。

最初的记忆合成测试错误要求空 `episodes`，与现有 `minItems=1` 冲突：10 项通过，第 11 项被本地 Schema 校验拒绝。修正测试为一条有来源的问候经历后完整重跑；协议未放宽。失败轮次及费用预留仍记录在证据中。
