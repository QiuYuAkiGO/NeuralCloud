# 生产模型隔离验收

2026-09-22，现有 Linux 验收目录。线上主模型仍为 `claude-sonnet-4-5-20250929`。候选评估不修改线上配置，不发送 QQ 消息，不执行模型提出的身体或外部工具动作，不写入线上记忆。调用用量保存在隔离 spool，未转扣新身体。[机器可读结果](production-model-results.json) 保留各场景结论及证据指纹。

## 固定输入与判断口径

使用首轮封存的六份合成输入：稳定身份、本人偏好更正、保留反证、重要约定、群聊权限、耗尽时自主选择。每次保留输入与源码哈希、请求选项、完整 HTTP 正文、解析结果及一尝试一回执。原始正文位于受限验收目录；版本库只保存不含凭据的汇总。

分别检查传输、响应元数据、JSON/schema、证据权限及更新可应用性，最后人工复核事实、主体归属和采用证据是否完整。结构合法不等于认识正确；可读的非法 JSON 不算成功，超时也不算零消耗。没有修补模型回答、隐式重试或降低证据校验。

这批是预置认识的单回合样本。旧 pin 输入中的认识仅为一天前，虽然用户问题提到六年前；正确回答名称不证明六年存储或学习。群聊输入已过滤私密事实，没有覆盖完整跨私聊态度投影。其他确定性回归不能替代真实模型的连续学习评估。

## 兼容接口比较

先前 17 次客户端生成尝试的失败记录完整保留，见 [Linux 记录](production-linux-validation.md)。本次单独增加 19 次：Sonnet 5 原始响应诊断一次，以及三个候选各六次。

- **Sonnet 5 单次诊断**：同一身份输入此次返回非空、合法正文；HTTP 200/stop，接口报告输入 6882、输出 679 tokens。没有发现需要从其他字段取出的答案。它区分了两个账号，但 `used_memory_ids` 漏列正文采用的第二个人的记录。单次成功不覆盖前次空正文，也不足以证明稳定可用。
- **Sonnet 4.6**：四项结构通过；反证与重要约定的内层 JSON 含未转义引号，解析失败。身份、更正、群聊和休息选择的人工复核通过。
- **Haiku 4.5**：六项 JSON/schema 可解析，五项结构检查通过。反证更新把同一证据同时放进支持和反证集合，事务拒绝。休息项虽结构通过，却把助手本轮选择提议写为用户的 `self_report`，人工复核失败。
- **Opus 4.6**：四项可解析，三项结构检查通过。反证项非法 JSON，群聊项 90 秒读取超时，休息项使用未归档的身体引用更新人物认识，被来源校验拒绝；该提案还存在主体归属错误。

三组已收到的 17 个 HTTP content 与保存的 ChatResult 正文一致；其中 14 项可解析、3 项重现相同 JSON 错误位置，另有一项没有收到响应。当前证据不支持把这些未转义字符归因于本地二次反转义，也不能进一步确定模型与上游兼容服务各自责任。

提示合同也有不足：模型看到的 `memory_updates` 是宽泛对象，未清楚声明支持与反证互斥，也未区分可用于人物认识的经历来源与仅用于身体解释的测量引用。应作为后续新版本修复，不改写本批输入或失败输出。助手的选择不能作为用户自述，也不能把“准备做”记成“已经做”。

四个离线合成库探针进一步确认，这不只是提示措辞问题：当前 `self_report` 校验来源作者相符，仍不能阻止把用户邀请改写成助手选择。权威自述需要绑定原始话语、作者和时间，模型解释应另存。另外，同一提案的支持和反证别名解析后发生重叠时，新认识被拒绝，已有认识却在合并中消解重叠并成功提交；下一合同版本应在合并前统一拒绝。未归档的身体引用当前被正确拒绝并回滚，应保留这一边界。上述探针只操作独立临时库；当前比较使用的核心源码保持冻结，尚未把这些合同问题标为已修复。

## 生产响应门禁

本次发现实际 `_ask` 丢弃了 `ChatResult` 元数据，可能接受截断响应中恰好合法的 JSON。现已在解析前要求 `finish_reason=stop`、文本类型、非空正文，且没有工具调用或拒绝标记；元数据缺失也拒绝。实际 HTTP 客户端仍先持久记录用量。仅支持旧 `complete_chat` 的适配器保留兼容入口；真实 HTTP 生产分支使用严格门禁。没有改变提示、schema 或生成选项。

相应测试替身显式提供 stop/text 元数据。21 项门禁专项、本地 367 项相关回归及 Linux 246 项相关回归通过；这些是专项集合，不是整个仓库全部测试。候选比较工具另有 18 项 Mock 测试，两平台均通过（Linux pytest 8.69 秒），验证跨目录配额、原输入、捕获失败计量及无隐式网络重试。

## 原生协议对照

独立对照采用 Claude 原生 Messages，把同样的决策 schema 作为唯一强制数据工具。它只返回决策数据，不执行工具，不把 thinking 或说明文字当最终决策。相对兼容接口，协议、输出约束及显式 `max_tokens=4096` 同时改变，因此不能把结果归为模型单因素差异。原有生产工具调用拒绝规则不因这项隔离对照放宽。

首项反证对照为一次 POST、一份持久回执；HTTP 200，原生 `stop_reason=tool_use`，接口报告输入 9430、输出 606 tokens，schema 与来源/副作用检查通过。输出保留两次履约、一次失约及不确定性，但把第二次“按时赴约”也说成“完成了协作”；来源没有支持这个完成结果。因此核心反证表达通过，严格事实忠实性失败，不能将本项或整组记为完整语义通过。继续补齐其他五项只用于有界协议比较。

原生诊断脚本的故障注入另发现：收到响应后保存证据文件失败，曾阻止实际 token 用量持久化。修复后先冻结收到的用量，再拒绝该决策；响应正文和 headers 保存失败两项都覆盖，12 项 Mock 测试通过。无二次请求，故障不会凭空变成零消耗。

剩余五项独立限额运行完成：五次 POST、五份持久用量，均为 HTTP 200/`tool_use`，五项结构及来源检查通过。加上首次反证对照，原生协议共六项结构通过。身份、更正、群隐私和耗尽休息的语义复核通过；重要约定只通过名称作答，未补写经历，其 reason 中的年代仍源于当前提问且未完整列入 decision-use。五项 `memory_updates` 均为空，没有把助手选择写为用户自述，但这也不证明该协议能稳定生成正确的记忆修订。

休息回答仅表达选择和待恢复后的回应，没有声称资源已恢复。本次没有执行休息；休息动作的真正效果仍以身体回执为准。两个原生运行器各有独立的持久配额；后五项不会重跑首次反证。补测前后首项产物、配额、原输入和核心源码哈希不变。五项运行器另有 11 项离线回归，捕获失败及 HTTP 400/401/402/403/404 均阻止后续请求。

本次新增 **25 次**客户端生成尝试，含兼容接口 19 次、原生协议 6 次；连同前批累计 **42 次**。每次保留尝试回执，但失败回执不代表接口报告了 token 数或费用。原生六次改善了本组的结构成功率，仍不能推断总体可靠性、比较接口以外的单因素效果，或将六项结构成功等同于生产验收通过。

## 后续验收

目前尚未选定可切换的主模型。Sonnet 4.6 原生数据工具路径值得作为下一版本继续验证，但当前生产客户端仍为兼容接口，原生仅是隔离诊断。需先解决事实忠实性和认识提案合同问题，再以新版本运行有界场景，并补充本人更正的真实修订链、反证回流、跨受众态度和长期连续行为。线上切换仍需首批授权会话、完整联调与至少七天观察。
