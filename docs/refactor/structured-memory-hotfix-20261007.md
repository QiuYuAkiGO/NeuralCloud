# QQ 后台记忆结构化响应热修复

已部署 `20261007-structured-memory-hotfix-v2`，代码提交 `60dc1a5`。六个服务 active、Runtime RUNNING、QQ 已连接，watchdog 为空。内稳态继续使用 `qq-social-drive-v1@3` / manifest revision 4 / shadow，数学规则、群权限与群接收策略未改。[部署、复现和恢复证据](../harness/evidence/structured-memory-hotfix-20261007/deployment.json)。

## 原因与证据

历史请求日志只保留 `StructuredResponseError` 类别，无法判断具体字段。选取一个达到 8 次重试上限的任务，在当前群接收权限允许下，以原冻结消息和当前上下文作受限生成复现：供应商返回 completed、完整 JSON，但两条人物印象缺少 `subject_refs`，本地 JSON Schema 的条件 required 校验拒绝了它们。省略上下文的先行探针没有复现；包含实际 persona 和相关旧印象后才复现，不能把先行探针视为原请求的等价回放。

旧在线 schema 的 `subject_refs` 有兼容历史记录的空数组默认值，只在 kind=person 的条件分支里被要求必填。模型可以输出漏掉该字段的完整响应，严格本地校验正确地拒绝。传输层拒绝发生在 proposer 的业务校验反馈循环之前，因此任务队列会重复调用，最终达到 8 次上限并跳过。复现能确认这一类具体故障，不能据此断言所有历史通用错误原因完全相同。

## 修复

- 在线 schema 无条件要求显式 `subject_refs` 并移除其在线 default；person 给一个来源身份，relationship 至少两个，topic/group 给空数组。
- 保留存储 DTO 默认值以读取旧记录；人物形状、来源身份枚举、群范围、引用和业务证据校验继续执行，不填造缺失身份、不接受原本不合法的响应。
- 结构化错误保留细分错误码及有限的 schema 字段路径、缺失字段；不记录字段值、未知键、供应商原文或 jsonschema 错误原文。

首轮 98 项针对性测试、83 项回归测试通过；历史任务恢复另运行 126 项测试通过（各轮可能有覆盖重叠，不视为唯一测试总数）。3 个过去达到重试上限的任务，用修复后的 schema 重新生成，均通过 schema 和业务证据校验。真实探针只用于验证，没有提交生成记忆；实际加工量正常记账。

## 历史任务恢复的第二层故障

首版上线后，结构化生成恢复成功，但 8 个历史任务在提交时触发 `impression evidence must be replayed in chronological order`：它们的证据早于后来已经形成的印象。第二版保留原有时间顺序保护，允许历史经历入库，对早于当前最新证据的印象增量明确记录 `historical_evidence_before_latest_impression`，不覆盖更新判断、不更新时间来伪装为新证据。8 个原失败 proposal 离线重放全部通过，共有 9 条印象增量暂不应用；无需生成新响应。支持和反证两个方向、重复提交幂等均有测试。
