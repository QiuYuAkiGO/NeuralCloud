2026-09-22。对应 [机制实现报告](production-memory-evidence-v2.md)。本轮修改候选代码并验证，不切换线上模型、会话或数据库。旧模型验收的 42 次请求及原始失败样本保留，不能按新合同重新计为成功。

## 实现范围

- 以最终发送给模型的原文视图签发持久来源清单；提交时检查片段、作者、版本、受众、撤销状态与已展示目标的修订号。当前长消息即使没有进入可引用视图，也仍在提交前检查撤销。
- 自述主展示内容由服务端取自原话，模型改写独立标记为暂定解释。支持、挑战、限定、背景与混合关系绑定具体判断版本及片段；引用匹配不提高事实可信度。
- 每个依赖组原子校验，独立组分别接受或拒绝。组内字段错误也进入耐久待办，不丢弃其他合法更正；任何组被拒绝时，本轮潜在依赖它的回复保守阻止交付。
- 同一 ID 的主体、主题、情境、分类及有效区间保持不变，直接自述还固定原始发言身份集合。新的本人偏好更正使用新记录及明确更正关系；旧版在生效前仍可用，撤销新版不会自动恢复旧偏好。精确重复检查覆盖未来窗口，但不尝试证明不同改写语义相同。
- 新表与既有有界索引连接，召回、历史、GUI 和撤销采用相同有效性检查。旧数值标记 `legacy_confidence`，旧自述仍是旧解释。普通对话、QQ 生产认知均接入新提交路径。
- 模型上下文曝光移到预算预留成功后的传输尝试边界；预算拒绝不记曝光。传输失败只证明尝试发生，不声称服务商已阅读。实际返回用量与记忆校验成功与否分开保存。

## 独立模型诊断的边界

最终代码的 Linux 回归 **536 项全部通过**，pytest 用时 **82.61 秒**，两项旧依赖提示；清单文件在测试前后哈希一致。没有在最后时间修复后重跑真实模型，因此模型结论仅属于前述冻结候选，不能称为最终版本六场语义通过。机器可读结果与最终核心哈希见 [production-evidence-v2-results.json](production-evidence-v2-results.json)。

[验收工具](../../tools/production_acceptance/evidence_v2.py) 默认不联网，执行真实请求需显式 `--execute`。使用现有主接口密钥只读读取，固定 Sonnet 4.6 原生 Messages 的单个强制数据工具，最多六次请求、无重试、跨运行名耐久限额。该适配器只用于隔离诊断；没有改动生产 OpenAI 兼容接口，也不执行回复发送、工具动作或身体结算。

六个新合成场景为：当前偏好更正、转述他人、假设语句、同回合允许休息并更正本人偏好、赴约支持与迟到经历、未来生效偏好。每场调用实际 `_ask` 与 `_commit_memory`，保存精确请求字节、完整响应、安全响应头、来源清单、原始提案、提交回执和真实用量。任何响应保存失败立即停止后续请求，已收到的用量仍保留。

自动通过仅表示结构、来源、提交及部分可机械判断的投影检查通过。还需逐条阅读原话、模型解释与关系，评估归属、事实扩张和反证处理。场景在提示中明确了歧义，有些旧偏好是合成预置；它们不能证明无提示自然会话的长期学习能力。

## 真实模型结果

原生 Sonnet 4.6 第一场“当前偏好更正”返回 HTTP 200，但提案组 **未通过校验**。本次实际发起 **1 次请求**、保留 **1 份用量收据**；后五场按首场门禁停止，没有重试。原始响应与请求均完整保留，配置与源码哈希未变，外部动作和 QQ 发送均为零。

逐项复核发现：模型理解了“咖啡改乌龙茶”，没有推断人格，却额外提出了旧记录截止时间修改，遗漏旧记录的主体字段；一个 17 字片段声明 `end=18`。实际最先触发的是 `evidence_anchor_span_invalid`，库内组回执为 `evidence_group_schema_invalid`。同组的新偏好也未写入；数据库仍只有预置旧认识 r1，错误提案留在 pending 队列。这符合依赖组原子拒绝规则，不能把未写入的新偏好计为“已学会”。

模型还把原先“我喜欢咖啡”的原话标成对旧咖啡偏好的挑战，混淆了过去的支持与当前更正。它生成的回复声称已经记住，但诊断没有发送任何文本。引用/结构门禁阻止了这次错误写入；它并未证明模型的证据关系解释可靠。

服务商报告 `input_tokens=13324`、`output_tokens=1242`，来源为 API 实际返回，不使用适配器默认空 usage 代替。`reported_response_model` 为 `claude-sonnet-4-6`，不能由该标签独立确认底层模型身份。本轮不建议因此切换生产主模型。

原始证据：Linux `evidence-v2-six-real-v1` 子目录；本地 `.tmp/production-linux/evidence-v2-six-real-v1-export`。导出归档 SHA256 `6872bf2698e7bbcb482d609e58766cfd0e23584c6c2c61bffc79ff64acb9995c`。原有 42 次模型验收仍保持原记录，本次另记 1 次，不以跳过场景充数。

## 尚未覆盖的能力

`pending_tasks` 和 `resolve_task` 提供持久查询及明确处置，目前没有自动模型重试 worker。GUI 显示本地受众最多 32 项待办，不能把待办状态理解为学习完成。精确去重不覆盖语义同义改写。

Runtime 控制版本检查与记忆 SQLite 提交没有变成跨服务原子事务；情绪、目标、交付及认识也没有新增统一事务。既有交付保护继续生效，本轮故障测试的证明范围限于所测提交边界。

本轮未重测十万/百万规模、冷缓存或持续维护积压，也未完成线上七天观察。不得把旧性能样本作为 v2 性能结果。回退需保留新库及 v2 reader；旧 writer 只能使用独立旧副本，不能覆盖已产生的新认识、撤销、交付或资源结算。

真实模型诊断后再次核对线上 `deploy.json`、`manifest.json`、`gui-settings.json`、`direct.json`，哈希均与原基线一致；四个 NeuralCloud 服务仍为 active，线上发布目录仍为 `/opt/neuralcloud/releases/20260920-qq-memory-latency-v1`。没有切换线上会话、主模型或数据库。
