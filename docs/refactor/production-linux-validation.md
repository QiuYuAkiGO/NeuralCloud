## 真实模型样本

首轮六个合成场景调用实际主模型，共六次请求；身份区分、更正、群聊权限和耗尽休息返回合法结构，反证与长期记忆两个场景返回 JSON 解析错误。所有尝试各自保留用量，未发送 QQ 消息、未调用身体或工具、未写入线上记忆。

随后只重跑两份原始冻结输入，在解析前保存完整响应。这两次均为 HTTP 200、`finish_reason=stop`，正文含未转义的字符串内双引号，再次解析失败；不是截断。首轮未保存完整失败文本，因此不能追认首轮的具体字符错误。诊断自身不计为成功验收。

生产 `_ask` 的实际客户端分支已显式传递 `response_format={"type":"json_object"}`。保留主模型路由、Pydantic 验证和失败用量，不增加隐式重试。新增 9 项测试连同相关客户端、认知、计量和提交回归共 95 项在本地通过。

修复后仅增加两次请求，验证完整请求除了 `response_format` 外与原诊断完全一致。两次仍为未转义引号导致的 JSON 解析失败，因而 **当前主模型接口的结构化输出未通过验收**。离线复核确认 NeuralCloud 客户端保留收到的 content 原样，没有二次反转义；现有证据不能进一步区分模型生成与上游兼容网关各自责任。该组原主模型评估累计 10 次传输尝试、10 份持久用量，全部留在隔离账本，未补扣线上身体。没有将非法决策修复成可执行动作。

这些场景使用合成经历与预先构造的认识，只提供模型行为样本；不证明跨月学习、真实人物关系效果或七天运行稳定性。首次执行的 pin 场景虽然询问六年前的约定，认识记录时间仍为 2026-09-21；它验证的是已提供 pin 的取用，不能宣称验证六年跨度。后续本地 fixture 已修正为 2020-09-23，但上述重试保持原输入，并未使用修正后的 fixture。群权限场景也未包含完整跨私聊态度投影链，该机制另由确定性回归覆盖。

截至上述批次，所有模型组累计 17 次客户端生成尝试；未选定替代主模型，线上配置保持原值。空正文、非法 JSON 和 HTTP 402 均保留为失败证据，不通过修补答案或降低校验标准计为通过。后续固定输入的候选比较、生产响应门禁修复及原生协议对照另记于 [模型验收续测](production-model-validation.md) 和 [模型汇总证据](production-model-results.json)，不覆盖这批历史结果。

## 性能测量

首次长时 Runtime 基准未完成：预设队列 8、两个前台槽、每次模拟模型延迟 30 秒，但测试命令从收件起仅给 90 秒期限，排队后触发超时，Runtime 正确进入暂停。之后基准还等待心跳而超时。保留该失败日志；不能把采样不足当作心跳性能通过。

修复基准的排队期限预算并加入失败立即输出部分报告后，第二轮完整运行 600.608 s。未改变生产 Runtime 的期限语义；测试期限按最多十次串行模型工作加裕量计算为 330 s。结果如下：

- 五秒心跳 120 次，全部发生于慢模型仍在运行时；从计划时刻到处理的 p99 **19.528 ms**，最大 23.638 ms，低于 250 ms 目标。
- 三次鉴权暂停请求，到阻止新工作的最大时间 **15.783 ms**，低于 500 ms 目标；各次暂停观察窗口均无新增模型调用或用户任务。
- 最大并行模型调用为 2，每事件最多一次模型调用，无失败事件，所有样本完整；`target_met=true` 且 `linux_acceptance_sample_eligible=true`。

这次采用真实 `RuntimeSupervisor`、`ProductionRuntime.run`、`PipelineCognitiveAdapter`、耐久 journal 和 ASGI 控制入口，但模型和身体为隔离模拟。没有四进程 RPC、QQ 发送或真实 MistyAI；排空时间是在观察结束后主动释放模拟调用得到的，不能当作自然等待外部模型完成的延迟。原始报告为 `runtime-benchmark-v2.json`。
