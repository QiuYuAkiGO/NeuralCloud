# UI 按需查询热修复

根因是 GUI 的 Runtime 事件订阅器在收到 event.completed、lifecycle 或 watchdog 时，无条件调用 status，随后才广播结果。没有浏览器连接也会查询完整快照；浏览器处于后台时也无法避免服务端读取。此前的有限条目查询与缓存降低了单次成本，但没有消除这条主动查询路径。

本次将事件转成轻量 state_dirty 通知，不在事件订阅器内读取快照。可见页面收到通知后以 250 毫秒合并事件，主动请求 /api/status；并发刷新复用正在执行的 HTTP 请求。页面隐藏时不发起快照读取，取消待执行的刷新定时器；返回前台后刷新。已经发出的请求允许完成，但隐藏页面不应用其结果。后台记忆工作、内稳态推进与 QQ 接收不依赖该显示查询。

首页当前直接展示共享记忆，因此打开可见首页就是查询需求，仍加载最近 50 条；本次没有新增分页界面。保留上一版有限条目读取、来源校验、群策略检查与单次异步缓存。显式操作者修改所返回的状态也保留。

21 项 Python 回归通过，新增验证在有订阅者及没有订阅者时 Runtime 事件均不读取快照；Node 专项检查覆盖隐藏页面零请求、返回前台刷新、事件合并、并发请求合并，以及隐藏期间完成的请求不更新界面。Ruff、JavaScript 语法检查通过。

部署采用独立 release，源码与线上基线按统一换行比较，仅 gui/runtime_server.py 与 gui/static/app.js 改变。部署前停止 writer、校验备份，群策略及配置保持不变。生产结果见部署证据；旧浏览器页签需刷新以载入新版脚本。
