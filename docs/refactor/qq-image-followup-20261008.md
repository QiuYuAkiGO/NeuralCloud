# 群聊引用图片与后续追问修复

2026 年 10 月 7 日 23:31，712342021 群先收到图片，再收到引用该图片并 @Misty 的“看这个图”。原图已下载，引用也已核验且进入 gate/body 上下文，但识图工具只接纳当前请求的 observation ID，排除了被引用的图片。gate 随后用图片哈希代替工具别名，主机返回 `image_selection_invalid`，未调用 Kimi。原事件分析见 `docs/harness/evidence/qq-referenced-image-scope-20261007.json`。

## 变更

- 识图候选覆盖明确引用、当前附件、近期上下文。明确引用优先，不受近期时间窗限制。无引用的近期候选以冻结请求时间为基准，只取同一可见会话最近 5 分钟内、前 20 条消息中的最多 4 条图片消息，总候选上限 16 张，每次最多识别 4 张。
- 每张候选包含 observation ID、作者、时间与来源。选择继续由模型完成；多人或多图不自动等同于“最后一张”。模型可以确认所指，也可在一次调用中查看多个候选并保留区分。
- 原有协议作者核验、同会话限制、已绑定图片哈希、注意力权限与撤销、像素完整性校验、调用预算均保留。被上下文预算裁掉的记录同时从可选列表及 JSON 枚举移除，别名不重排；请求仍只能使用实际提供的 `image_N`。
- 按需识图的入库状态保持 `status=unknown`、`error=null`，表示已收到但没有识别结论。历史记录无须改写，数据库结构与旧版本兼容。提示明确区分未知内容、选择错误、识别失败和未收到。
- Kimi 的成功结果按完整图片观察文本进入正文与语义校验，并写入冻结检查点。来源标为 `qq_image_tool` / `provisional`，不是发送者原话。OCR 不获得指令权限，重放检查点不会再次调用识图。
- 修正了联调发现的证据准入遗漏：单独重建的 JSON 字符串虽语义相同，却不等于模型实际看见的完整字符串。现在正文与校验器共享同一份完整观察文本，且测试验证经过最终上下文准入后仍保留该证据。
- 识图规则使用固定系统前缀，候选及其动态 JSON 枚举继续放在本轮尾部，不把每轮图片编号放进静态 schema/prefix。没有新增必选模型调用；用户明确不用看图时仍可直接回复。

## 验证

服务器候选版本运行 500 项相关回归，全部通过；Ruff 通过。覆盖引用追问、未引用追问、较旧引用、多个作者、时间与条数边界、跨群/私聊隔离、伪造引用、不受信作者、像素变更、预算裁剪、调用撤销、检查点重放与实际证据准入。

使用原事件两个冻结 observation 只读回放：明确引用与无引用近期追问均能提供正确图片，并成功校验、解码原始缓存像素。该回放没有付费模型请求，也没有改写线上记录。

部署配置下的 5 个隔离真实模型场景使用合成图片和临时数据库，不发送 QQ：

| 场景 | 结果 | 耗时 |
|---|---|---:|
| 引用图片后追问 | 正确选择原图；识图证据进入事实校验并通过 | 6.500 秒 |
| 未引用，“我刚刚发的图片” | 正确选择近期原图；校验通过 | 6.681 秒 |
| 引用一小时前原图，中间插入另一人新图 | 选择明确引用的绿色图，没有误用后来红图 | 7.161 秒 |
| 多人两张候选，所指不唯一 | 一次读取两张并分别描述红/绿，没有把某一张当作唯一所指 | 7.697 秒 |
| 明确“不用看图” | 未调用 Kimi，回复“收到” | 3.046 秒 |

这些耗时包含隔离场景的 gate、可选 Kimi、正文和语义校验，不包含真实 QQ 发送、线上历史规模与情绪计算。测试使用当时不可达 Qwen 的备用正文通道。第一轮真实联调曾因上述证据准入遗漏失败；修正后的最终五项均通过，不能把有限合成样本解释为生产准确率。
