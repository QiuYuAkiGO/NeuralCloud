# JSON 事实校验与 Qwen 后台预检

针对 712342021 群中虚构餐馆亲历的回复，本次把配置了独立结构化通道的正文校验改为逐条 DeepSeek JSON 语义审查，并加入 Qwen 后台可用性探测。发布基线为 `20261007-ui-snapshot-hot-v1`，已上线版本为 `20261007-semantic-health-v2`。

## 语义校验

- 使用现有 `deepseek-flash` Responses JSON Schema 通道；线上启用 `validator_enabled`。配置该通道后，fast/deep 正文均检查，不受旧的 fast 抽样率影响。未配置结构化通道的兼容路径保持原行为。
- 模型逐句返回原文片段、断言类型、是否有依据、依据类别、证据行号和修订建议。类型覆盖自身经历、共同历史、归属、身份、关系、感知、动作结果、身体状态及外部事实，并单独标记假设、比喻、共情和承认不知道等非事实表达。
- 程序检查 JSON Schema、引用是否越界、引文是否存在于正文，以及依据与类别是否一致。它不能机械证明证据真正蕴含结论；这仍是模型的语义判断。
- 人设、完整已准入证据在前，待检查文本在后；保留既有缓存友好输入排列。证据不因追求缓存而截断，也不把其他群或他人的经历当作自身经历。
- 过去已经发送的自我陈述只证明“说过这句话”，不自动证明内容真实。性格相似、情绪提示、回复计划不能作为亲历的证据。特别补充省略主语、行为习惯和共情中续写具体动作的检查。
- 单次语义检查预算 8 秒，并通过内部不可延长的 deadline 约束包装器重试。QQ 包装器同时尊重调用方更短的超时参数。
- 确认内容问题后，QQ 正文最多修订一次，并重新检查。JSON 无效、超时、证据引用无效或检查失败均不放行；校验服务故障不会额外浪费一次正文生成。原有 QQ 错误处理继续负责本轮失败。
- 格式、长度、请求/响应协议、身份授权和发送核验继续由确定性代码处理。board/voice 原有独立规则入口未在本次整体替换。

代码入口：`harness/validator/semantic.py`、`harness/validator/validator.py`、`harness/pipeline/pipeline.py`。同时加固 QQ gate 与正文提示，避免计划先要求模型提供没有依据的自身经历。

## Qwen 预检与切换

配置位于服务器 `/etc/neuralcloud/main-fallback.json`，没有在仓库保存密钥。

| 配置 | 上线值 | 行为 |
|---|---:|---|
| health_check_interval_seconds | 5 | 后台 GET `/v1/models`，核对已配置模型 ID |
| health_check_timeout_seconds | 1 | 探测网络超时，并限制主正文连接超时 |
| health_recovery_successes | 2 | 连续两次探测成功才重新使用 Qwen |
| primary_timeout_seconds | 10 | 健康探测通过后，实际主请求仍有超时保护 |
| fallback_reserve_seconds | 原值 10 | 保留原有备用请求预算机制 |

主请求不会同步等待健康探测。状态未知、探测失败或超过 11 秒未更新时直接用备用模型。主请求发生连接/服务错误或空响应时立即打开故障状态；早于该故障开始的探测不能覆盖新故障。实际 API 请求仍经过原有预算与计量，不把计量服务错误误当作主模型故障。

默认配置的探测间隔为 0，兼容未启用的新旧部署；本次线上配置显式开启为 5 秒。长驻客户端持有后台探测线程，关闭客户端时停止线程。GUI 状态中的 fallback 增加 `primary_health`，可查看是否可用、最后探测距今多久及探测参数。

这些超时是 HTTP 网络操作的限制。`/models` 成功并不保证随后推理一定成功，也不能消除探测与请求之间的故障窗口，因此仍保留连接保护、主请求超时及备用通道。

## 验证与边界

结果见 `docs/harness/evidence/semantic-health-20261007.json`。

- 最终真实 DeepSeek 测试 55/55 符合预期，包含原事件完整冻结证据的错误/正常回复、17 个追加边界案例，以及错误主体、历史自我陈述污染、日期错置、假设、否定、比喻、明确不确定等情况。检查失败不能被计入正确拦截。
- 最终单次检查中位数 1.31 秒，最大 2.626 秒。有限案例经过开发迭代，不能解释为生产准确率 100%，也不是独立随机评测。
- 相关自动化回归最终 317 项通过。广泛扫描初次为 3374 passed / 148 skipped / 44 fixture errors / 1 failed；补齐隔离测试目录缺少的根 conftest 后，44 项环境错误全部纳入最终通过集合。剩余错误为 `test_qq_memory_model_budget` 对旧错误文案的断言，在原线上版本也复现：期待旧英文句子，实际为 `source_partition`。没有为了本次发布修改该无关断言。
- 在服务端 Qwen 不可达的条件下，最新隔离正文链路约 5.329 秒，包含一次内容修订和两次语义检查；物理请求只有 DeepSeek 正文及 JSON 检查，没有先向 Qwen 发出正文请求。该时间不包含实际 QQ 的注意/决策、上下文准备、情绪计算和发送流程。
- 全部探针未发送 QQ 消息。首次发布尝试因发现其他任务已切换线上版本而在预检阶段停止；随后在最新版本上无冲突叠加并重新运行相关检查。

模型校验仍可能遗漏或误判。尤其正文备用模型与校验模型均来自 DeepSeek 时，分开调用不代表错误相互独立；外部实时事实也不能仅凭校验模型自身知识保证正确。应继续用已出现的真实反例扩充回归集。

发布保留旧版本及 `/var/backups/neuralcloud/semantic-health-20261007` 配置备份；失败时恢复配置与版本，不回退会话数据库。

最终核验：6 个服务均 active/running，Runtime 为 RUNNING，QQ 已连接，全部服务进程来自新版本。GUI 和认知服务有效配置均确认 validator_enabled=true；后台健康状态持续刷新，Qwen 当前不可达时直接使用备用正文通道。
