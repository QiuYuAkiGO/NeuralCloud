# 自述归属与证据关系：第二版实现报告

2026-09-22。第二版已在代码中实现来源清单、严格提案、分组提交、版本化判断与关系、时间更正、撤销及召回/GUI 投影，并接入普通对话和 QQ 生产认知路径。本报告说明实现合同与边界，不代表线上数据库、writer 或模型配置已经切换。原验收输入、失败输出及下文的探索探针保持历史身份。

实现采用“可核验的来源与原话 + 带主体和语境的陈述 + 针对具体判断的证据关系”。严格 DTO、版本检查和来源白名单不能单独证明语义归属，因此原话与模型解释分开展示，模型解释不标成已核验事实。旧合同的提前互斥检查仅修复其新旧记录行为差异；第二版按目标版本和来源片段判断关系。

代码与测试入口见第 8 节。Linux、模型调用计数及本轮实测结果另见 [第二版验收记录](production-evidence-v2-validation.md)；本文不以历史探索探针替代实现验收。

## 1. 为什么之前的修补还不够

实现前的 `ProductionAppraisal.memory_updates` 是通用字典，旧存储层将模型自由生成的 `statement` 绑定到入口用户。检查来源作者等于用户，只能说明这条消息来自此人，不能说明消息中的每句话都在描述此人，更不能证明模型改写忠于原意。

已复现的错误是：用户邀请助手休息，模型生成“选择开始休息”的自述，最后记在用户名下。仅添加模型填写的 `subject_id`，或者让第二个模型说“校验通过”，都会继续依赖可出错的语义判断。

支持与反证还有另一层混淆：“他失约一次”反驳“他每次都守约”，却支持“现有经历有履约也有失约”。如果 `statement` 是后一种综合叙述，就不该机械地把失约视为对整段叙述的反证。来源并没有固有的正负标签；角色取决于它针对的判断。

当时旧合同还有明确的工程差异：新认识拒绝支持与反证重叠，已有认识先合并并消解重叠，再验证。现在旧路径已在合并前统一校验；这个修补仍不能证明所有重叠都属于同一种语义错误。

## 2. 将“他说过”与“这句话意味着”分开

沿用现有经历库，区分三类信息：

- **原始事件与原话**：账号、通道、发生时间、完整原文、权限、来源版本；这些由通道或真实回执提供。更正也作为新事件摄取，旧原文保留。
- **陈述提取**：模型认为这句话在谈谁、什么、什么时间，属于直接自述、转述、假设、请求、意图或否定。保存原话位置和提取版本；“引用匹配”与“语义解释正确”是两种不同状态。
- **认识与行为投影**：目前怎样理解这个人、当前该采用哪一项偏好、怎样描述经历。它们依赖陈述及证据，可以被修订，不反过来成为新的独立外部证据。

原话引用由服务端根据 `source_id + source_version + span` 取得；模型提交的引文必须逐字匹配。首版优先保留整条短消息，长消息保存定位片段及必要上下文，避免只截出引号内的“我”。偏移量需绑定同一文本版本和编码约定，不能在文本改动后重新寻找一个相似片段便当作原引用。

实际 DTO 为 `MemoryUpdateGroup`、`ClaimProposal`、`EvidenceAnchor` 与 `ImportanceProposal`。作者、来源权威和受众不是模型可授予的字段。自述的 `current_impression` 与数据库主显示文本由服务端从完整原话、作者、时间构造；自由 `statement` 单独保留为 `model_interpretation`。`quote_verified` 仅证明引用匹配，`semantic_status` 仍是 `model_interpretation`。未识别人物以 `subject_mention` 保存，不赋予猜测的稳定身份。

这个设计借鉴来源、归属和派生关系的区分，以及带上下文和版本的文字定位；不要求引入 RDF 或新图数据库。[W3C PROV-DM](https://www.w3.org/TR/prov-dm/#term-attribution) 区分归属与派生，[Web Annotation](https://www.w3.org/TR/annotation-model/#text-quote-selector) 定义引文及位置选择器。它们帮助保存证据链，不替系统证明自然语言含义。

**消息作者、语境内说话人、被描述的人、解释者必须分开。** A 说“B 说 C 不喝茶”，作者是 A、被转述的说话人是 B、被描述者是 C，系统对这段话的理解又是第四层。它不能成为 C 本人的自述。已识别人物只能绑定本轮允许的稳定标识，不能由模型创建同名身份或覆盖通道作者。尚未识别的新人保存为未绑定的人物提及及转述，不丢弃原话，也不猜测身份。

助手的选择由认知决策记录为助手意图；只有 Runtime/MistyAI 成功回执才能构成动作结果。身体测量可解释助手的感受和选择，不会自动成为用户偏好的证据。

引用真实也不代表命题真实：“如果我喜欢茶……”和“他说‘我喜欢茶’”都含有原样的“我喜欢茶”。因此，自由解释始终保留为解释；不能把 `quote_verified=true` 显示成“事实已核验”。

## 3. 本人更正仍然立即影响当前理解

不要求用户反复确认每次自然语言更正，也不为每条消息增加一次模型评审。

当前消息先耐久摄取，并进入当前上下文。明确识别的本人偏好更正由同一轮认知生成有原话依据的更正关系，指定稳定主体、偏好主题、情境及生效时间；同主体、同主题和同情境的更正提交成功且已生效后，当前偏好投影采用新自述。旧经历、旧解释和旧偏好保留历史，明确更正不会被旧支持数量压过。“从明天起”使用新记录和显式 `supersedes`，现在保存、明日生效；晚到的历史消息不能按提交先后盖掉更新的有效自述。

同一 `record_id` 的修订要求准确的 `expected_revision` 和 `revision_reason`，并固定主体/未绑定提及、主题、情境、facet、kind、report_mode 及有效时间区间。省略日期表示沿用原区间，不是取消到期时间。未来生效、情境或分类变化不能偷偷改写同一当前头；需新记录，符合条件的偏好/意愿更正使用显式替代关系。越界提案被耐久拒绝，原话仍保留。替代只允许同主体、同主题、同情境、同 facet 的直接自述偏好或意愿，不适用于人格判断。

直接自述的同 ID 修订还固定原始发言的身份集合，不能把今天的新原话换进两天前的记录，再通过省略日期沿用旧生效时间。集合按已经核验的来源根、作者、完整原文哈希、发言时间、来源版本、类别和权威比较，不按模型解释或选中的短片段比较。同一原始发言的别名捕获、片段选择、关系角色及模型解释仍可重评；替换、增加或删除原始发言会以 `evidence_direct_report_utterances_changed` 拒绝该组。新发言须新建记录；属于当前偏好/意愿更正时使用 `supersedes`，不先修改旧记录的到期时间。新原文、旧当前投影、历史及拒绝待办均保留。这是来源身份约束，不能证明对原话的语义解释正确。

“从今天起只喝红茶”更新饮品偏好，不证明此人善变、不可靠或更值得亲近。“工作时喝咖啡、晚上喝茶”是不同情境，不互相覆盖。记录时间、发言时间和所描述事实的有效时间分开；不能把“昨天开始”一律改成提交时刻。

“我一直很可靠”可保存为本人对自己的评价，却不按最新自述优先规则覆盖行为认识。偏好、意愿和人格/行为判断使用不同的投影规则。撤销最新偏好使其失去依据，也不自动证明旧偏好重新生效；无法确定当前状态时应保留未知。

无法明确判断是本人更正、第三方引用或假设时，原话仍立即可达，相关解释标记有歧义。只有歧义会改变当前重要选择时才询问本人；不用关键词过滤，也不因助手选择休息而禁止同条消息中合法的偏好更正。

这一流程保证立即保留新输入并允许及时更新投影，不能保证所有自然语言更正都被模型无误识别。该限制需要真实语义场景验收，不能由数据库约束消除。

## 4. 证据角色绑定到具体判断

把模型输出的整段人物描述拆为数量有界、可理解的判断；不追求将所有自然语言编译成形式逻辑。每个判断至少有主体、内容、语境、时间范围和版本。综合叙述从这些判断及经历生成，属于可重建投影。

证据关系形如：

```text
来源版本 / 原话片段 → 判断版本
关系：支持、挑战、限定、提供背景、尚不确定
解释：模型为什么这样联系二者
来源根：用于去重和追溯，不代表统计独立
```

例如，第三次失约可以挑战“在这三次约定中每次都守约”，也可以支持“第三次没有按时赴约”。它与前两次履约共同构成“表现有好有坏”的综合叙述。同一消息里关于不同事情的两句话，可以选择不同片段、指向不同判断，不必把整条消息永久分到一侧。

还需保留证据自身的性质：“用户自述按时赴约”与“系统观察到按时到达”是不同依据，前者不能悄悄显示成后者。判断与证据之间的支持关系仍是可修订解释，不因通过字段或引用校验就成为形式证明。

确定性校验仍然必要：

- 同一提案对同一来源片段、同一判断版本重复提交，幂等去重；用别名不能绕过。
- 同一提案对同一关系同时提交相反角色，拒绝该冲突组；模型也可主动提出单条“尚不确定/有混合信息”关系，系统不把两条冲突记录自动转成它。重评需要原版本和理由，不能依赖处理顺序自动保留一边，也不能靠新 ID 隐去旧挑战。
- 同 ID 内容重评生成新修订，要求完整关系集合和理由；旧证据不自动合并到新句子上。时间、情境和分类变化遵守第 3 节的新记录合同，保留旧版及其挑战历史。
- 单个事件拆成多个片段、经摘要转述多次，仍共享来源根，不能算成多个独立事件。

有支持、有挑战、两者都有、尚无合格证据，可以是检索和界面的证据状态，但不是四个绝对真值。单条“混合/未定”只设置待复核状态，不同时充当一条支持和一条反证。正常偏好随时间改变也不自动等于矛盾。

第二版不计算旧路径的 `(支持数 + 1) / (支持与反证总数 + 2)`，其 `confidence` 为 null；旧数值仅保留旧机制标签，不能当作新认识概率。来源去重不证明统计独立，消息也不是同质试验；“按时赴约”“完成协作”“通常可靠”更不是同一个目标。投影展示 `support_only / challenge_only / contested / neither`、来源与时间，`mixed` 单独设置 `needs_review`，不双算支持与挑战，也不产生固定好感或人格分数。

同受众可用且有效区间重叠的精确重复判断有索引守卫，包含尚未生效的未来区间。解释类按主体、主题、情境、facet 和 statement 建键，仅做 Unicode NFC 与空白规范化；自述类的陈述部分来自原作者与完整原话，排除发生时间，避免不同改写绕过去重，也避免错误概括阻挡不同原话的合法更正。未绑定提及不按同名人物合并。新 ID 不能用同一精确命题替换掉旧挑战，需修订已显示的旧记录；明确不重叠的区间可以另建。经核验的偏好替代关系在新生效时刻结束旧偏好的有效性。

该守卫不做语义聚类：不同措辞表达同一命题仍可能绕过精确匹配。代码也不能证明模型选对了 topic、facet、语境或证据角色，需单独做语义验收。

## 5. 由运行时提供本轮可使用的证据清单

在提示裁剪结束后生成耐久的 `EvidenceManifest`，记录本轮实际展示的来源、片段、版本、权限、参与者和允许用途。模型只引用这个清单中的短句柄，不自行填写作者、来源权威或权限。

当前人物记忆清单只从已归档原始来源生成有资格的原话视图，旧摘要和既有认识不会自动暴露为新的独立来源。身体测量仍属于身体、情绪和行动上下文，不作为用户偏好的原话来源；助手表达只获自身表达用途，助手意图不能证明动作成功。服务端检查来源类别与允许用途，模型不能自报“来源相容”。若后续扩展更多结果来源，需逐项增加明确合同，不能把通用 `source_refs` 全部升级为人物证据。

提交时在同一短事务中重新检查：句柄属于本轮实际输入，来源和判断版本未过期，身份及权限仍有效，来源未撤销，拟写关系与来源类别相容。关系绑定具体判断修订；更新判断携带预期旧版本，提交采用比较并交换，不能把慢模型结果自动接在最新头后面。变更事件和投影游标同事务提交。客户端 DTO 校验与存储层守卫同时存在。清单 ID 由服务端持久状态绑定，通过认知结果私有字段传递，不接受模型回填；没有新增形式上的 HMAC 签名系统。

普通私聊与群聊继续使用不同的证据权限。公开输出不能通过筛掉私有引用来保留一个实际上依赖私有事实的解释；需形成受众有效的投影。安全的态度变化继续走既有独立机制，不能附带私聊解释。

证据状态本身也按受众过滤：群里不能泄漏“还有几条私密反证”、隐藏冲突状态或私有来源的失效原因。保留反证不要求每轮展开全部原文，但不能先只取相关性最高的支持，再把“未入模”当作“没有反证”。在当前允许范围内先确定依赖与冲突，再有界选择必要内容；预算不足时保留限定说明或暂缓无保留结论。

## 6. 不把学习失败变成经历丢失

原始消息摄取、实际模型用量记录、认知提案验收、动作交付分别有稳定回执。第二版 `apply_groups` 在 SQLite 写事务中用 SAVEPOINT 按组验收：同组声明、关系和更正原子提交；`depends_on` 按拓扑检查，前置拒绝使依赖组拒绝。跨组重复修改同一目标拒绝，避免数组顺序决定结果。已经接收的独立组不会被无关错误回滚；每组都有明确回执。旧 `apply_updates` 保留旧合同，不接管第二版提案。

模型获得严格分组 schema；认知入口同时保留响应中的原始分组交给 writer 逐组验证，避免一个 schema 错误组令合法更正消失。缺失、非字符串或过长 group_id 也保留实际原提案及稳定拒绝键，而不是只留下空对象。外层响应语法、动作及协议门禁仍然必须通过，不能把任意无法解析的响应当可提交提案。

拒绝组进入 `pm_v2_tasks`，保存原提案、原因、清单绑定和 pending 状态；不撤销已摄取消息、实际调用用量或有效独立组。当前认知入口只要存在拒绝组，就阻止该次可能依赖坏解释的回复/动作继续，保留结果供后续明确处理，不静默忽略坏项后照发。

**尚无自动消费这些任务的 worker。** 已有的是库内 `pending_tasks(audience, limit)` 元数据查询、GUI 有界待办展示，以及需明确调用的 `resolve_task`。`acknowledged` 只表示明确处置，不声称修复成功；`replaced` 必须引用同受众已耐久接收的新提案组。两者都有幂等处置回执，保留原拒绝记录，不触发模型。后续若新增自动维护，必须使用新提案和现有每小时 12 次自主调用预算，不能把 pending 当作已经自动学会或无预算重试。

实现使用同一 SQLite 内的 `pm_v2_*` 修订、关系、时间线、精确键、事件、回执和任务表。当前记录以 `pm_records.kind='claim_v2'` 接入既有有界索引；`pm_evidence` 仅登记来源依赖，不承载第二版的支持/挑战语义。召回、可见性、历史及操作员投影按类型分派；来源撤销通过依赖和读取时核验阻止使用，pin 不能越过撤销。schema 创建和键迁移不重写旧来源或旧认识，精确键回填只在首次创建表时执行，不在每轮提交扫描全部旧修订。

事件留痕也不能绕过用户的删除请求：保留必要的撤销标识和完整性关系不等于永久保留被要求删除的原文；正常召回、GUI、派生叙述与受控审计均服从对应的删除权限和保留政策。

## 7. 已采用方案与仍保留的取舍

**仅加强提示和 JSON schema**：值得立即做，能减少字段歧义和格式错误；无法证明主体与语义一致，不适合作为最终机制。

**只保存原话，取消所有解释**：来源清晰，但无法支持人物理解、时态更正和自主选择。适合作为事实基础，不宜替代认识层。

**每次增加第二模型裁判**：可能发现部分事实扩张，也可能复用同样误解；增加延迟与预算，不能产生通道作者、真实动作回执等权威。适合作为复杂冲突的有界维护和评测工具，不作为每轮写入的唯一守门人。

**完整形式逻辑或大型知识图谱**：复杂度和迁移成本过高，自然语言到逻辑的入口仍会犯错。当前优先采用小型结构化关系与显式语义不确定性。

已实现的组合是严格提案类型、可信原话、可修订语义解释、针对判断的证据关系、提交时证据清单。它允许保存新经历和修订解释，同时把可验证的边界留给代码，把仍需模型解释的部分明确标出来；没有增加每轮第二模型裁判或通用逻辑推理器。

专项覆盖见 [store/提案测试](../../tests/test_evidence_v2.py)、[直接自述发言身份回归](../../tests/test_evidence_v2_self_report_provenance.py)、[来源清单测试](../../tests/test_evidence_manifest.py)、[独立审查回归](../../tests/test_evidence_v2_review_regressions.py)、[投影测试](../../tests/test_production_evidence_projection.py)、[认知集成测试](../../tests/test_production_evidence_integration.py) 和 [进程退出/恢复测试](../../tests/test_evidence_v2_crash_recovery.py)。有界独立模型 runner 的工程合同由 [验收工具测试](../../tests/test_production_evidence_acceptance.py) 覆盖；具体运行环境、计数和结果统一记在 [第二版验收记录](production-evidence-v2-validation.md)。

旧自述保留原 ID、原 statement、来源和机制标签，不自动补成逐字原话或已证实命题；旧支持/反证仅表示旧版本的解释，不批量重跑模型重写历史。第二版使用新增表及明确 reader 分派，不把旧验收输出追改为新合同成功。

**旧 writer 不能通过代码回退接管已产生第二版记录的新数据库。** 新事实、修订、撤销、计量与处置事件必须保留；第二版关系不能无损塞回旧表。需要回退时使用独立旧副本，并保留新库及支持其格式的 reader/恢复路径，不用旧 snapshot 覆盖新史。实际切换仍需一致性备份与单写边界，不由本报告自动授权。

工程校验与模型语义分别验收。即使来源、schema、事务与关系都合法，也不能推出模型正确识别了引述、假设、否定、真正更正或可靠性；精确去重也不能阻止所有语义改写。真实学习效果仍需固定场景及持续观察。

下节完整保留实现前探索探针的计数、哈希和能力限制，它们不是上述实现回归的汇总。
