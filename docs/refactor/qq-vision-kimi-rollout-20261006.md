# QQ 按需 Kimi 识图发布（2026-10-06）

本次按用户确认保留主模型 `qwen3.8-27b`，恢复 QQ 图片获取，并让主模型自行决定是否调用 `kimi-k2.6` 非思考识图工具。Kimi 返回图片观察，最终人格回复仍由原主模型生成。用户同时授权提交全部现有项目改动；凭据、运行数据库、私人 QQ 报告和个人目录不入库。

## 实现与配置

- Direct：`qq_image_mode=all`、`qq_image_analysis=on_demand`。入口只下载、校验和保存图片，不预先调用视觉模型。
- Cognitive：主模型填写可选 `vision_request`，每轮最多调用一次、最多四张。Kimi 使用官方中国区接口、非思考模式和温度 0.6；凭据通过 `NC_QQ_VISION_TOOL_CONFIG` 独立配置。
- 识图结果交回主模型，再由它选择是否生成 `web_plan`。Runtime 使用现有搜索授权和来源检查；`qq_web_policy=after_gate` 对现有可发送会话启用，QQ 发送名单不变。
- 超时、无效来源、哈希变化或模型结果截断不会形成确定图片事实；冻结检查点支持恢复、撤销和重放，不重复付费识图。

配置模板与操作说明见 [QQ 按需识图](../QQ_ON_DEMAND_VISION.md)。先前本地视觉、Kimi 与 DeepSeek 的直接回复对比见 [模型评测](../research/qq-vision-local-api-comparison-20261006.md)；直接回复的耗时不等于本次工具链路耗时。

## 长历史上下文预算修复（2026-10-06）

当天的自然群聊暴露了先前短上下文识图验收未覆盖的问题：判断和正文历史分别通过预算检查，但正文追加历史时会重复携带身份与省略记录等元数据，最终组合超过线上 120,000 字符上限。四次决策在主模型调用前失败，三次成功发送了错误回退提示。QQ 收发连接正常，失败原因保存在决策记录的 `context_budget_exceeded` 中。

修复在选择历史时检查“原判断输入＋正文额外历史＋后续预留”的实际序列化长度。判断已看到的记录、当前消息和必要引用保持完整，只移除可选旧历史。真实群历史的隔离副本随后还暴露了识图结果返回后的预算缺口，因此同一逻辑也用于识图返回阶段：保留已经调用过的判断消息与完整工具结果，重新选择尚未提交给正文模型的额外历史，并同步更新冻结来源、证据和已展示记录。新增总字符数、识图后总字符数及移除历史数量的诊断计数。

线上预算、主模型和按需 Kimi 非思考策略不变。必需内容本身超限时仍明确失败；不截断当前原文或绕过预算检查。

Linux 最终关联回归 273 passed，24.91 秒，覆盖上下文选择、当前消息和引用保留、准备/恢复、来源有效性、长 OCR、按需识图、重复调用防护，以及认知和情绪管线。测试准备期间补齐了隔离验收目录的工具模块和根 `conftest.py`；新测试显式关闭可选验证器，消除其抽样调用对调用次数断言的影响。生产代码未为这些测试环境问题放宽条件。Windows 前一阶段关联回归 259 passed，补入识图返回阶段修复后相关 37 项通过；最终发布代码以 Linux 的 273 项结果为准。
