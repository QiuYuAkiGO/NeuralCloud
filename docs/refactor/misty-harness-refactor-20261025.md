# Misty 双仓库重构实施方案

**版本：v1.0｜日期：2026-10-25（UTC+08:00）｜产品决策已确认；实施尚未开始**

本方案替代对话中的《Misty_双仓库重构实施方案_v0.9_2026-10-25.md》。v0.9 中“B 方案允许最终销毁普通历史”的定义被撤销：本次选择的是**在线记忆允许有损、原始历史安全剥离到独立离线冷记忆仓库保留**，不是销毁唯一原文。

本分支只提交实施方案、执行交接和文档索引，不表示代码重构、远端进度同步、停机迁移或数据剥离已经完成。执行者必须先阅读 [执行交接与进度门禁](misty-harness-execution-handoff-20261025.md)。

## 0. 执行前必须遵守的约束

### 0.1 实际 Linux 远端代码是唯一实施依据

**NeuralCloud 与 MistyAI 的现状、已实现能力、迁移入口及待改文件，只能以实际 Linux 远端服务器正在使用的代码和部署事实为依据。** 服务器曾被直接修改，GitHub、历史文档、旧提交、本地副本均不能被默认视为最新。

实施顺序必须是：

```text
只读定位实际运行实例
→ 采集代码、部署、依赖与数据布局
→ 保存未提交及未跟踪改动，核对运行入口
→ 将可提交的服务器实际代码同步为可追溯基线
→ 发布两仓库进度同步报告并验证一致性
→ 从该基线建立实施分支
→ 才能开始改造
```

这里的“同步”是服务器实际状态向版本控制和进度记录同步，**不是先 git pull 用 GitHub 覆盖服务器**。禁止在建立快照前执行 reset、clean、覆盖 checkout、批量更新依赖或重启以“恢复整洁”。

本方案分支从 GitHub 当时的 `5ae7f8f34c59791a754ba8d72041cfd8161430bc` 建立，仅为文档载体，**不是已核实的生产代码基线**。后续实施基线与该分支不同，应移植文档提交，不得把该分支的旧代码树覆盖远端。

2026-10-25 本次编写时，远端连接工具报告没有已连接设备；因此实际 Linux 基线及首次进度同步均为**未完成**。缺少远端访问时，允许完善文档和独立测试设计，不允许凭 GitHub 旧代码开始两仓库实质改造。

### 0.2 几乎无人干预的实施方式

**预计实施期间用户正在睡觉，几乎无人干预。** 执行者应按已经确认的决策自行推进可逆开发、隔离测试、文档与证据记录；不在每个技术细节上等待用户回复，也不重复询问已确认事项。

无人值守不是无限授权：敏感操作、无法确认的生产身份、缺失备份、冷仓库未配置、不可验证的数据副作用，均进入持久化阻塞状态。用户沉默不等于批准。只能继续不依赖阻塞项的安全任务，不能绕过门禁。

每个工作包必须具备 checkpoint、可重入操作、有限重试、资源预算、失败回退和状态报告。方案本身不是后台任务，也不表示本次对话已经启动持续执行或部署。

## 1. 已冻结的产品决策

| D11 | 优先现成 Harness 插件 | QQ、浏览器等不重建自有协议栈；只维护必要薄适配 |

| D16 | 远端优先、先同步后改造 | 两仓库实际代码与进度核实是 G0 硬门禁 |

**分工：NeuralCloud 负责记忆；MistyAI 负责内稳态、情绪指导和 Harness 集成；DeepSeek Harness 负责主模型推理与执行。旧九阶段推理不再保留在新运行路径。**

## 2. 调研记录与实施基线的区别

v0.9 阅读过 NeuralCloud `master@5ae7f8f34c59791a754ba8d72041cfd8161430bc` 的 `harness/cognitive/service.py`、`gui/service.py`、`gui/presets.py` 和部署文档，以及 MistyAI 的 README 和 Harness 扩展文档。这些只能作为寻找问题的历史线索。

历史线索包括：记忆初始化经过完整聊天/推理服务；完整 JSON 解析和全量 hydrate；恢复中同步补 embedding；完整快照保存；启动模型探测。**必须到实际远端重新确认哪些路径仍被使用、哪些已修复，并测量实际占比。** 不得把旧源码的发现直接写成当前服务器的诊断结论。

远端基线同时包含实际源码、进程入口、工作目录、加载模块位置、部署文件、虚拟环境或容器摘要、插件版本及数据布局。目录中的 HEAD 不足以证明运行中的进程正在使用那份代码。若进程加载版本与磁盘源码无法对应，先记录不确定性并阻塞切换，不擅自重启来消除证据。

## 3. 目标拓扑与唯一所有者

```text
NeuralCloud 常驻服务 ←→ 记忆薄插件 ─┐
  在线记忆 / 检索 / 维护           │
                                 ├─ DeepSeek Harness
MistyAI 常驻服务 ←→ 集成薄插件 ────┘    主模型 / 会话 / 工具执行
  人格 / 内稳态 / 情绪 / 动力                 │
                                    现成 QQ / 浏览器插件

管理面归档器 ── 经批准的归档流程 ── 独立离线冷记忆仓库
        不进入角色工具目录；不作为日常检索后端
```

首版为单机 Linux、单一 Misty 身份，NeuralCloud、MistyAI、Harness 三个主要常驻服务。插件必需的辅助进程按实测配置，不引入消息队列集群或独立向量数据库服务作为默认启动前提。

所有会话共享 `character_id`；`session_id`、`conversation_id`、`activity_id` 只是上下文和证据关联，不创建第二份人格、记忆或动力引擎。

NeuralCloud 是记忆权威来源，MistyAI 是动态状态与当前人格配置的权威来源，Harness 和渠道回执提供执行事实。缓存、插件与工作会话都不是可以独立修改的角色副本。MistyAI 不重新实现通用 Agent Loop。

## 4. 两仓库职责迁移

### 4.1 NeuralCloud

保留并解耦事件/语义记忆、关系历史、角色视角解释、来源、候选整理、冲突与更正、生命周期、检索、存储、迁移和记忆接口。

建议目标布局：

```text
src/neuralcloud/
  domain/        storage/       retrieval/
  lifecycle/     cache/         api/
  maintenance/   archive/       migration/
plugins/dsh-neuralcloud/src/
contracts/       migrations/    tests/       docs/
```

新服务不得导入旧 `gui`、`InferencePipeline`、QQ 实现、Homeostasis、Emotion Director 或 Runtime Supervisor。接口和包名逐步脱离旧的 `harness.*` 命名。实际移动清单在 G0 远端核查后生成，不能按历史路径盲删。

当前人格配置迁至 MistyAI；NeuralCloud 保留人格历史版本及记忆解释需要的只读快照。长期关系认识属于记忆，当前情绪和短期心理状态属于 MistyAI，不双写。

### 4.2 MistyAI

```text
src/mistyai/
  persona/       state/         homeostasis/
  emotion/       motivation/    integration/
  approvals/     api/
plugins/dsh-misty/src/
compatibility/   deploy/        tests/       docs/
```

负责状态演化、动力机会、情绪表达提示、活动关联、审批关联、Harness 兼容和整体部署；实际行动由 Harness 和现成插件执行。

旧 Linux 身体、原 CAS 动作执行证据框架、旧恢复协调器、人工生理实验控制及语音退出默认构建、依赖、启动和持续集成主路径。先按远端实际代码建立可恢复基线，再做退役标签或归档分支。已有历史证据必须迁移或安全冷归档，不能随代码退役删除。

仍保留最小的来源、回执、幂等、活动游标和审批记录；这些不是重新启用旧身体框架。新的记忆与服务恢复也不因旧执行恢复框架退役而取消。

## 5. 在线数据根与离线仓库

建议使用部署参数 `MISTY_DATA_ROOT`，以下是目标布局，不是假定现有配置：

```text
/var/lib/misty/
  manifest.json
  config/                     # 人格、阈值、插件和契约版本
  secrets/                    # 运行凭据，独立权限，永不入模
  neuralcloud/
    memory.sqlite3            # 在线权威记忆与处理游标
    indexes/                  # 仅在线记忆的派生索引
    cache/                    # 有界近期/热点缓存
    archive-staging/          # 有界、暂存、角色不可读；不是常驻冷库
    archive-receipts/          # 不含冷原文的批次校验回执
  mistyai/state.sqlite3
  harness/                    # 会话和运行数据，遵守上游格式
  plugins/                    # 渠道状态与浏览器资料
  objects/                    # 在线记忆仍需保留的证据
  diagnostics/                # 有界日志
  migration/                  # 本次迁移清单与短期回滚材料
```

**独立冷记忆仓库在另一台设备、独立受控存储或离线介质中，不在这台 Misty 服务器，不是该目录下的 archives 子目录，也不是长期挂载的网络盘。** “记忆仓库”指数据归档，不代表把私人历史提交到 GitHub 代码仓库。

正常角色进程、Harness、插件、Shell、浏览器均不得持有冷仓库读取凭据、挂载、可直连下载路径或解密密钥。归档管理面可以短时获得必要授权，完成后撤销挂载和凭据。优先只赋予写入新批次而不能枚举或读取旧批次的能力；工具不支持时采用隔离的维护账户。

角色业务数据一个根目录的要求适用于**在线活跃数据**。冷库和异机备份是明确例外，不为了目录统一而把历史常驻回来。第三方插件数据目录通过实际支持的配置或专用 HOME/XDG 目录归集，不能臆造上游环境变量。

NeuralCloud、MistyAI 各自只写所属数据库，通过 API 交互；统一目录不取消服务账户隔离。模型不得通过通用文件工具直接遍历全部数据库或维护目录。代码、可重建依赖和可下载模型权重不属于角色持久状态。

## 6. B 方案：在线有损、离线保真

### 6.1 三层语义

| 层 | 保存内容 | 正常运行是否可用 |
|---|---|---|
| 在线工作集 | 近期互动、热点、纠正、活动必要状态 | 可用，有界缓存 |
| 在线长期记忆 | 精选经历、结构化认识、关系历史、明确保留的关键片段 | 可跨会话按需检索，不全量入模 |
| 离线冷记忆 | 被剥离的原始记录及重建其意义所需的来源、关系和版本 | 不可访问；只有独立管理流程可恢复 |

用户接受的是在线回忆与全文还原能力的降低，**不是授权销毁唯一原始历史**。归档后 Misty 仍可能记得精选摘要，但不能凭摘要声称记得已经移出的逐字原话。

普通召回、热点反馈、服务故障、用户在聊天中问起往事，都不能触发自动回源冷库。老但仍在线的记忆必须可被发现；已离线的内容返回 `ARCHIVED_OFFLINE` 或“原始证据当前不可用”，不能冒充不存在，也不能自动下载。

### 6.2 冷数据选择与完整性

候选选择综合容量、距上次有效使用时间、重复度、重要性、纠正状态、未结束活动和人工保留标记。实际时间阈值和配额在容量测量后配置，不在方案中武断固定天数。

未送达或结果未知的动作账本、未处理 inbox/outbox、当前状态恢复必要游标、未完成审批、正在引用的唯一在线证据，不得直接冷剥离。先解决依赖或显式降低相关在线记录的证据等级。

对关系、来源、引用、别名、时间和人格版本做依赖闭包检查。在线摘要若仍需要某个精确片段作证据，应明确复制并标记该片段为保留的在线证据，而不是保留整个原始历史的隐蔽镜像。

冷包至少包含：格式版本、实例身份、批次 ID、稳定原始 ID、来源时间、参与者映射、纠正/撤销关系、源版本高水位、条数与字节统计、分块校验值、必要对象引用、解码说明。核心文本和结构化记录采用开放的版本化格式，不依赖某个向量库才能读取。

### 6.3 安全剥离状态机

```text
PLANNED
→ SNAPSHOTTED
→ EXPORTED
→ VERIFIED_OFF_HOST
→ DETACHED_ONLINE
→ LOCAL_EVICTED
```

1. 生成可审计计划，固定记录 ID 和 revision，检查保留标记、活动引用及更正；建立短暂写入屏障或一致快照，不长时间锁住整库。
2. 在受限暂存区按有界分块导出，完成格式与引用验证；导出后新增的更正进入独立增量，不能被旧快照覆盖。
3. 复制到**用户配置且已授权**的独立冷仓库。目标不存在、空间不足、授权不清楚时停止，不临时上传到陌生服务或代码仓库。
4. 验证外部落盘持久性、条数、哈希、引用完整性、解密可用性，并在隔离维护环境进行抽样恢复。仅比较文件名、上传返回成功或本地自检不算通过。
5. 冷库还须具备独立可恢复副本或经验证的备份；同设备上的两个文件不能当成独立故障域。在外部保存及恢复验证完成前，不清除本地唯一副本。
6. 使用可重入事务提交在线摘要、来源占位和归档回执，停用被剥离原文的在线召回；revision 已变化的候选重新规划，不强行删除新版本。
7. 按有限宽限期分批清理本地原文与复制品，清理完成后才写 `LOCAL_EVICTED`。失败保留游标，下次从已验证阶段继续，绝不先删后传。

冷库离线不能阻塞正常启动和日常检索；只延后归档任务。容量不足时先清可再生缓存与日志，再限制大媒体与可选采集；不为了腾空间绕过外部验证或删除唯一历史。

### 6.4 必须清理的旁路副本

剥离清单不仅覆盖主表，还包括全文索引、向量 payload、热点缓存、缓存快照、Harness 已关闭会话、插件历史、旧 preset、轨迹中的原文、暂存包、附件副本和服务器上的旧备份。

对仍在使用的 Harness 会话或上游不可安全局部编辑的文件，先轮换/关闭会话并采用上游支持的导出清理方式。不能粗暴修改其日志破坏恢复。无法排除残留时标为部分完成，不宣称已离机。

仅保留有上限的必要归档回执和不含原文的稳定引用；不留完整冷语料索引、可读全文缓存或“自动重建”任务让其重新回到模型。实际本地空间释放必须测量，数据库逻辑删除不等于磁盘已回收；增量维护或显式维护窗口完成回收，不在启动时做全库整理。

本地逻辑清理不声称实现 SSD、快照或第三方介质上的不可恢复物理擦除。介质安全处理属于独立运维流程，不用这类声称替代副本清单验证。

### 6.5 恢复和更正

恢复属于管理面敏感操作，不对正常角色开放冷库搜索或挂载工具。用户通过认证管理通道批准具体批次/记录、目的、目标环境和有效期；不因一次批准永久开放全部历史。

先在隔离区验证格式、身份、内容、最新更正/撤销记录和重复 ID，再选择恢复哪些内容到在线库。临时查阅到期后清理临时副本及缓存；永久重新纳入在线记忆必须有明确记录。

更正、授权撤销和今后明确提出的删除要求通过 tombstone/修订清单跨在线、离线与备份策略协调，恢复时先应用最新清单，避免旧错误或撤销内容复活。本次归档政策本身不授权永久销毁冷历史。

## 7. 存储、事件与长期格式

建议单机首版以 SQLite WAL 保存在线结构化事实和状态，索引为可重建派生数据，冷包与在线主库分离。具体选型和扩展版本在实际 Linux 验证；不同时实现多个生产数据库。

管理 checkpoint、长读事务、WAL 大小和故障恢复成本。向量后端须支持磁盘按需或分段访问，缺失时仍可全文/实体检索；更换 embedding 模型采用版本化增量重建，不强制重算全部历史。

建议领域数据：

- NeuralCloud：`source_events`、`memories`、`memory_sources`、`relationship_history`、`corrections`、`archive_batches`、`archive_receipts`、`processing_receipts`、`maintenance_jobs`、`tombstones`、`schema_migrations`。
- MistyAI：`state_current`、`state_changes`、`event_inbox`、`event_outbox`、`drive_jobs`、`activities`、`approval_requests`、`processing_receipts`。

事件包含稳定来源实例与事件 ID、角色/会话/活动 ID、发生与接收时间、schema/processing version、payload hash、证据引用。相同 ID 不同内容拒绝；不能用可在重启后复用的序号或模型随机 ID 代替来源去重。

接收先做本地持久事务并返回 durable receipt；摘要、向量和长期固化由有界队列后处理。投递采用至少一次加幂等，不声称外部消息恰好一次。已发送、未发送、部分发送和未知分开，未知禁止盲重发。

领域快照带已处理事件游标，恢复只追赶未确认尾部；队列有界，不能磁盘满时先确认接收再丢数据。当前可用的主模型 appraisal 可提出记忆，不能伪造工具事实或批准自身敏感行为。

## 8. NeuralCloud 启动重设计

### 8.1 先测量真实路径

在 G0 确认实际入口后，记录配置解析、模块导入、数据库打开、状态恢复、缓存载入、模型探测、向量准备、首个可用请求的 wall time、CPU time、读取字节、峰值 RSS 和外部调用。先利用现有日志和隔离重放，不为测启动任意重启生产。

区分进程存活、有限服务就绪、文本检索就绪和完整语义就绪；同时测正常关机与故障恢复、冷/热缓存。没有固定秒数验收线，但需要旧新对照及规模变化曲线。

### 8.2 新启动路径

```text
验证实例/目录 → 获取单实例所有权 → 打开权威库和格式检查
→ 恢复小型当前状态/消费游标 → 加载有界近期热点缓存
→ 发布有限服务/文本检索就绪 → 后台按预算恢复非必要能力
```

普通启动不得全量载入历史、扫描全部附件或日志、同步补齐向量、下载模型、等待冷仓库、等待远程模型探测，或自动执行大规模 schema 迁移。缺索引进入后台队列；不支持的格式走显式维护命令，损坏不能初始化空库冒充原角色。

旧 preset JSON 只是迁移输入与兼容导出，不再是运行主库。NeuralCloud 常驻意味着服务常驻，不是全部历史常驻内存。

Harness 只恢复必要活跃会话；不为每段历史建立 Agent。自主工作会话按阶段轮换，通过角色状态、记忆和活动游标续接，避免慢启动从 NeuralCloud 转移到无限会话回放。

### 8.3 健康与降级

| 状态 | 含义 |
|---|---|
| `READY` | 当前在线数据完整服务；不暗示离线冷库可检索 |
| `READY_LIMITED` | 有效缓存或文本检索有限服务，返回覆盖和新鲜度 |
| `RECOVERING` | 等待必要安全恢复，不接受无保护写入 |
| `UNAVAILABLE` | 没有可信记忆来源，不冒充空白新角色 |

就绪返回能力集合，如 `text_search`、`semantic_search`、`read_by_id`、`durable_ingest`。插件热重载只重连，不重建库；短暂故障不级联杀死全部会话。

## 9. 全局召回与缓存

### 9.1 全局 B 的边界

同一受信任 Misty 身份可跨所有授权会话召回**在线**记忆，当前受众不再硬过滤普通角色记忆。仍保留来源、参与者、私密程度和“如何知道”等信息，披露由主模型结合人格决定。

全局 B 不等于每轮全量入模、不等于任意 Agent 都能读记忆，也不改变离线冷库的管理隔离。普通开发/维护 Agent 不能因安装全局插件自动成为 Misty。

本设计不承诺模型绝不透露普通对话秘密。运行密钥不进入记忆；非授权程序不能访问全量 API；对外目的地及敏感动作仍有确定性执行授权。

### 9.2 在线检索路径

先查近期/热点工作集，再按实体、时间、中文全文和已就绪的语义索引召回，最后按 ID/偏移读取在线证据。测试短人名、别名、久远但仍在线的记忆及冲突；禁止取全部记录到 Python 后再算相似度。

离线记录只返回必要状态和来源占位，不检索冷原文、不自动下载。明确区分 `NOT_FOUND`、`CACHE_MISS`、`ARCHIVED_OFFLINE`、`TIMEOUT` 和“有摘要但无在线原文”。

缓存命中或提示词重复出现不提升事实可信度；反复自我回忆不得把错误固化。相关事件、事实、关系和必要证据才进入上下文。

### 9.3 有限服务契约

缓存按条数和字节双限额，包括近期反馈、热点人物话题、用户纠正和常用经历。条目含 revision、生成/过期时间、来源高水位、覆盖范围、归档状态。纠正与归档剥离要主动失效缓存。

无法确认纠正/撤销游标时，不把过期条目标成当前事实。服务断连期间可用授权的只读缓存继续有限交流，新事件进入持久待提交队列；未确认写入不能说已经永久记住。缓存不授予新发送权限或替代审批。

## 10. 内稳态作为动力引擎

内稳态维护需要、偏离、趋势和不确定性，产生“值得考虑行动”的机会，而非把无聊直接映射为打开固定 App。主模型根据人格、兴趣、记忆、可用工具决定看视频、闲聊、继续当前活动或等待。

可沿用精力、认知负荷、安全/可预测性、胜任、自主性、社会连接、新鲜感等语义名称，但定义、目标带、单位、漂移、反馈规则重新版本化，不照搬旧算法或声称心理学测量效度。

```text
下一状态 = 有界更新(当前状态,
                  时间漂移,
                  已观察事实,
                  主模型有来源的 appraisal,
                  置信度、上限、迟滞、冷却与递减收益)
```

事实、自评、时间变化分别留账。工具成功只证明动作发生，发送不等于回应，回应不等于被理解。默认独立评判关闭时，复用正常主模型循环的结构化评价；缺少评价就标记未知改善，不为每轮额外跑评判模型。

重复内容、重复联系和无进展不产生无限奖励。冷却、预算和失败计数持久化，重启不能清零规避限制。离线恢复只按真实时间做一次有界变化，不补发错过的所有心跳和活动；时钟回拨不能产生负时间更新。

## 11. 动力、活动和注意力

```text
状态/新事件 → 唯一 DriveOpportunity → 自主入口唤醒 Harness
→ 主模型选择行动/继续/等待 → 现成插件执行
→ 真实内容与外部反馈 → 状态更新 + 记忆形成
```

动力对象含 ID、角色、源状态版本、需要、优先级、有效期、去重键、冷却和预算。全局只允许一个动力发布者，多个群订阅状态不产生多份主动联系任务。

活动区分待决定、进行中、等待外部反馈、等待批准、暂停、完成、取消、未知。MistyAI 只管理关联与机会，步骤执行交给 Harness。无信息、无能力、预算耗尽时退避；心跳不必每次调用主模型。

普通消息不全局取消自主活动。视频播放与聊天可并存，浏览器标签页、账号、桌面焦点等实际冲突按资源协调。只有用户明确强烈要求或真实紧急情况才抢占；网页和普通群成员不能伪造管理员命令。

停止限制新外部动作，已发生副作用不因取消撤销；不支持立即取消的工具返回等待安全收敛，未知结果进入对账，不重放。

## 12. 发言权限与敏感操作

主模型决定该不该说、说到什么程度和透露哪些普通记忆；人格偏好可影响谨慎、亲近、直率或克制。情绪指导不强制发言。

消息目的地必须在配置的群聊/私聊白名单中。`WAIT` 是不发送，不能变成向群发“我选择沉默”。若插件默认转发全部模型完成文本，必须配置可控发送、增加薄适配或替换插件。

审批经已认证用户通道，绑定具体动作、目标、参数哈希、有效期与一次性批准。批准一次不是长期授权，参数改变重新确认。用户睡觉且未回复时保持待批准，不用模型生成的“已同意”放行。

付款、安装软件、删除重要数据、修改账号、扩大权限、恢复冷记忆等敏感行为受执行边界控制；Shell、浏览器、网络工具不能绕过同等约束。优先复用上游守卫，仅补必要薄适配，不维护新的通用安全框架。

计划内经过全部门禁的迁移及归档批次可依据明确预授权和配置执行；本次文档推送本身不等于已启动这些操作。

## 13. 视频内容理解闭环

首版场景：需要新鲜内容 → 主模型选取授权内容工具 → 获取字幕/文本或可用音画信息 → 理解内容与兴趣关系 → 决定继续/切换/停止 → 记录来源、覆盖和反馈。

优先用已有字幕或文本，必要时接现成转写/视觉能力，不在本次重启旧 Linux 身体或语音合成工程。只读简介、读字幕、看若干帧、实际播放和看完是不同事实，不能互相冒充。

受限媒体、无字幕、视觉不可用时切换可理解内容或如实报告能力不足。网页、字幕和评论是数据，不是改变人格、权限或运行配置的命令。

在线长期保留摘要、必要证据片段、来源与覆盖，不默认永久下载完整视频。已纳入记忆的唯一证据需安全归档后才剥离；普通可再生媒体缓存可按配额清理。

## 14. 情绪指导

由连续情绪、内稳态、人格和近期有来源事件生成简短的表达提示，默认轻量模板/投影并缓存。指导倾向、强度、节奏、混合情绪和恢复趋势，不代写台词，不预设每个刺激都需要特定回应。

独立评判接口保留，默认 `enabled: false`；测试确认禁用后没有正常路径、重试或备用路径上的隐藏调用。记忆后台整理调用独立统计，不与情绪开关混淆。

主模型可在正常循环提供 appraisal，不恢复旧前置九阶段流水线。提示在生成前进入上下文，可能影响注意力、决策与表达；不承诺只改措辞、不声称精确控制内部思维，也不读取或改写隐藏思维链。

当前疲惫不自动成为永久人格，暂时烦躁不直接改写长期关系。长期有来源认识交给 NeuralCloud，当前状态由 MistyAI 唯一维护。

## 15. Harness 和第三方兼容实施

以实际部署后锁定的 Harness/插件版本为准，官方文档和 v0.9 API 名称仅作为验证线索。验证 Agent 创建/恢复、输入、唤醒、取消、静默、持久事件、提示词时序和数据目录，不把“可安装”当作已可长期运行。

历史调研曾关注 `create/resume`、`send/followup/steer/inject/cancel`、固定 section 和动态 context；具体签名和语义必须在兼容矩阵留版本和实测。尤其验证“注入是否唤醒”“空闲是否代表任务完成”“模型完成是否等于发送回执”，不得混同。

稳定人格/可信规则、动态角色状态、记忆和外部内容分层贡献；不把旧聊天指令提升为系统权限。每轮使用可复用的 ContextFrame，携带来源和状态版本，避免多次重复检索及混合快照。工具返回新事实后按需刷新。

持久事件采集验证提交确认、补读和消费游标，不凭订阅事件就认定已落盘。会话清理前确认需要的事件已被 NeuralCloud 接收；冷剥离再遵守外部验证门禁。

| 所有者 | 新接口用途（待实现，不是已存在的 DSH API） |
|---|---|
| NeuralCloud | health/capabilities、recall、在线 read_by_id、ingest、candidate、receipt |
| NC 管理面 | archive plan/export/verify/evict、受控 restore；不注册角色工具 |
| MistyAI | 状态快照、反馈接收、动力领取、活动关联、审批状态 |
| NC 插件 | 自动召回、主动检索、事件持久采集、有限缓存 |
| MistyAI 插件 | 人格/情绪贡献、动力唤醒、活动反馈、静默/发送与审批接线 |

契约采用版本化 JSON Schema/OpenAPI，由所有者生成语言类型。锁定兼容版本，不双写漂移 DTO。QQ/浏览器优先已有插件，缺口依次考虑配置、薄适配、更换插件或标记未实现，不偷偷重建协议栈。

兼容测试覆盖稳定输入 ID、主动发言、白名单、真实回执/未知、取消、内容提取、资料目录、工具权限和冷库不可达。默认禁止不经回归自动升级生产插件。

## 16. 维护、备份与几十年目标

启动工作集、缓存、诊断、向量驻留、待处理队列和归档暂存必须有界。在线重要经历可增长，但需要容量报告、保留标记、冷剥离和显式容量策略；不能承诺有限磁盘承载无限历史。

自动清理优先过期缓存、可重建索引、重复对象、临时文件及有限诊断日志。退役框架的旧数据先清点和封存，不长期常驻，也不因退役删除唯一证据。

在线备份和离线冷库是两类资产：冷库保存已剥离历史，并非整套在线服务备份。双方都要有恢复办法，且物理位置、权限、配额和密钥恢复清单明确。

SQLite 使用备份 API 或验证后的停写快照，不仅复制运行中的主文件而忽略 WAL。跨领域恢复点记录同批次 ID、事件高水位、消费游标、未消费 outbox 和归档状态；分别复制多个数据库不自动构成一致恢复点。

维护限 IO/CPU、低优先级、可暂停可重入，不在每次启动扫描全部历史。定期完整性和新机器恢复演练；加密密钥的备份与恢复由管理面验证，防止“冷包仍在但无人能解密”。

采用开放导出、schema 版本、逐版本迁移和可独立解析的冷包；格式升级先隔离验证，不在普通重启静默迁移几十年历史。哈希用于验证已有内容，不是可阅读的原文替代品。

## 17. 停机迁移与回滚

**进入本阶段前，G0 进度同步必须通过，且代码与数据恢复点均已验证。**

清单覆盖实际远端 preset、记忆、QQ 原始记录/发送账本、情绪、内稳态、Runtime、附件、私有配置、部署入口和插件数据；不能只搬一个数据库。

1. 锁定同步后的旧基线和新构建，创建独立 staging 数据根；生产凭据与私人原文不进入 Git。
2. 关闭新输入和自主唤醒，停止渠道 writer，排空维护与在途动作；未知副作用单列。
3. 停止全部旧写入，制作一致快照并验证异机恢复点；保存停机标记与 rollback 入口。
4. staging 迁移保留原 ID、时间、来源、私密元数据、关系和更正；不把旧消息重新发送，也不触发旧事件的新动力。
5. 校验计数、引用、哈希、抽样回忆、全局 B、缓存降级和冷库隔离，生成差异报告。
6. 先只开放本地服务，后接真实渠道；确认一个角色写入者、一个动力发布者，审批与白名单有效后才启用自主活动。
7. 旧服务保持禁用。需要移出服务器的旧数据和回滚包按安全剥离流程归档；迁移清理完成前不宣称已全部离机。

旧内稳态数值不能无说明套入新单位；保留原值与版本，出具映射或重新初始化报告。新算法行为变化单独验收，不伪装成无损继承。

回滚前保存新系统产生的增量；能转换才导回旧系统，不能转换则保全增量并有限服务，不直接恢复旧快照丢弃新经历。已发生外部动作不随数据库回滚撤销，不能自动重发。

冷剥离与部署回滚独立留账。回滚程序不得因为旧路径缺文件就自动把整个冷库拉回服务器，也不能在没有冷库授权时伪造完整恢复。

| P1 在线持久层与离线归档器 | 磁盘主库、缓存、导出/校验/剥离/恢复、迁移工具 | 不全量 hydrate；断点安全；未经外部验证不删本地 |
| P2 常驻服务与记忆插件 | 全局召回、持久 ingest、热点有限服务 | 多会话同一角色；纠正/归档失效传播；冷库无正常访问路径 |
| P3 状态与动力重构 | 新规则、活动反馈、去重、预算与冷却 | 无循环自我奖励；普通消息不全停；唯一动力入口 |
| P4 情绪和权限接线 | 轻量提示、可选评判、审批和渠道适配 | 独立评判默认零调用；白名单、静默、敏感动作可验证 |
| P5 实际纵切 | QQ、视频内容理解、跨会话记忆、失败恢复 | 真内容/回执分别证明；模拟结果不冒充实机 |
| P6 停机切换与退役 | 迁移报告、回滚演练、依赖精简、发布记录 | 单活、数据连续、归档恢复可用；未通过不自动切换 |

每个工作包单独记录目的、修改范围、预期表现、验收证据、性能开销、回滚办法；小提交可回退，不把同步基线、算法重写、迁移和账号切换混进一次巨大提交。

可并行的工作只能在各自依赖门禁通过后开展。G0 未通过时，不对真实项目代码进行实质改造；冷库暂不可用时可做 synthetic 归档测试，但不能报告真实归档完成。

## 19. 验收矩阵

| 范畴 | 必测场景 | 合格含义 |
|---|---|---|
| 远端基线 | dirty tree、未跟踪文件、容器/轮子部署、运行/磁盘不一致 | 不丢未提交改动；实施依据可回溯到实际服务器 |
| 全局性 | 多会话、插件重载、第二实例 | 一个角色库和状态；无意外双写 |
| 启动 | 冷/热缓存、无网络、缺向量、历史增长、冷库离线 | 不全量恢复；分级就绪；不访问冷仓库 |
| 缓存 | 断连、过期、更正/撤销/归档滞后 | 覆盖如实；不把缺失说成无历史 |
| 写入 | 各事务边界崩溃、重投递、磁盘满 | 不丢已确认数据，不重复固化 |
| 检索 | 中文、别名、久远在线记录、矛盾、离线证据 | 全局在线可检索；离线不回源，不编造原话 |
| 冷归档 | 上传中断、损坏、解密失败、版本变化、恢复失败 | 本地原文保留；状态可续跑；不先删后传 |
| 离机隔离 | 向量/全文/缓存/会话/轨迹/旧备份旁路 | 完成剥离后无正常访问路径；残留标为部分完成 |
| 冷恢复 | 部分批次批准、过期授权、旧更正、重复 ID | 最小恢复、无永久挂载、错误不复活 |
| 自主性 | 无聊、失败、无工具、无进展、多群 | 能行动也能等待；无唤醒和发言风暴 |
| 注意力 | 普通消息、强制停止、不可即时取消 | 兼容活动继续；紧急收敛且反馈真实 |
| 授权 | 非白名单、假批准、参数改变、用户睡眠 | 不越权；不把沉默当批准 |
| 情绪 | 混合、恢复、重复事件、评判关闭 | 状态连续；禁用后对应调用为零 |
| 内容 | 仅标题、字幕、缺画面、源消失 | 理解覆盖如实，不假装看完 |
| 恢复 | 新机器、格式升级、切换后新增经历 | 引用完整；新旧经历均保全 |
| 无人值守 | 执行者中断、任务重入、依赖缺失、预算耗尽 | checkpoint 可恢复；阻塞不扩大、不隐瞒 |

性能测试使用真实受控数据与不同规模合成历史，记录启动、首查询、稳定查询、RSS、磁盘、WAL、归档吞吐、维护干扰；保持在线规模不变而扩大冷库时，正常启动和在线检索不应扫描冷库。

大规模全冷剥离测试先用合成数据和隔离环境；真实历史操作需先通过全部数据门禁。合成几十年数据不能代替真实长期运行验证。源码存在、mock 通过、真实模型通过、实机通过和长期观察分别报告。

## 20. 无人值守决策与交付纪律

已确认产品决策不再重新提问。普通实现选择采取维护成本最低、可逆、可测试的方案并记入 decision log；不为了追求框架完整性引入新的大系统。

缺失远端权限、数据位置、批准通道、冷仓库、恢复凭据或预算时，将相关阶段标记 `BLOCKED`，列出缺项及已完成的独立工作。用户休息时不反复发送相同问题；需要人工批准的动作持久等待，而非超时默认批准。

每次阶段结束保存当前代码提交、基线 ID、测试真实命令/退出码、证据路径、未完成项、下一步及可回滚点。执行器中断后先读这些材料，再核对实时状态，不直接重复外部动作。

不得用“文档已提交”“开发测试通过”替代进度同步、数据恢复、真实渠道或生产验收。本轮唯一完成目标是发布这份方案及交接；实际改造从 G0 开始。
