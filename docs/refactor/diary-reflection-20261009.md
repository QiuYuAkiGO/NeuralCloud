# Misty 日记来源覆盖与重复检查

## 变更范围

日记开启 `reflection_enabled` 后使用独立事件整理入口。普通聊天检索排序不变；旧日记原文、哈希、每日上限及自然窗口保持兼容。默认关闭，Runtime 与 Cognitive 读取同一份 `NC_DIARY_CONFIG`。

- `harness/diary/reflection.py`：入库水位、历史起点、协议身份去重、北京时间分组、64 条/12,000 字符分批及 SQLite 缓存。
- `harness/cognitive/diary_reflection.py`：独立串行后台任务、权限复查、分层摘要、正文与一次结构化检查。输出采用批内短引用，持久层保存完整来源映射。正文 18 秒、检查 6 秒、整体 25 秒，并受请求截止时间约束。
- `harness/runtime/diary.py`、`harness/diary/store.py`：准备时传入上一成功覆盖点；正文和覆盖证据同事务持久化；共享记忆提交失败只重试提交，不重新写日记或重复收取写入工具费用。
- `harness/cognitive/diary.py`：恢复已接受决策、提交前权限检查。详细证据继续由受限诊断接口读取。

后台摘要不持有对话所有者锁，开始每次模型请求前等待前台空闲。已经在途的请求不会强行中断；模型调用与用量沿用现有计量。失败保留已完成批次，等待不消耗覆盖点。来源撤权后重新整理；历史原文不做清洗或改写。

## 持久化与迁移

共享记忆相邻的 `*.diary-reflection.sqlite3` 保存任务、摘要、来源映射、兼容起点、准备决策和用量。Runtime 日记数据库只新增 `reflection_evidence` 辅助表。没有历史覆盖字段时，以最新日记写入时间计算并持久化初始水位；没有日记时覆盖已有授权记录。

每个摘要保存完整输入引用和实际采用引用；长记录通过事件 ID、偏移量和原文来源追踪。最终上下文分开限制新摘要 12,000 字符、最近三篇日记 4,000 字符、感受及覆盖约 2,000 字符。摘要覆盖不代表正文保留每个细节。
