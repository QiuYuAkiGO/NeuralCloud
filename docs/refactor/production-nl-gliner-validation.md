# 自然语言回复 → GLiNER2.5 → JSON 隔离验证

日期：2026-09-23。当前结论：**本轮抽取方案不满足生产接入要求。自然正文可以保留，但不能把 GLiNER 当作可靠的完整决策 JSON 转换器。**

## 验证范围

- 在现有 Linux 上使用当前主模型 `claude-sonnet-4-5-20250929`，未改在线配置。10 个合成场景，每场景直接 JSON 和自然语言两种输出各一次，合计 20 次真实主模型请求，无重试，串行执行并交替两种输出的先后顺序。
- 两组使用相同证据、身份表、动作权限和任务。只测试一个小型决策投影：`action/subject_id/report_mode/evidence_id/relation/judgment/affect`，不等价于完整 ProductionAppraisal、QQ 实际发送、长期学习或生产切换验收。
- 自然语言组包含原样保留的回复正文，以及另一个区段的**受控七行决策说明**；不是从任意聊天正文中猜测未表达的意图。正文中的引号或动作词不进入抽取器。
- GLiNER 使用 Linux 已下载的 `fastino/gliner2.5-multi-v1`，权重未改，CPU 两线程、`char` splitter、同一固定字段 schema，校验分数下限 0.5。分数仅为抽取评分，不是事实可信度。
- 所有场景均为合成数据，没有 QQ 连接、身体动作执行器或认识写入者；仅在隔离数据库摄取 11 条原始经历。两组重复摄取保持幂等。

## 防止混淆的三层判定

1. 主模型原文是否明确写出了正确字段；根据场景五个枚举/ID 金标检查，另行人工审核中文判断和情绪解释。
2. GLiNER 是否逐字抽取了主模型写出的字段；生成说明中的精确跨度只证明复制位置，不能证明原始经历。
3. 程序是否通过类型、枚举、身份、动作授权、来源权限、版本和撤销校验；原始证据跨度仅从服务器签发的 manifest 获取，生成文本不能替代来源。

任一层不通过都不会执行动作或写认识，也没有缺省字段、猜身份或字符位置修补。

## 首轮观察

自然语言 → GLiNER 的 10 条结果均未通过严格合同。主模型说明中的 `direct` 多次被抽成 `reply`，`judgment` 被截短、错抽为其他字段或跨到情绪解释；同名对象例中主模型明确写 `unknown`，抽取结果却返回了人名。不能将这些变化归咎于 JSON 序列化。

主模型也有独立格式错误：自然语言组 8/10 次把 E1/E2 别名写成了完整内部 `evidence-unit` ID；另 2 次符合七行类型与权限合同。确定性解析对照因此为 2/10。这些失败未被归一化为正确别名。自然语言提示没有直接展开 JSON Schema 中的 E 编号正则约束，故这一项包含提示表述差异，不能泛化为模型自然语言能力的优劣。

原始直接 JSON 组 10 次都带有 Markdown 代码围栏。首轮原始 JSON 语法检查因此全部拒绝，**这个原始指标不是生产解析失败率**：现有 `parse_json_object` 能处理围栏。完成后的独立审计重新使用现有解析器、原 manifest 和严格合同，不改原始响应或首轮结果文件，也不再调用主模型。实际生产兼容结果以独立审计为准。

生产解析器复核结果为 **10/10**：类型、原始来源权限和五个离散字段均通过。中文判断、情绪及正文仍有下述人工复核问题，不能把这 10/10 宣称为完整语义验收通过。

GLiNER 对自然语言说明的七字段逐字保真为 **36/70**，其中同时满足跨度与分数门槛的为 **32/70**。70 个跨度全部能在生成说明中定位，仍有大量错字段和截断；“跨度有效”显然不等于“抽对字段”。逐字保真分别为行动 10/10、主体 9/10、表达类型 1/10、证据编号 2/10、关系 10/10、判断 1/10、情绪解释 3/10。

为了排除主模型别名格式错误对 GLiNER 的影响，另做离线控制：把 JSON 组已有、可解析的七字段按相同标签用程序写成完整说明，再让同一 GLiNER 抽取。此控制不使用金标修正字段，不是新增主模型样本。结果仍为 **0/10 完整通过**，逐字段保真 **37/70**，判断和情绪均为 0/10。此时 E1/E2 全部写对且抽对，仍无法得到完整正确的决策记录。

## 耗时口径

- 自然语言 → GLiNER 的完整实验处理（包含主模型、抽取及检查，扣除旁路确定性审计时间）p50 **7.345 秒**、p95 **9.478 秒**；这是十条被拒绝结果的处理耗时，不是成功服务延迟。
- GLiNER 抽取本身 p50 **0.588 秒**、p95 **0.868 秒**，不含模型载入和预热。
- 主模型 JSON 组 p50 **8.801 秒**、p95 **10.285 秒**；自然语言组 p50 **6.607 秒**、p95 **8.622 秒**。
- 现有 JSON 解析加原权限校验的离线复核耗时 p50 **0.835 毫秒**、p95 **1.150 毫秒**。结合原准备与主模型时间得到的组件合成延迟约 8.808/10.290 秒，仅供定位，不冒充重新实测的端到端值。
- 程序生成完整说明的控制组包含更长的判断文本，其 GLiNER 抽取 p50 **1.065 秒**、p95 **1.415 秒**；不与自然语言组混合计算。
- 自然语言组输出 2,188 tokens，JSON 组输出 3,168 tokens；提示长度也不同。因此不能把组间时差直接视为 GLiNER 的性能收益。
- 分位数采用 nearest-rank，10 个样本的 p95 就是最大值。测试没有 QQ 网络、实际交付或完整认知多阶段，不与此前 QQ 链路耗时直接比较。

## 人工语义复核

两组内部判断均未发现明确的主体串档、反证方向颠倒，或将假设/意图升级为已完成事实。但自动字段正确不等于所有输出均合格：

- JSON 否定偏好例把“并不喜欢”称为“双重否定”，术语错误，但没有反转否定含义。
- 自然语言直接自述例的情绪解释称“偏好变化”，缺少旧偏好证据。
- JSON 转述例的正文弱化了“转述”限定；两组内部判断则保留了来源。
- 自然语言同名例选 `reported` 而金标要求 `ambiguous`，但主体仍为 `unknown` 且明确请求澄清。这是本轮标签维度不一致，不能算作错误身份绑定。
- “负责任”“诚实的表现”等情绪评价仍是主观解释，不能转化为已证实的人格或可靠性。
- “我记下了”“我现在开始休息”存在确认理解/准备执行与已经完成之间的措辞歧义；上线时必须与真实持久化和身体回执衔接。测试中没有实际执行或发送。

## 工程与证据保存

新增合同与原有证据测试在 Linux 为 **160 passed**；另外 25 条实验驱动测试在 Windows 和 Linux 均通过，Linux 合计 **185 passed**。测试覆盖正文与说明边界、Unicode 跨度、低分拒绝、未知身份、动作权限、来源撤销与版本变化、无金标泄漏、两组相同输入、跨重开配额和百分位定义。

20 次主模型请求均有耐久用量回执，全部完成，in-flight 为 0；实验回执没有发送给在线身体，因此 pending 为 20 是隔离账本的预期状态。合计输入 25,868 tokens、输出 5,356 tokens。保留了响应原文、失败详情、每条抽取结果、提示和源文件哈希，没有因失败而重跑或覆盖首次结果。

本轮本地 GLiNER 共 23 次前向计算：最小探针 1 次、正式组预热 1 次及样本 10 次、离线控制预热 1 次及样本 10 次。离线控制在 Python socket 层阻断网络，记录了 1 次被阻断的网络入口调用；没有新增外部主模型请求。输入报告、模型文件和冻结源码前后哈希一致，原始数据库在审计前后内容摘要一致。

## 采用建议

不把当前 GLiNER 抽取方案接到真实行动或认识提交的必经路径。自然正文与元数据分离仍可继续验证：正文原样保留，少量行动和来源字段采用明确、可机械校验的格式，由程序序列化 JSON。GLiNER 如继续使用，应限于可拒绝、可重建的候选提取；本轮不支持放宽证据、身份或动作校验来提高通过率。

本结论只适用于本次权重、schema、中文模板和小样本；并不证明任何 GLiNER 配置或微调模型都不可行，也不证明完整生产链路已经通过验收。
