# QQ 记忆准备优化：实现、论文依据与隔离实测

2026-10-05。状态：已部署到 Linux，版本 `20261005-memory-prepare-v1`，北京时间 23:55 通过发布检查，23:56 复核通过。

## 结论

在同一台 Linux 主机、同一份生产数据快照上，完整 `CognitiveSharedMemory.qq_binding` 准备阶段从中位数 **5,473.8 ms** 降为 **67.5 ms**，降低 **98.77%**，约 **81 倍**。优化版 30 个新增消息样本全部小于 1 秒，P95 **138.0 ms**，最大 **139.4 ms**。

另测 1 个私聊、3 个群聊，每个分别提供查询词／不提供查询词，每次重建同步对象以绕过进程内文件时间缓存，8 个组合为 **45.4–538.4 ms**。首次全量校验约 **4.65 s**，在服务就绪前执行；该数字不属于日常回复准备指标。

此前线上诊断的记忆准备中位数约 13.15 s，受线上负载和并发影响；不能把它与本次隔离结果直接相除宣称线上加速。本次前后对照未运行模型、传输和生产后台任务，尚未证明线上 P95 或端到端回复时长。

## 瓶颈与改造

| 环节 | 原行为 | 当前行为 |
|---|---|---|
| QQ 来源导入 | 任一新消息使 DB/WAL 时间戳失效；重新验证、转换、比较约 1.42 万条历史记录 | 首次完整验证；之后只验证已提交游标之后的新增行及其依赖；本次每轮 2 行 |
| 人格准备 | 每轮解析约 49.95 MB 完整人格存档，再用当前人格覆盖 | 从当前认知所有者构建轻量人格对象；记忆仍由同一个受限视图提供 |
| 无查询词回退 | 按频道读取各群的观察记录，再按受众过滤 | 将精确会话加入 SQL 条件，使用已有复合索引，保持原排序和授权校验 |
| 生命周期 | 增量导入受 `production_memory_enabled` 开关影响 | 追踪同步独立于该开关；服务启动时安装来源追踪并完成全量基线 |

隔离测量中，QQ 导入中位数从 **4,437.8 ms** 降为 **4.16 ms**；轻量人格构造中位数 **0.019 ms**。本地记录同步约 **2.75 ms**、跨频道查询合计约 **2.89 ms**。其余主要为既有派生记忆召回。各阶段中位数之和不等于总时长中位数。

未更换记忆模型、减少召回条数或修改召回预算。`production_memory_enabled` 保持关闭，线上启用的群聊、私聊、操作者完整召回控制在隔离副本中保留。

## 论文如何影响方案

1. **DBSP: Automatic Incremental View Maintenance for Rich Query Languages**，Budiu 等，2022：[原文](https://arxiv.org/abs/2203.16684)。借鉴增量视图维护：已有验证与投影结果作为持久状态，新增输入只产生增量工作。本项目使用 SQLite 与显式校验实现，并未接入 DBSP 引擎。
2. **Differential Dataflow**，McSherry 等，CIDR 2013：[原文 PDF](https://www.microsoft.com/en-us/research/wp-content/uploads/2013/01/differentialdataflow.pdf)。借鉴复用先前计算、跟踪输入变化与依赖的原则。这里只实现追加数据的增量路径；历史修改会触发完整审计，没有实现论文的通用差分／迭代计算。
3. **MemGPT: Towards LLMs as Operating Systems**，Packer 等，2023：[原文](https://arxiv.org/abs/2310.08560)。借鉴活跃上下文与持久记忆分层的方向。具体落地为复用已加载的人格和记忆所有者，避免为了生成回复重新解析完整归档；没有引入额外 LLM 管理调用。

这些论文提供设计依据，性能数字来自本项目基准。当前主要损耗是重复导入和反序列化，因此暂不更换向量数据库或采用新的语义召回算法。未来若检索本身成为主因，可考虑持久化词法／向量索引；届时需要单独验收中文召回质量、来源和会话权限。[SQLite FTS5 官方文档](https://sqlite.org/fts5.html)是词法索引的候选技术参考，本次没有引入。

## 完整性与失效规则

来源数据库保存独立身份、修改版本和各表行号水位。写入端安装触发器；只读导入器校验追踪结构并在一致的 SQLite 快照内读取。来源更新、删除、显式行号复用、非正行号插入、唯一键替换，以及已发送决策变化都会使旧追加前缀失效。SQLite `INSERT OR REPLACE` 在默认配置下可能不触发删除触发器，因此额外在替换发生前检测各唯一键冲突。

目标端在同一事务中提交记忆投影和同步检查点；检查点使用比较后写入，拒绝过期导入覆盖较新进度。同一认知所有者内部用锁串行化同步请求，避免 UI 与后台任务竞争游标。验证失败或目标写入失败均不推进游标、不部分导入。数据库文件替换、来源身份变化、授权范围变化或水位回退重新完整校验。文件时间缓存也包含设备和文件身份。

旧数据库没有追踪结构时仍走完整只读导入。缺失／损坏的追踪触发器会拒绝使用增量证明；写入端修复触发器时提升修改版本。保留原有不可变归档语义：来源删除不会删除已经保存的历史证据，相关关联仍需通过原验证逻辑。

异常重建、扩大授权、大量积压导入与首次启动不承诺 1 秒。这里的目标是已有基线、正常增量输入下的准备耗时；SQLite 锁竞争、CPU/GIL 竞争和后台工作仍需在线上验收。

## 实验与验证

- 快照取自 2026-10-05 23:29 左右（北京时间）；评测完成于 23:40 左右。
- 来源：6,657 个档案、6,714 条观察、379 条聚合发送回执、463 条分段发送回执，共 14,213 行；人格 JSON 为 49,952,278 字节。
- 从正在使用的 SQLite 数据库通过只读连接和 backup API 取得隔离快照；模型调用数、外部发送数均为 0。
- 对照组与候选组复用同一快照，逐轮追加具有确定身份的有效档案／观察副本；插入耗时不计入 `memory.prepare`。基准使用真实准备函数、已加载的完整人格记忆、10 条本地近期窗口和实际召回控制。
- 基线 5 次，候选性能组 30 次；样本量较小，P95 按最近秩计算，是样本统计而非线上 SLA。
- 另运行候选 5 次用于等量内容比较，5 个新增消息轮次和 8 个重建对象场景的 **13/13** 组结果哈希相等。哈希覆盖人格、上下文、来源 ID 和派生记忆，不覆盖测量时间与完整归档容器。完整归档由原记忆所有者持有。
- 最终相关回归 **280 passed, 2 warnings**；所有改动的 Python 文件 Ruff 通过。
- 新测试覆盖跨重启增量、旧档案依赖、全量结果等价、旧数据变更、回执与决策失效、事务回滚、授权扩展、旧库兼容、触发器修复、文件替换、替换写入、非正行号与前台不重读人格存档。
