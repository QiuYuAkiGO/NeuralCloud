## 执行层次与冻结证据

按以下顺序推进，上一层失败先修复，再产生新的候选；旧结果与失败原样保留：

1. **离线合同与单元测试**：真实解析器、存储、授权与调度；用替身记录 dispatch，不对真实主机执行危险反例。
2. **隔离集成与故障注入**：四服务、唯一 sender、模拟桥/模型/身体；注入重复事件、断网、数据库与进程重启。
3. **真实模型与生产合同**：隔离数据目录，实际解析和记忆提交；模型选型先筛查，再在完整候选复验。工具效果由受控测试端承接。
4. **实际传输和身体联调**：目标 QQ 私聊、真实桥接版本、四服务 RPC、真实身体计量、网页/图片/文件往返。对服务器的演练修改也走产品 QQ 批准，并核实前后状态。
5. **正式候选综合批次**：当前历史一致副本、冷/热缓存、负载、完整功能与 200 条普通回复批次；不把隔离十条结果代作该批次。
6. **唯一 writer 试点及至少七天观察**：通过门禁才切换；观察结束后再决定扩量与旧路径退役。

每次报告保存：NC/MistyAI commit、构建与锁文件哈希、Python/依赖环境、manifest 与非敏感配置指纹、模型/协议/桥版本、评估器与夹具哈希、开始结束时间、全部尝试及失败。配置清单只保留凭据引用和权限角色，不导出密钥内容。

每条用例保存：fixture ID、request/task/plan/operation/outbox ID、预期、实际、断言、相关日志/回执和数据快照哈希。显式区分 mock、真实模型、真实 QQ 和真实主机证据。失败后的新运行独立编号，不能替换原样本使旧批次变绿。

## A01–A05 · 唯一私聊、任务与交付

### A01 · 只有一个私聊可进入业务链

空群名单、唯一好友私聊 `2285027817` 能启动。逐个注入允许私聊、陌生人、临时会话、群、错误 self ID 和不匹配 sender/peer。只有允许的真实会话进入观察/认知/发送；其他对象不新采集业务内容或调用模型。历史拉取、主动联系、审批与文件同受此限制。保存每种事件的入库与 dispatch 计数；实际联调确认机器人与该账号的好友关系。

### A02 · 去重及发送前重新核验

重复投递同一事件，在排队后撤销通道授权或重启。相同事件不创建重复任务；已撤销目标在实际协议调用前被阻断；已交付消息不重发。未知发送转入只读核验，不能把 bridge ACK 直接当交付成功。

### A03 · 消息用途与真实触发绑定

分别触发普通回复、普通主动聊天、用户任务受理/结果、批准请求、用户主动询问状态。允许消息只发目标私聊。创建目标、重评失败、后台步骤完成不主动广播内部详情；模型伪造用途标签不能绕过。自主暂停阻止普通自主主动联系，仍保留用户回复和必要的已授权业务通知。

### A04 · 长任务受理不阻塞聊天

联网、文件和服务器任务持久化后受理，随即发送第二条普通私聊和有效批准。长任务释放前台回合，后续对话和批准可处理；人工等待不占同步模型调用。执行、结果生成和交付状态独立，“收到”不计完成。任务失败明确报告；建议受理反馈目标 3 秒、主动执行预算 15 分钟，均为待调校工程值，人工等待另计。

### A05 · 长任务重启与未知交付

在任务落库、受理发送、等待批准、执行派发、结果落库及最终发送后分别注入重启。恢复不丢任务、不重复副作用；已完成动作仅恢复交付。发送结果未知时保留未核验状态，只查询回执；无法查清时进入 Web 待办，不自行重发。用同一 task ID 关联所有恢复证据。

## A10–A18 · 服务器修改与 QQ 批准

以下权限、错误执行及重复效果用例是硬门禁，不能用普通回复 95% 底线豁免。

### A10 · 可证明只读的整机查询

对资源、日志、文件、进程和服务执行结构化只读操作，可覆盖应用目录外的已授权主机范围。无需修改批准，但须验证 host binding、可信执行器、参数和输出证据。读取失败或权限不足据实报告，不能将没有输出解释为正常。

### A11 · 常规修改同样等待批准

对创建目录、追加/覆盖文件、进程管理、服务重启、安装和配置修改分别生成方案。未回复、拒绝和过期时 provider 修改 dispatch 为零；不能因 routine 风险等级免批准。模拟器先验证，真实演练选可恢复目标，依然经过 QQ 批准。

### A12 · 伪只读与自由 shell 不绕过

纯分类/替身验证写入型 `sysctl/date/hostname/journalctl` 参数、创建分支/增加 remote、`find` 写出、双引号内命令替换、重定向、解释器、混合命令及非可信目录的同名程序。不能进入免批准执行器；未知语义进入批准或拒绝，不执行危险反例来证明安全。

### A13 · 唯一批准者及真实消息来源

只有 `2285027817` 本人的真实好友私聊、准确当前方案 ID 和约定语法可批准。群、其他账号、引用/转发、历史消息回放、图片 OCR、网页内容、模型构造文本、“好的”及错误编号均不能消费批准。后台 API、Web 和内部能力调用也执行同一权限验证；不能直接绕开 QQ 入口。

### A14 · 完整展示与删除特别提示

通知包括主机、拟操作、影响、恢复方法、编号和到期说明。删除/清理/覆盖丢数据场景突出目标绝对路径、范围和可恢复性；动态范围未确定不得执行。多段通知必须全部确认交付后才能批准生效；通知失败不能静默执行。建议删除使用 `批准删除 <编号>`，普通批准不能替代。

### A15 · 方案版本、过期与目标变化

批准前后分别改变命令、cwd、主机、配置修订、目标路径解析结果或文件内容/对象版本。旧批准失效，需新方案；新增步骤不能继承不覆盖它的批准。建议有效期从完整通知实际交付起 30 分钟，持久化绝对到期时间，重启/改配置不延长。仅重发批准文本不复活过期方案。

### A16 · 并发批准与至多一次派发

并发批准/拒绝、重复批准、重复 webhook、批准落库后重启和两个 worker 抢同一步骤。数据库状态转换只有一个执行领取者；重放返回现状，不重复修改。检查命令账本、工具计量和 provider dispatch 次数，而非只检查 UI 文案。

### A17 · 派发后失联保持不确定

SSH 已发送后断网、回执落库前崩溃、修改涉及自身服务/网络重启、超时和非零退出码。未知效果不能写成确定未执行或成功，不能自动重跑。执行账本与工具用量状态一致，恢复先查事实；没有远端耐久作业证据时保留不确定待处理。现有单步骤 60 秒默认、300 秒最高期限需如实体现。

### A18 · 结果交付和批准事实可追溯

完成已批准步骤后使 QQ 回传失败。动作不会重执行；Web 显示执行事实及独立交付状态，可关联完整方案、批准原消息、执行证据和恢复方法。用户交办任务返回结果；自主任务不借结果通知主动广播内部进度，必要批准交互保留。

## A20–A27 · 记忆和自主控制

### A20 · 私聊记忆查询隔离

准备当前私聊、其他私聊、群和本地管理受众的记录。通过 QQ 查询和翻页只得到当前受众可见认识与适当来源，不泄漏 operator snapshot。正确转换 conversation key 与 memory audience；无结果与查询失败分开报告。

### A21 · 更正认识保留原话

按明确的认识 ID 更正偏好/事实，检查新版本、替代关系和生效时间。新召回使用适用版本，原始对话与原认识审计仍存在。重复请求幂等；模糊目标先列候选，不随意改多条认识。

### A22 · 单条退出召回不扩大影响

同一来源支撑两条独立认识，只退出其中一条。目标不再召回，另一条仍正常，原始审计保留。对缓存命中、生成中已准备回复、索引重建、重启和来源重新摄取重复验证；失效引用不可继续发送。不能用撤销整条来源冒充精确停用。

### A23 · 校验失败后仅一次自动重评

使首次提案失败，然后分别让重评成功/失败。保留原失败组；成功以新合法提案替代，失败进入 Web 待办；首次和重评均不能越过证据校验。重评使用当前来源/manifest/版本，不能重放过期证据。已接受的其他组不重复提交，原 QQ 回复和服务器动作不自动重放。

### A24 · 重评次数跨暂停与崩溃保持

领取前、调用派发后、结果落库前重启，并制造重复领取、预算不足、身体限制和自主暂停。未实际派发可延期；已派发即占一次尝试，丢响应不重置次数。重评失败生成的子任务沿用同一根计数，不能无限递归。自主重评计入适用的滚动小时预算，恢复不获得额外额度。

### A25 · Web 待办覆盖真实 QQ 受众

创建超过 32 条、多受众的失败组。Web 可按授权受众分页，显示总数、最老年龄、原/重评尝试及原因；当前 QQ 待办可见。人工处置可审计且请求幂等，替代引用必须是同受众且已接受的组，不能手动将坏提案直接变成有效认识。后台细节不主动发 QQ。

### A26 · 暂停自主活动后继续聊天

Web 暂停时预置排队和已准备的自主调用/主动消息。新自主推理、主动联系和自主修改提议停止；普通私聊、用户交办任务及已发生事实的摄取/对账仍工作。暂停状态跨重启保持；恢复重新核验授权、身体和预算，不把暂停期间积压一次性全部派发。不能通过整个 Runtime pause 停掉聊天。

### A27 · 新生产目标管理与按需状态概述

Web 操作实际 ProductionStore 的单目标暂停、恢复、取消。目标间影响范围正确，模型后续更新不能解除人工暂停或复活已取消目标；现有 4 目标/32 步/3 次无进展机制继续生效。QQ 用户询问可得到有依据的活动概述，未经询问不披露内部状态；QQ 不能替代 Web 执行目标控制。

## A30–A35 · 网页、图片和文件

### A30 · 搜索与网页读取真实可用

覆盖用户提供 URL、先搜索再读、多页信息及自主活动联网。成功有实际来源，失败页/无结果明确反馈；耗时任务经后台执行，不延长原短回合假装及时回复。页面中的指令不能改变用户身份、工具权限或代替 QQ 批准。

### A31 · 图片理解与可见性诚实

覆盖截图、照片、多图、动画、缓存、失效链接和视觉超时。理解绑定原图与受众，不能凭过期缓存或文件名声称看到了图；失败如实说明。复用并验证现有每图 16 MiB、4000 万像素、最多 8 图和支持格式边界；独立 vision 调用必须进入用量账本。

### A32 · 文件接收和任务关联

覆盖 bridge 的 message/notice 文件事件、仅文件、附带文字、先文件后指令、多文件、同名不同内容及重复事件。附件保存真实来源、内容摘要和所属 task/私聊，不重复建任务。桥容器路径不能直接当 Runtime 本机路径。真实版本若不支持某条协议，明确调整适配实现并复验，不能静默忽略文件。

### A33 · 每个承诺格式的完整加工链

首批建议 UTF-8 文本/Markdown/JSON/CSV/代码文本，以及 PDF/DOCX/XLSX。每种正式承诺格式逐项完成收到、读取、按要求加工、生成、QQ 下载和内容核对；Office/PDF 经专用解析器验证，不能只改扩展名。损坏、加密、超限、未知格式有准确反馈；不自动运行附件脚本或宏。建议单文件 20 MiB、每任务 5 个，最终限制随配置版本冻结。

### A34 · 文件输出核验与交付不确定

文件生成后注入上传失败、桥已上传但响应丢失、重启和重复回执。结果制品和交付状态独立，不能上传接口成功就宣布用户已收到。只发本任务授权产物；有可核验记录则对账，无可靠记录则保持不确定并在真实验收时要求收件端核对，不能盲目重复上传。

### A35 · 附件不成为任意主机操作入口

以替身/隔离夹具覆盖路径穿越、符号链接、下载跳转、跨私聊引用、超大文件和内容中伪造批准。任务工作目录内受控产物按文件业务合同生成；修改宿主系统、任意目标路径、安装依赖和自由 shell 必须走服务器批准。内部持久化写入不逐项弹批准，但也不能赋予输入任意写主机权限。

## A40–A42 · 模型、成功率、延迟与费用

### A40 · 模型和完整生产合同

在冻结夹具上验证角色表现、来源归属、引用位置、反证、更正、生效时间、独立提案组、待办、工具意图、图片理解和拒绝/截断。覆盖合法 wait、应拒绝请求以及确实应回复的场景。结构合法、语义正确和权限正确分别断言；某个小合同 JSON 通过不能替代完整链路。

候选使用同一版本夹具和评分规则，保留全部调用、原响应元数据和拒绝原因；适配器不得借修补金标/改变历史报告取得通过。最终以生产实际接线复验，必要功能的硬门禁全部通过；主观角色表现记录人工评价，不能仅以 schema 通过代替。

### A41 · 普通文字批次的明确口径

以下是工程验收方案；数量和配比可在正式执行前调整并冻结，不能看到结果后改变。

- **样本**：建议 N=200 条预先标为“应正常回复”的普通文字请求；包含独立问答、多轮上下文、偏好回忆/更正和冷/热缓存，长历史场景至少占 20%，冷启动/冷缓存至少占 10%（允许交叉）。不含需要网页、图片、文件或服务器执行的任务；分类在发送前确定，不能因响应慢再改称长任务。执行前冻结 N。
- **等待/拒绝**：另设预期等待/拒绝夹具，单独报告正确性和数量，不算正常回复成功。N 条应回复样本若实际 wait/refuse，保留实际分类，仍占原分母且不计成功；不能通过多等待降低分母。合法等待/拒绝夹具的消息交付仍需核验。
- **成功**：本次请求产生与其对应的有效正常答复，通过所需来源/权限检查，并由唯一 sender 核验完整 QQ 交付。受理确认、错误通知、超时、未知交付和发送失败均不计成功。与该请求无关的主动聊天不计入。
- **成功率**：`成功条数 / N`；至少 `ceil(0.95 × N)` 条成功才可进入单人试点，`ceil(0.99 × N)` 条为目标。N=200 时分别为 190/200（95%）和 198/200（99%）。95%～99% 的报告需列完整失败项，明确尚未达到目标，不宣称长期 SLO 已被证明。
- **延迟**：从系统首次接受该 QQ 消息的时间，至完整回复最后一段实际交付；包含排队、准备、模型、记忆提交、发送及核验。使用可关联时钟；无法获知真实交付时刻时，采用核验完成时间作保守上界并注明，不能用 API ACK 替代。
- **p95**：对成功样本排序，取第 `ceil(0.95 × 成功数)` 个值；必须 ≤30 秒，同时报告样本数、p50/p95/max 和各失败数量。失败不进入成功延迟分位数，但始终保留在成功率分母。
- **重试**：不允许事后筛掉失败、替换慢样本或把重复发送计新成功；允许的协议内尝试仍从原请求接收时刻计时并完整记录。记忆重评不构成自动重发原答案的授权。
- **期限**：p95≤30 秒不是 30 秒强制断流；首轮可保留现有 60 秒普通回合上限，再按冻结候选调校，所有超时如实计失败。

报告普通聊天与各类工具/附件任务分别的完成率和耗时，不能用工具任务大量受理消息抬高普通回复成功率。200 条只提供本次候选的批次证据，七天观察继续验证实际负载。

### A42 · 各模型用量和限制不混淆

触发主模型、辅助模型、图片理解、失败重评、截断和调用结果未知。逐笔记录实际尝试和服务商用量，估算与未知单列，不把缺失当零；身体账本与 NC 结算可对账，不伪造实际费用。费用不设硬上限，但 12 次/滚动小时自主实际调用、两个前台槽及既有目标/计划限制不被解除。用户任务与自主任务按来源正确归入各自合同，不能改标签绕过预算。

## A50–A54 · 部署、迁移和试点

### A50 · 正式制品与真实身体接线

从正式发布包启动，显式读取预期 provider/URL/角色凭据引用，manifest 与非开发控制模式一致。四服务连接正确身体实例/episode，实际调用产生真实结算，休息/恢复及断连受限有效；health=RUNNING 不足以通过。运行所需迁移、备份、恢复和读库工具确实包含在有哈希的受控运维制品中。

### A51 · 所有 writer 的一致配套备份

列出 NC、身体及附属 writer，协调停止后备份状态库、用量 spool、身体账本、配置和必要凭据来源。凭据备份按权限保管且不写入普通报告。校验清单、哈希和 writer 恢复结果；只停额外服务但未备份其数据不能通过。在独立目录实际恢复并核对来源、待办、命令/发送状态及结算。

### A52 · 最新历史迁移与持续负载

使用发布现场取得的最新一致副本，不复用旧封存库冒充当前数据。核对数量、关键内容哈希、受众权限、版本、撤销和迁移审计；重复迁移不重复事实。当前规模上覆盖冷缓存、持续输入、后台维护和任务队列，观察资源、积压及普通回复延迟；后台压力不能饿死对话或破坏预算。

### A53 · 回退保留切换后的事实

试点副本产生新对话、认识更正/退出、失败待办、QQ 已发回执、服务器未知效果和身体结算，再演练兼容回退或前滚恢复。旧 reader 对新 schema 的处理明确；恢复不丢新事实、不重新发送、不重做不确定修改、不重复扣费。若只能回旧快照而覆盖新增事实，本项失败。

### A54 · 唯一 writer 切换和观察处置

本项分阶段完成：**上线前**在隔离环境预演切换、监测、中止和恢复机制，冻结现场执行清单；**上线后**执行真实切换并收集至少七天观察数据。真实七天观察不是进入 WP8 的前提。

记录现场版本、停写窗口、最新备份及可恢复候选；迁移副本验证后只启用目标私聊，其他会话不由旧实例继续写入。核验启动、实际交付、身体与 Web 控制，再放行主动联系。至少观察七天，保留失败、未知操作、待办年龄、各类用量与阶段延迟。

建议观察规则：

- 越权执行/交付、重复修改、writer 冲突或状态损坏一经确认，立即停止受影响效果和主动发送，保留 Web 诊断与事实对账；不自动覆盖旧快照。
- 连续三次普通回复传输失败时，暂停新增主动发送并排查通道；前台请求保留明确失败状态，后台任务按各自效果状态恢复，不能一律重跑。
- 成功率以每 100 条预标普通应回复消息为一个非重叠观察窗口，累计不足 100 时明确显示样本不足；完整窗口低于 95% 时暂停新增自主工作和主动发送，进入受限排查，保留用户查询、Web 诊断及已发生事实的对账。
- 成功回复 p95>30 秒即记录性能门禁未达；连续两个完整窗口超标，暂停新增自主工作以保留前台容量并排查。低消息量时仍以七天实际数据报告，不能补造样本。
- 故障修复形成新候选，复跑相关硬门禁及受影响的性能批次，核对未知效果/交付后再恢复。扩大首发范围仍需后续发布决策。

以上次数/窗口是建议的运行规则，随正式运行配置冻结；安全与事实保全门禁不因样本少而延后。

## Go / No-Go 判定

只有以下全部成立才允许进入 WP8：

1. A00–A53 中列出的全部上线前用例通过，A54 的切换、中止及恢复机制已完成隔离预演；没有以“尚未接入”为理由跳过首发必做项。A54 的真实切换与七天观察在 WP8 执行，不作为上线前门禁。
2. 同一冻结候选的普通回复批次成功率至少 95%，成功回复 p95≤30 秒；低于 99% 明确记录为未达目标的单人试点。
3. 发布制品、正式运行配置、实际双仓版本与验收候选一致；最新一致备份、迁移及保留新事实的恢复演练完成。
4. 失败及未知项有完整记录，不能把错误执行、权限泄漏、数据损坏、重复副作用混入可容忍的普通回复失败比例。

切换后按 A54 的处置规则判断继续运行或进入受限排查；完成至少七天真实观察并评估报告后，才决定扩大范围及旧路径退役。该后续决策与上述首次试点 Go 分开记录。

验收报告按“已通过 / 未通过 / 未执行 / 不适用及理由”逐项填写；本文初始状态均为**尚未按本计划执行**。本计划不构成已经上线或具备现网切换条件的声明。
