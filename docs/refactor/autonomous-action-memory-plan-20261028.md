# 自主行动经历记忆：实施计划与待办

日期：2026-10-28（北京时间）

状态：待实施。本文件仅记录已确认设计和验收要求，不表示后台任务已启动、代码已修改或生产已部署。

## 目标与已确认决策

将每次自主行动提炼成一份可检索的经历记忆，写入 NeuralCloud 记忆数据库；需要核验细节时，依据证据引用按需读取原始日志。MistyAI 负责采集执行事实和任务生命周期，NeuralCloud 负责记忆持久化、派生关系和检索。

采用一次自主任务一份经历记忆。原始观察与日志继续保留，摘要是派生记录，不是新的独立证据。连续等待的合并仅作为后续归档优化，首版不合并任务。

摘要生成在独立后台队列中执行，失败不阻塞聊天、任务结算或下一次自主行动。每个固定输入版本最多调用摘要模型 3 次，仍失败则写入异常记忆表，等待后续解决。

## 记忆合同

- 稳定标识：`character_id`、`drive_id`、关联活动与会话 ID；一项任务只有一个逻辑经历 ID。
- 时间与版本：触发、开始、结束时间，事实快照版本、输入哈希、摘要合同版本、摘要模型版本。
- 触发背景：真实需求、任务触发条件和相关情境；没有记录的动机明确标为未知。
- 实际操作：按顺序区分计划、调用尝试、执行完成及外部回执；每项绑定证据引用。
- 观察结果：实际取得的内容及覆盖范围；不得把打开页面、标题或截图等同于完整阅读。
- 评价：仅保留明确提交的收益、置信度与反馈来源；不把相关变化写成已证实的因果效果。
- 结算结果：`WAIT`、`COMPLETED`、`FAILED` 或 `UNKNOWN`，保留未核实事实及对账版本。
- 未完成事项：仅记录明确尚未完成的事项；等待、自然结束和历史承诺不自动生成补发任务。
- 证据关系：引用原始观察记录、发送回执、活动 ID、日志事件范围与校验值。
- 隐私与派生关系：继承来源访问限制和参与者约束，记录派生来源，避免重复计作独立证据。

证据定位使用受控引用，不赋予角色任意路径读取能力。不在记忆中保存凭据、完整配置、无关私人数据或截图编码。

例：今天 08:00 的任务可概括为“连接需求触发自主行动，观察手机前台 Chrome 的 MDN HTML track 搜索页面，随后选择等待；未发送消息或继续操作。日志未记录选择等待的具体理由。”禁止补写其心理原因。

## 数据流与失败恢复

1. 任务结束、异常或对账完成时，持久化事实快照与待提炼事件；结算和入队之间使用事务或可恢复 outbox，避免漏单。
2. 后台 worker 根据任务 ID 和输入哈希领取工作，只读取关联活动、回执及限定范围日志。记录缺口，不能用猜测补齐。
3. 每次模型调用前持久化尝试序号与状态，限制并发、输入大小、输出大小和超时；固定输入版本最多 3 次。
4. 先校验证据完整性、任务归属、事件范围及哈希，再提炼摘要；输出校验必须检查引用、结果状态、发送事实和来源约束。
5. 使用稳定逻辑 ID 和幂等键将经历写入 NeuralCloud，拿到持久化确认后才标记工作完成。确认丢失时重试写入，不重新生成摘要。
6. `UNKNOWN` 任务可以保存标明不确定性的暂定经历；对账后更新同一经历的版本，旧版保留审计，默认检索返回最新有效版。
7. 模型调用或输出校验失败累计到 3 次时，写入异常记忆表并停止自动调用。崩溃时状态不明的已发出调用计入预算，不能自动获得额外尝试。

摘要调用预算与数据库投递重试分别管理；任何投递重试不得触发外部行动重放。人工重试必须具备操作者、证据与审计记录，不自动清零计数。

异常记忆表建议保存：任务及工作 ID、异常类别、输入版本和哈希、尝试次数、逐次错误、最后状态、证据引用、归档时间、处理状态及解决记录。敏感原文仅通过受控引用访问。

本次维修建立的 `exception-memory.sqlite3` 是运维留档，不代表已有正式生产异常队列；实施时须确定正式归属、迁移方式和权限。

## 完成标准

自主任务能形成有证据、可检索、可修订的经历；手机操作等现有缺口得到覆盖。摘要处理失败不会阻塞角色运行，最多 3 次调用后有可追踪异常记录。原始执行日志、操作结果和摘要之间可核验且不混淆。以上待办全部完成并有验证证据后，才能将本计划标为已实施。
