# QQ 重复无回复的机制修复（2026-09-16）

## 线上证据与范围

上一轮 `20260916-qq-expiry-v1` 上线后，Runtime 保持 RUNNING，未复现 FF14 请求遇到的全局 FAULTED。但新运行周期的首批 49 条实时非自身消息中，20 条 failed、8 条 expired；部分决定已生成正文，随后在 protocol.delivery 终止。旧遥测把多数协议拦截统一记成 model_error，不能据此认定主模型异常。

核对代码和命令时间线，确认两类结构性原因：

1. 原发送条件把任何同群新消息都视为旧回复失效，包括其他成员对已经真实 @ 本账号的请求插话。
2. 协议队列共用单个工作者。部分排队已达 48–58 秒，而回复期限固定为收到后 60 秒。模型准备还串行执行联网判断、情绪观察和决定/生成；抽样联网判断约 6.6–8.4 秒，情绪观察约 10.2–10.4 秒。频繁群聊很容易让旧正文在发送前失效。

这些观察不等于所有 failed 都应发送，也不等于所有超时均由同一原因导致。本次修复保留原对话判断和情绪处理。

## 实现

- `direct_store.normalize_message` 从真实 OneBot at 段或已验证私聊范围生成 `protocol_addressing`，文字伪造 @、@all、引用和模型推断不获得同样权限。
- `check_send` 重新校验原始协议文件哈希、事件身份、作者及消息内容；发送还要求冻结决定中的 addressing 证据绑定本条 observation。合格明确请求只因原作者后续消息被取代，其他成员插话不再取消；普通群聊仍执行原新鲜度规则。
- `pending` 优先选择仍在原期限内的协议点名/私聊请求，再处理有效普通消息、过期消息、历史及自身回显。同级保持 FIFO；不延长期限，不丢弃待处理事件或原始证据，不新增并行认知主人。
- Web 选择器仍调用主模型并保留完整人格，来源校验后仅获取精确触发事件和同会话最近 6 条核验对话，不再检索完整群成员资料及共享记忆。本轮原文/OCR独立保留；历史整条裁减到 16K 软目标，完整当前输入和来源仍可使用原 64K 硬上限。
- Direct 事件新增可空的 `terminal_reason / terminal_stage / terminal_at`，trace 新增 `termination`。能区分新消息取代、期限、发送预算、冷却、共享服务故障和交付不确定。只保存固定类别，不保存异常原文；旧事件原因保持未知。

TTL、原作者更正、会话权限、owner/epoch、冻结计划、outbox、防重发和不确定交付保护继续生效。此版本没有自动补发旧请求。

## 保守边界

这次修改不抢占已经开始的普通群聊认知，因此在持续超出处理能力的流量下仍可能排队到期。同一作者后续发言仍会使旧请求失效；普通群聊也可能按原策略沉默或被较新上下文取代。真实 at 段紧贴前文时，旧决定正则可能没有认定明确点名，此时不会授予新豁免。后续应依据新的终止原因统计决定是否引入可取消准备、按会话合并普通触发或进一步拆分串行阶段，不能用放松来源和交付检查替代。
