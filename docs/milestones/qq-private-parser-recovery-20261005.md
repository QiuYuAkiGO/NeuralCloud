# QQ 私聊错误兜底修复（2026-10-05）

适用会话为 `private:2015188508:2285027817`。本次故障发生于北京时间 21:40:32 收到“能看见吗”的私信后：主模型已生成“在的，刚看到消息”，交付层却在 21:41:20 发送了通用故障提示。

## 原因与修复

辅助模型解析固定内部指令时返回无效 JSON。`ContextParser` 已按既有设计恢复为规则解析结果，但 `_QQScopedLLM.failed_error_type` 留下 `model_invalid`，后续成功生成的正文被 QQ 决策层判为失败。原始辅助模型响应体没有保留，无法确定当时 JSON 的具体格式错误。

`harness/qq/decision.py` 现在只在固定内部指令解析确认恢复成功、此前没有失败、当前错误为 `model_invalid` 且未超时时清除这个错误标记，并记录恢复事件。规则恢复结果仍不缓存为模型解析成功。用户消息解析、真正的 HTTP 错误、正文校验错误、先前失败和超时继续走原有失败处理。

该私聊先前不在低延迟策略名单中，因此全局的 `compact/direct` 设置没有对它生效。本次在 GUI 和 QQ Direct 两份配置中加入其精确账号/会话键，启用既有精简上下文和直接正文流程。

另外复用协议 ID 的 Pydantic 校验器，减少每条记忆反复构建校验器的开销；本地聊天同步改为一次事务批量写入，保留来源不可变性、重复导入幂等性及异常时整批回滚。共享存储初始化的“是否为空”检查改为取一条记录。
