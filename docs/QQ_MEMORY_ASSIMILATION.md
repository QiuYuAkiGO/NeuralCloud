# QQ 观察清洗与印象演化

实现入口为 `harness/cognitive/qq_memory.py`。Misty 继续使用同一个 Cognitive 所有者、MemoryService 和工作预设；QQ 群聊与私聊经历写入同一套记忆。原始观察保留在共享库，派生情景、候选、语义判断、印象历史及提交收据保存在同一个预设快照中。

## 处理与证据

- `QQAssimilationQueue` 在共享 SQLite 的 `qq_memory_jobs`、`qq_memory_job_sources` 中保存冻结窗口和提案。每个群／私聊会话静默 30 秒封窗，最长 120 秒或 32 条消息。模型在窗口内部按参与者、引用和话题拆情景。
- 协议消息按账号、会话、消息 ID 去重；同文且身份无法确认的桌面采集保留为疑似重复，不增加独立证据。同一窗口同一判断至多强化一次。
- 窗口边界不代表独立经历。相同对象、主题、情境和证据方向的连续发言，默认静默不足 60 分钟仍属同轮；每次连续活动延长该轮。`continues_episode_id` 还可明确引用更早的同一经历。延续内容进入 `continuation_evidence`，保留情景和原文，不重复加置信度、独立证据或强化。首次反差可以修订，同轮反复提及同一反例不反复降低置信度。60 分钟是可配置的保守工程初值。
- 原话、作者自述、第三方评价和图片模型解读分别标明来源。Misty 自己的发言、纯引用、重复采集和无法确认的图片不作为独立证明。
- 印象提案必须声明 `evidence_kind`。只有有作者归属的实际发言行为可以支持或反驳印象；自述真实性、第三方标签、图片解读及无新行为的推演只能标记不确定，保留为情景内容。
- 话题使用可复用的认识维度，情境使用“日常闲聊”“技术讨论”“认真求助”等场景类别。昵称、性别猜测和逐条原话不作为印象身份或情境键。
- 模型可以不形成印象。一次结构校验修正仍必须使用相同冻结来源；再次失败保留任务，按退避重试。两次提案共享后台模型期限。

## 印象与生命周期

人物按数字 QQ 身份，关系按排序后的参与者组合，均绑定来源群或私聊会话。初始印象、当前判断、原始证据、反例、置信度、记忆强度和版本历史分别保存。

默认初始置信度为 0.15；新支持证据按 `c += 0.35 * (1-c)` 更新，反证按 `c *= 0.65` 更新。稳定判断同时要求置信度达到 0.70、至少 4 个独立情景、跨至少 2 个上海时区自然日。模型不能指定置信度或晋升状态。反证保留旧版本并标记争议，不把一次反差当作最终结论。情境不同形成补充分支，不作为原判断的反证。

短期继续使用独特性对应的 5 分钟至 7 天保留期。中期、长期强度分别按 14 天、90 天半衰期下降；每日检查，低于 0.20 降一级并以 0.50 重新计时。没有新证据时，衰减降级的记忆不能通过到期复审反复升回原层。已淡忘的印象退出召回，其派生语义判断同时撤下，历史仍可追溯。

置信度不随时间自动降低；记忆强度决定可唤起程度。实际决策中展示过的情景 ID 会冻结在 `recalled_episode_ids` 中，同一决策仅强化一次。不会把最新版印象的全部历史展开强化，也不会让调试、后台扫描或历史回填刷检索命中。

参数由 `Settings.qq_memory_*`、`Settings.qq_impression_*` 配置。它们是可调整的工程初值。

## 提交与恢复

模型和批量向量生成在前台锁之外运行。模型默认最多 45 秒，非必需的向量生成最多等待 5 秒。提交时由 Cognitive 持有短锁，检查预设实例、作用域、版本及冻结来源；在当前快照上合入派生结果，保留模型运行期间新增的本地对话。
对于已经确认支持关闭思考的 DeepSeek 整理调用，如果输出预算耗尽导致正文为空或被截断，会在原期限内最多重试一次关闭思考的结构化请求。其它供应商不猜测参数；失败继续保留任务。此恢复只作用于后台整理，不改变 QQ 回复模型设置。
如果剩余期限不足，任务记录 `reasoning_budget_exhausted`；下一轮直接使用关闭思考的整理请求，避免再次耗尽同一思考预算。每轮仍只使用原 45 秒期限。

预设写入采用临时文件、fsync 和原子替换。替换失败不会直接覆盖旧文件。保存成功后才安装内存结果并确认队列；保存后确认前崩溃，通过预设收据恢复。恢复或重新加载同 ID 预设也会对账。隔离历史回填先按原时间重放，最后按当前时间维护；线上每日衰减和实际采用强化独立于清洗队列，失败窗口不阻止维护。迟到证据保留实际发生时间，但不会把强度时钟倒退。

后台更新的 Cognitive 版本先落盘再发布。如果主预设已保存但版本文件保存失败，保留这份权威记忆及收据，下轮仅重试发布同一版本并对账队列；不会重新形成印象、增加置信度或回滚成可能覆盖新收据的旧内存。两个功能开关关闭时仍允许完成这项持久化恢复。

`qq_memory_import.validate_bundle` 从冻结初始预设逐窗重放已保存提案，核对整份结果、来源、提案摘要和收据；导入还要求当前源库中原始来源摘要一致。导入前备份当前预设与共享 SQLite，合并期间新增的本地信息保留。

## 召回与观测

候选合并和检索池都先校验作用域。群内只召回本群派生记忆，失败时不会移除群级过滤。私聊使用账号和对方数字身份组成的独立作用域，普通私聊只读取本会话记忆，不会按昵称或相同内容跨会话合并。

所有者明确授权后，其已核验 QQ 私聊可同时召回当前授权群、授权私聊和同一 Misty 的本地主记忆。此权限由服务端保留的所有者身份、当前账号、允许私聊名单和独立开关共同校验，消息中的自称或请求不能授予权限。扩大召回的每条结果附带来源渠道与会话，仍共用一份 8 条／16,000 字符预算。旧的无作用域记忆默认仅本地可见，只能通过这项明确的所有者权限进入其私聊。群和其他私聊的范围保持原有规则。

QQ 使用同一份选定记忆同时判断“是否回复”和生成回复。默认最多 8 条、16,000 字符，并计入 QQ 资料输入预算。被预算裁掉的记忆不会记录为采用。当前认识一并携带最早留存印象、置信度、争议状态和相关反例；“最早留存”不代表真实初遇。

2026-09-14 按所有者要求，资料输入上限从 48,000 字符提升到 192,000 字符，记忆部分从 4,000 提升到 16,000。`NC_QQ_INPUT_TOKEN_BUDGET=96000` 使用项目既有的每两字符约一 token 的工程估算，不是供应商 tokenizer 的精确计数；gate／draft 共用此上限并预留 assessment。人设及规则继续使用原有 compiler 余量。`NC_QQ_MEMORY_RECALL_MAX_CHARACTERS=16000` 控制记忆部分。保留最多 8 条记录及 40 个证据编号，相关内容不足时不填满预算。

增加输入上限不增加前台模型调用、摘要步骤、输出上限或重试次数，60 秒回复期限保持原值。静态解析缓存忽略这些仅影响输入选择的预算字段，预算切换不会造成额外的解析缓存失效。更多实际输入仍可能增加供应商读取耗时，不能承诺绝对零延迟；本地选择与固定模型耗时的回归分开计量。健康接口和 GUI 的 QQ 记忆摘要显示当前预算，trace 单独记录输入字符数及估算 token 数。

四倍预算上线验收共 632 项相关测试通过。群聊及私聊超过旧上限的输入能完整进入 gate／draft；超过新上限的必需资料会在调用模型前拒绝。最新私聊问题的线上预览选出 8 条、7,244 字符，群聊预览选出 8 条、4,874 字符。交替运行的同快照纯选择测试各 20 次，中位耗时为原预算 29.66 ms、新预算 21.23 ms；这不是供应商端模型耗时测试，也不代表大预算始终更快。启动配置已持久保存，Runtime 为 RUNNING、QQ 已连接。详见 [四倍输入预算验收](milestones/evidence/qq-input-budget-fourfold-2026-09-14.json)。

需要回退时，在 `data/shared-misty-launch.json` 将 `NC_QQ_INPUT_TOKEN_BUDGET` 设回 `24000`，将 `NC_QQ_MEMORY_RECALL_MAX_CHARACTERS` 设回 `4000`，按现有工作流重载 Cognitive；原始记录、分层记忆及授权范围不需变更。

已授权所有者在私聊中泛问群友或遇见之人的印象时，最多优先选择两条其他会话中的人物印象，再按相关度填充其余预算，避免重复当前问题及 Misty 的旧回答占满上下文。具体事实问题保持原排序。每条本地语义判断只带最近两条可见支持经历，整个回复的证据编号保持在接口上限内；未授权或缺失的支持经历不进入回复与采用收据。

`PrepareQQResponse` 在 Cognitive 获得锁时读取最新记忆，不要求匹配 Runtime 缓存的记忆版本，避免后台提交导致回复准备冲突。身份、来源、群、期限、幂等收据和响应版本单调性校验仍然有效；其他领域命令继续遵守原有版本校验。

GUI「调试 → QQ记忆」只读展示群聊与私聊的证据、作者归属原文、修订历史、置信度和强度。状态接口分别统计情景、各层记忆、印象状态、稳定判断、处理窗口和已处理观察，并分渠道显示情景与印象数量；健康接口不返回原文或印象内容。
同轮延续单独展示，不混入支持／反证的独立证据计数。

以下操作使用现有 Cognitive 服务令牌访问 `POST /v1/ui/control`：

- `qq_memory.status`：读取状态和证据详情。
- `qq_memory.configure`：`payload` 为 `{"enabled": true, "recall_enabled": true}`；两个开关独立保存。
- `qq_memory.configure` 另支持 `private_enabled`、`private_recall_enabled`、`owner_private_full_recall_enabled`。旧控制文件缺少时均默认关闭；前两个控制私聊清洗与召回，最后一个只控制已核验所有者私聊的扩大召回。全局两个开关仍为总开关。
- `qq_memory.preview`：`payload` 为 `group_id`（群号或 `private:self:peer`）、`query` 和可选 `member_id`。按服务端授权返回相同的预算内结果；不调用模型、不增加采用或命中，不接受范围覆盖参数。
- `qq_memory.import`：`payload` 为已复核输出目录 `output_dir` 和固定的 `expected_preset_sha256`。群回填要求两个总开关关闭、无正在处理的窗口。私聊专用回填仅合并指定私聊，可以保持群后台运行，保留期间新增的群、本地和采用记录；混合群／私聊输出暂不接受导入。

初次上线的规则复核可额外传入 `expected_owner_state_sha256`，只对完全重放校验通过的结果执行受版本保护的替换。必须覆盖线上所有已提交来源、保留情景和候选 ID，并且不能丢弃冻结基线之后的实际决策采用记录。当前本地对话保留，当前预设和队列先备份。该接口不接受直接修改某个人的置信度。

关闭两个开关即可回到原有 QQ 回复路径，已保存的原始来源、派生记忆和提交收据继续保留。历史清洗不会发送群消息，也不补发旧回复。

仅回退私聊接入时，将三个私聊开关设为 `false`；群清洗和群召回可以继续运行。关闭私聊清洗不删除已整理的私聊经历。提交前再次校验当前账号、授权和预设；撤权后的待处理提案与采用不会写入记忆。

## 历史回填

使用 `python -m harness.memory.qq_backfill`，参数为 `--source-db`、`--preset`、`--settings`、`--output`、`--self-id`，以及可重复的 `--group-id`。`--max-jobs` 可分批运行；`--retry-failures` 可有限次恢复失败检查点。同一输出目录续跑只处理冻结来源。

私聊专用回填不传 `--group-id`，改传可重复的 `--private-peer-id`。同样冻结原始时间与来源，沿用情景、初印象、反差和衰减规则；私聊不能生成人数或群氛围判断。来源必须属于该账号与对方，Misty 自身回复不能独立证明对方的印象。完整提交收据用于重复导入确认，即使之后已经发生真实采用或衰减，也只确认、不覆盖后续演化。

输出包含原始源库副本、初始预设、工作预设、来源清单、队列和计数报告。应放在 QQ 私有目录；这些文件含聊天原文，不应提交到仓库。验收统计分别报告原始观察、情景、印象和稳定判断，不以单一“记忆总数”代替。

验收测试包括 `test_qq_assimilation`、`test_qq_impressions`、`test_qq_memory_commit`、`test_qq_memory_worker`、`test_qq_memory_lifecycle`、`test_qq_memory_adoption`、`test_qq_memory_import`、`test_qq_memory_reply`、`test_qq_backfill`、`test_memory_scope` 和既有 QQ/预设/检索回归。本机主记忆使用现有内存存储与 JSON 预设；PostgreSQL 作用域迁移已提供，需在使用 PostgreSQL 的环境另行执行迁移和数据库集成测试。
