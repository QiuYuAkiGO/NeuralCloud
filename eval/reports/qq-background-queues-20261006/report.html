QQ 后台队列隔离与多线程适配

2026-10-06 · 已部署 v2 并完成线上健康验收。10 月 5 日的诊断样本保持原采样截止。

后台情绪更新与 Runtime heartbeat 分别排队，同步阻塞工作分别使用专用线程；前台不再等待情绪模型或整轮例行维护完成。

前台读取最近已提交的情绪与 Homeostasis 状态。共享状态提交保留必要的短锁，以维护幂等、消息游标、持久性及暂停语义。

三个执行通道

QQ 前台队列

来源与期限校验
→ 读取已提交快照
→ 现有决策与正文流程
→ 交付和提交

QQ 准备完成后只提交情绪刺激，不等待后台模型返回。

后台情绪队列

按会话合并刺激
→ 专用 nc-affect 线程
→ appraisal / guidance
→ 情绪组件提交

保留同一状态所有者的刺激顺序；模型等待期间释放前台命令锁和情绪读取锁。

Heartbeat 队列

独立时钟与工作协程
→ 合并待处理 tick
→ 状态更新与维护检查
→ nc-heartbeat 线程扫描

例行维护不占用前台 dispatch；前台忙碌时暂缓新的自主机会。

Heartbeat 具体执行哪些工作

项目执行方式及边界
Homeostasis 更新与 watchdog保留及时状态更新；与前台状态写入互斥。critical 或暂停状态会阻止较晚完成的 QQ 结果继续产生回复。
embodiment / 终端和服务审批过期由独立 heartbeat 协程检查；每个阶段记录耗时，阶段开始前检查 Runtime 是否仍在运行。
留言板、日记、能力调用恢复与自主机会大批记录读取移到专用线程，使用线程自己的只读 SQLite 连接；控制器状态与写入仍由原事件循环负责。线程读取完成后重查当前记录和前台状态。
日报、自检保留既有后台任务语义；自检 journal 历史扫描移到 heartbeat 线程。新增阶段计时便于定位此前几秒钟的未拆分维护时间。

并发一致性

  • 模型推理只持有情绪操作顺序锁；快照读取、回执记录及持久化使用短状态锁。
  • 情绪完成时从当前状态合并，保留推理期间新增的已交付消息，不回退较新前台游标。
  • SQLite 仅提交情绪增量；JSON 仅替换上一次已提交投影中的情绪组件，不提前发布前台尚未完成的 revision 或 session。
  • 线程复制 ContextVars，维持 trace 关联。取消调用者不会假定 Python 线程已经停止；退出有排空期限，未排空时保留状态文件独占权。
  • 状态接口新增 background.heartbeat 与 background.affect。journal 新增 heartbeat_work_started、heartbeat_work_completed 和 heartbeat_stage_completed。

收益与适用范围

这次消除了两类结构性前台等待：正在执行的 heartbeat 整轮维护，以及后台情绪模型持有全局锁。历史样本中曾有 2.937 秒 Runtime 排队明确等待 heartbeat 结束；这是优化动机，不能当作上线后的固定节省值。情绪与维护仍会共享 CPU、网络、模型服务容量和数据库提交资源，独立队列不等于硬件资源完全隔离。

本次接入当前 legacy QQ 快照流程；独立的 production / research Runtime 维持既有执行机制。历史批量导入、网页选择和正文长输入处理仍需后续独立优化。后续应复测入站至受理、前台队列等待、各 heartbeat 阶段及首段验证回执。
